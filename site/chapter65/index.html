실행을 확인한 커널은 Python 3.12.15입니다. 예제에 사용한 외부 패키지는 langchain-core 1.6.12입니다.

02

규칙 기반 의도 분류

의도 라우터는 질문의 유형에 맞는 도구를 고릅니다. 두 의도가 섞이거나 분류 근거가 약한 경우에는 추가 질문이 필요합니다.

먼저 ‘영수증’, ‘결제’ 같은 단서로 문의를 분류합니다. 결제와 기술 단서가 함께 있거나 둘 다 없으면 clarify를 돌려줍니다. 이 규칙의 결과를 뒤에서 선택할 도구와 연결합니다.

셀 01 · rule_route()의 단일 의도 판정

두 조건 중 어떤 조건이 참인지 확인하며 마지막 반환값을 읽으세요.

실행 결과

technical

technical은 문의의 분류 결과입니다. 이 문자열을 얻은 것만으로 기술 도구가 실행되지는 않습니다.

technical은 이 규칙이 고른 처리 경로입니다. 기술 문의로 분류했다는 사실만으로 해당 도구를 실행할 권한이 생기지는 않습니다. 분류 결과를 받은 쪽에서 경로별 허용 도구를 확인하고, 의도가 겹칠 때는 추가 질문을 보냅니다.

분류 결과는 다음 단계의 입력

기술 문의가 선택되면 다음 분기가 technical용 도구를 찾습니다. 지금 출력한 문자열만으로는 도구가 실행됐는지 알 수 없습니다.

과제 02 · 복합 의도의 추가 확인

‘영수증 조회 중 401 오류가 납니다’를 기존 함수에 넣고 어디로 가는지 확인하세요.

풀이와 실행 결과 보기

실행 결과

clarify

clarify입니다. ‘영수증’은 billing을, ‘401’은 technical을 참으로 만듭니다. 두 경로 중 하나만 참이어야 반환하는 조건이어서 마지막 줄로 갑니다.

서로 다른 의도가 한 문의에 섞일 때

분류가 모호하면 도구를 실행하기 전에 필요한 정보를 되묻습니다. 기술 문의와 다른 의도를 함께 넣고 선택한 경로를 보세요. 라벨을 고른 단계와 그 라벨에서 허용한 도구를 고르는 단계가 구분돼야 잘못된 실행 위치를 찾을 수 있습니다.

선수 개념 · 14장 분류 함수와 조건부 라우팅

단서가 섞이면 추가 질문

결제 단서만 있으면 billing이고 기술 단서만 있으면 technical입니다. 두 단서가 함께 있거나 둘 다 없으면 clarify가 됩니다. 단지 먼저 발견된 단어로 결정하지 않습니다.

03

분류별 허용 도구와 추가 확인

LangChain 도구는 모델에 제시할 수 있는 설명과 실제 호출 함수를 함께 갖습니다. 여기서는 분류의 영향을 보기 위해 모델의 자유 선택을 생략하고, 허용 목록에서 얻은 도구를 직접 invoke합니다.

셀 03 · 의도별 허용 도구

도구 이름과 실제 안내를 확인합니다.

복합 문의의 분류값 clarify에는 바로 실행할 도구가 없습니다. 이 값이면 도구 목록을 찾기 전에 질문을 돌려주세요. 아래의 기술 문의만 technical 목록에서 함수를 골라 실행합니다.

실행 결과

technical_faq
401 오류는 키 설정과 실행 환경을 확인하세요.

technical_faq만 선택됐습니다. 안내는 수업용 함수가 반환한 문구입니다. 계정의 키를 읽거나 인증 상태를 조회한 일은 없습니다.

선택한 도구를 실행하는 위치

allowed에는 technical_faq가 technical 경로에만 등록되어 있습니다. route가 그 키와 일치할 때 selected.invoke를 호출합니다. 이 실습에서는 Python의 조건문이 도구를 선택합니다.

04

선택 실습 · Jev 분류 결과의 수용 조건

Jev 선택 2H에서는 같은 문의와 세 분류 기준을 TypeSafeClassifier.invoke에 전달합니다. 반환된 choice와 해당 선택의 probability, confidence를 본 뒤 예제의 두 기준을 적용합니다. 아래 경계값 과제의 숫자는 수업용 입력입니다. 기본 실행은 실제 모델의 확률이나 정확도를 측정하지 않습니다. Jev 계정 없이도 같은 경계값 실습을 할 수 있습니다.

셀 04 · 선택 실습 · Jev 분류 호출

기본값에서는 네트워크를 호출하지 않습니다. 강사가 수업 커널에 langchain-typesafe와 키를 준비한 경우에만 한 건을 요청하세요. 키 값은 출력하지 않습니다.

실행 결과

Jev 실제 호출을 선택하지 않았습니다.

기본 실행에서는 호출을 건너뜁니다. 실제로 요청한 경우에는 선택값, 그 선택의 확률, confidence가 나옵니다. 다음 과제의 0.80과 0.49는 경계 판단을 연습할 예시이며 이 요청의 실측값이 아닙니다.

선택 실습의 실제 호출 조건

기본값 run_jev=False에서는 분류 서비스를 호출하지 않습니다. True로 실행해 응답을 받은 경우에만 선택지, 해당 선택지의 확률, confidence를 실제 반환값으로 읽습니다.

과제 05 · 확신도가 낮은 결과 처리

분류값이 billing 또는 technical이고 probability가 0.75 이상, confidence가 0.50 이상일 때만 선택을 수용하세요.

풀이와 실행 결과 보기

실행 결과

clarify

확률 0.80은 기준을 넘지만 confidence 0.49가 부족해 clarify입니다. 실제 운영 문턱은 평가 자료로 따로 정해야 합니다. 실제 분류까지 비교할 때는 수업용 키가 설정된 커널에서 Jev 셀의 run_jev를 True로 바꾸세요. 같은 문의에서 받은 분류와 직접 잰 응답 시간을 기록하세요. 기본 실행의 규칙 결과에서는 그 두 칸을 비워 둡니다.

분류가 맞아 보여도 확신도가 낮을 때

과제는 technical과 함께 probability 0.80, confidence 0.49를 제공합니다. 선택지 문자열 하나로 도구를 바로 부르지 말고, 주어진 수용 조건을 둘 다 만족하는지 확인합니다.

풀이와 실행 결과 보기

실행 결과

billing []

분류기는 결제 경로를 골랐지만 이 수업의 allowed에는 technical만 등록했습니다. 응답 화면은 결제 지원 경로를 안내할 수 있습니다. 분류 결과만 보고 첫 번째 기술 도구를 실행하면 다른 업무의 답이 나옵니다.

06

분류 후보를 실제 호출 가능 목록과 맞추기

분류기가 technical을 골라도 서비스에 연결한 도구가 없거나 판단이 모호하면 곧바로 실행할 수 없습니다. 앞의 rule_route와 technical_faq를 이용해 분류값을 검사하는 부분과 도구를 호출하는 부분을 나눕니다.

셀 08 · 분류 데이터에서 실행 후보 한 건 고르기

아래 점수는 실제 모델 요청을 대신하는 수업용 입력입니다. confidence 기준 0.70은 이 서비스가 실험해 보는 값입니다. 기존 예제에 등록한 도구 이름을 예상하고 실행하세요.

실행 결과

['technical_faq']
401 오류는 키 설정과 실행 환경을 확인하세요.

technical_faq가 실제 목록에서 찾아졌고 호출 결과에 키 설정과 실행 환경 안내가 보입니다. 점수가 높아도 registry에 해당 분류가 없다면 빈 목록이 돌아옵니다. 분류 후보와 실제로 연결된 도구는 서로 다른 값입니다.

과제 09 · 도구가 없는 분류는 추가 질문으로 돌리기

영수증 문의는 rule_route가 billing으로 분류하지만 이번 등록 목록에는 결제 도구가 없습니다. 등록된 도구가 하나이고 분류 기준을 통과했을 때만 호출하는 응답 함수를 만드세요. 모호하거나 실행할 도구가 없으면 도구 호출 없이 확인 문장을 돌려주세요.

정답 코드와 실행 결과 보기

실행 결과

('billing', '담당 분야와 안내 가능한 범위를 확인할게요.')
('technical', '담당 분야와 안내 가능한 범위를 확인할게요.')

첫 줄은 billing이 선택됐지만 등록된 도구가 없어서 멈춥니다. 둘째 줄의 technical에는 도구가 있지만 점수가 낮아서 같은 안내로 갑니다. 두 경우를 개선하는 방법은 다릅니다. 앞의 경우는 도구 연결을, 뒤의 경우는 질문을 어떻게 명확히 할지 점검하세요.

분류기의 확신이 높아도 등록한 도구 목록을 확인해야 합니다. 분류 정확도와 서비스가 처리할 수 있는 범위는 별개입니다. 낮은 확신과 미등록 분야를 나눠 기록하면 보류 이유를 찾을 수 있습니다.

선택 Jev 호출을 실행한 학생은 실제 result.choice와 result.confidence를 같은 경로에 넣어 규칙 분류와 차이를 확인할 수 있습니다.
