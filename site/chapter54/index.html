02

WHERE에 문서 ID와 소유자 조건 결합

SQL 매개변수는 쿼리의 자리표시자에 값을 별도로 전달합니다. 트랜잭션에서는 변경을 확정하기 전에 되돌릴 수 있습니다.

강의 원자료와 같은 문서 ID로 작은 SQLite 메모리 표를 준비합니다. 쿼리 문자열의 ?는 SQLite용 값 자리입니다. 입력값을 SQL 문장에 직접 이어 붙이지 않고 별도 튜플로 넘깁니다. PostgreSQL의 psycopg에서는 이 자리를 %s로 씁니다.

초안이 보입니다. 문서 ID가 같아도 WHERE 조건의 owner가 다르면 같은 행을 읽을 수 없습니다. 실제 서비스의 owner는 인증을 마친 요청에서 정해야 합니다.

‘초안’이 조회됐다는 사실은 해당 행의 저장을 확인해 줍니다. 다른 사용자가 같은 문서 번호로 조회하거나 수정할 수 있는지는 별개입니다. 다음 쿼리에서 문서 번호와 소유자를 함께 조건에 넣어 접근 범위를 제한합니다.

문서 한 건을 담는 테이블

course_documents의 id는 문서 한 건을 구별합니다. title과 content에는 각각 제목과 본문을 저장하고 owner에는 소유자를 저장합니다. 첫 셀이 초안을 넣고 commit한 뒤에는 이 행을 기준으로 수정 전후를 비교할 수 있습니다.

테이블이 저장을 거부하는 값

이 예제에서 id는 PRIMARY KEY이고 title과 owner에는 NOT NULL이 붙습니다. 같은 문서 ID를 다시 저장하거나 제목에 NULL을 넣으면 제약 위반입니다. owner 열에는 별도의 외래키가 선언되어 있지 않습니다.

03

UPDATE와 rollback()

트랜잭션은 함께 확정하거나 되돌리는 변경의 단위입니다. UPDATE 직후 같은 연결에서는 바뀐 제목을 읽을 수 있습니다. 커밋 전에 롤백하면 앞서 커밋한 초안으로 돌아갑니다.

셀 03 · UPDATE 직후 행 조회

아직 commit을 호출하지 않습니다.

실행 결과

수정한 초안

수정한 초안입니다. 이 출력은 같은 연결에서 새 값을 읽었다는 증거이며 변경이 영구 저장됐다는 증거는 아닙니다.

문서를 새로 넣기와 제목 바꾸기

INSERT는 새 ID와 소유자·제목·본문을 한 행으로 저장합니다. 뒤의 UPDATE는 WHERE에서 같은 문서 ID와 소유자를 모두 지정하고, 이미 있는 행의 title만 수정한 초안으로 바꿉니다.

셀 04 · rollback()으로 변경 취소

위 셀 직후 rollback을 호출해 처음의 행을 다시 조회합니다.

실행 결과

초안

초안이 복구됩니다. UPDATE 직후에 commit을 넣으면 이어지는 rollback은 이미 확정한 변경을 되돌리지 못합니다.

마지막 커밋으로 돌아가기

초안을 INSERT한 뒤 한 번 commit했습니다. 이어 UPDATE하면 같은 연결의 SELECT에는 수정한 초안이 보입니다. 여기서 rollback하면 마지막 커밋 이후의 UPDATE만 취소되어 문서 행은 남고 제목이 초안으로 돌아갑니다.

삭제한 같은 행을 두 번 조회하세요. 첫 조회는 DELETE 직후, 두 번째는 rollback() 직후입니다. 문서 제목이 돌아왔는지는 두 번째 출력에서 확인합니다.

DELETE와 대상 행 검사

DELETE는 조건에 맞는 행을 지웁니다. 열 하나를 비우는 UPDATE와 다릅니다. 아래 문장은 오늘 만든 새 실습 문서 한 행만 대상으로 삼습니다. WHERE가 빠진 DELETE는 테이블의 모든 행을 대상으로 하므로 그대로 실행하지 않습니다.

sql/054_changes.sql은 BEGIN부터 COMMIT까지 한 묶음으로 제공합니다. 삽입한 제목은 초안, 수정 후 제목은 수정한 초안, 삭제 뒤 조회는 0행이 예상됩니다. 마지막에 행이 없는 이유는 오류로 되돌렸기 때문이 아니라, 묶음 안에서 그 행을 삭제하고 확정했기 때문입니다.

04

선택 실습 · PostgreSQL 값 바인딩

준비한 커널에서는 psycopg로 PostgreSQL의 임시 연습 표를 만듭니다. 실행 중 만든 표와 행은 트랜잭션 끝에 롤백합니다. 기본 연결은 53장에서 강사가 설정한 수업용 DB를 사용합니다.

셀 06 · 선택 실습 · 매개변수 바인딩

HK_COURSE_USE_POSTGRES=1과 수업용 연결이 준비되면 아래 블록이 실행됩니다. 저장소의 영구 테이블에는 쓰지 않습니다.

실행 결과

PostgreSQL 변경은 준비된 수업 커널에서 확인하세요.

실행한 PostgreSQL에서는 “조회문 복습”이 나와야 합니다. 접속 준비 안내는 PostgreSQL에서 변경이 성공했다는 뜻이 아닙니다. 앞에서 실행한 메모리 실습은 SQL 변경 순서를 확인한 결과입니다. 서버 실습에는 psycopg, 수업용 PostgreSQL 연결, 임시 테이블 생성 권한이 필요합니다. HK_COURSE_USE_POSTGRES=1인 수업 커널에서 실행한 뒤 바인딩한 제목과 다시 읽은 값을 비교하세요.

선택 셀의 PostgreSQL 연결

이 셀은 psycopg가 설치되고 HK_COURSE_USE_POSTGRES 값이 1일 때 연결을 엽니다. 연결이 준비되면 임시 테이블 hk_note에서 값을 바인딩해 저장·조회하고 rollback합니다. 기본 SQLite 셀은 PostgreSQL 연결 없이도 실행할 수 있습니다.

SQLite의 ?와 Psycopg의 %s

기본 셀의 sqlite3 쿼리는 값 자리에 ?를 씁니다. PostgreSQL 선택 셀에서는 psycopg가 %s를 사용합니다. 두 경우 모두 SQL과 전달할 값을 execute의 별도 인수로 넘깁니다. 자리 표시자가 달라도 문자열을 붙여 SQL을 만드는 과정은 없습니다.
