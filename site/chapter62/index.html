패키지 모듈을 찾을 수 없으면 55–56일에 사용한 수업 환경이 선택됐는지 먼저 확인합니다. 이번 작성에서는 새 설치나 환경 해결을 수행하지 않았습니다. mcp가 없다는 사실은 직접 도구 검사를 할 수 없다는 뜻이 아니며, 직접 도구 검사가 통과했다는 사실도 MCP가 설치됐다는 뜻이 아닙니다.

먼저 같은 함수를 LangChain Tool로 호출하기

DirectEndpoint는 get_library_hours를 같은 프로세스 안에서 부릅니다. make_tool은 day를 받는 함수를 StructuredTool로 만들어 create_agent에 전달합니다. coroutine은 기다릴 수 있는 실행 함수를 지정하는 자리이며, 이 예제는 직접 경로와 원격 준비 경로의 호출 형태를 맞추기 위해 모두 비동기 함수로 제공합니다.

response_format=content_and_artifact는 모델에게 전달할 JSON 문자열과 코드가 검사할 사전을 함께 남기게 합니다. 화면에 읽히는 content만 보고 원본 결과를 잃지 않도록 artifact에 같은 세 필드를 보관합니다. 도구를 등록했어도 실행 허용 목록과 인자 검사는 별도로 적용됩니다.

generation_calls는 도구를 요청하지 않는 응답을 받은 횟수입니다. 여기서는 두 번째 대본 응답이 한 번이므로 1입니다. 실제 외부 모델 호출은 0이며 토큰·요금·응답 시간은 측정하지 않았습니다.

도구 실행부를 결과 어댑터로 바꾸기

FixtureEndpoint는 직접 만든 MCP 결과 모양 사전을 normalize_result에 넘깁니다. 이 경로로 결과 형식·오류 표시를 검사할 수 있지만 initialize나 HTTP 메시지를 주고받지 않습니다. 실제 SDK의 내부 동작까지 모의한 것으로 설명하지 않습니다.

SessionEndpoint는 열린 공식 ClientSession을 받는 준비 코드입니다. 도구 요청을 session.call_tool에 전달하고 돌아온 SDK 객체를 사전으로 변환해 같은 normalize_result로 읽습니다. 이 경로를 사용하려면 실제 연결이 열려 있어야 합니다. 닫힌 세션을 나중에 호출하도록 저장하지 않습니다.

connected_agent.py는 실제 SDK 환경에서 사용할 준비 코드입니다. session_for의 with 블록 안에서 초기화하고 세션을 넘깁니다. main은 그 블록이 열린 동안 run_case를 기다립니다. 작업이 끝나면 context manager가 연결을 정리합니다.

stdio는 Client가 자식 서버를 시작하고, HTTP는 이미 실행 중인 제공 서버로 연결합니다. 두 방식의 결과가 같을 수 있어도 연결 방법과 종료 책임은 다릅니다. 현재는 두 경로 모두 실행하지 않았으므로 코드의 존재를 통신 성공의 증거로 삼지 않습니다.

Streamable HTTP 제공 주소와 접근 제한 읽기

제공 HTTP 주소는 http://127.0.0.1:8916/mcp입니다. 127.0.0.1은 이 컴퓨터를 가리키며 포트 8916은 제공 서버의 연결 위치입니다. /mcp는 요청을 받을 경로입니다. server_http.py는 공식 FastMCP 앱을 제공 ASGI 구성에 붙입니다. 이 단계에서 FastAPI나 ASGI 프레임워크의 내부 구현을 선수 지식으로 요구하지 않습니다.

ClassroomGate는 공개된 수업 표식 헤더와 허용 Host/Origin을 확인합니다. 표식이 없거나 다르면 401, 허용하지 않은 Host/Origin이면 403을 반환하며 안쪽 앱을 호출하지 않습니다. 이 표식은 누구나 소스에서 볼 수 있으므로 실제 사용자를 인증하거나 계정별 권한을 보장하지 않습니다.

adapter-comparison.json의 cases에는 평일과 주말이 있습니다. 각 case에는 direct와 provided_result_fixture가 있고, 질문·인자·data_version·tool_name을 같은 값으로 유지합니다. 정상 결과의 answer와 data가 같은지는 그다음에 비교합니다.

두 모드에서 모델 2회·도구 실행 1회·생성 1회를 관찰했습니다. 이는 대본이 한 번 요청하고 한 번 답하는 방식이 같기 때문입니다. 프로토콜이 더 빠르거나 모델이 더 정확하다는 결론은 낼 수 없습니다. latency_ms, provider_usage, monetary_cost는 미측정이므로 null입니다.

A62-2 · 같은 입력과 같은 성공 결과를 따로 판정하기

student_task.py의 compare_records는 실행된 두 기록을 읽는 과제입니다. 새로운 모델이나 서버를 호출하지 않습니다. question, arguments, data_version, tool_name 네 값이 같으면 same_input을 True로, 두 run_status가 completed이면 both_completed를 True로 돌려줍니다.

same_result는 same_input과 both_completed가 모두 참이고 두 result가 같을 때만 True입니다. 두 실패가 모두 None인 경우를 정상 비교로 통과시키지 않는 것이 핵심입니다. 입력 기록은 수정하지 마세요. 수정된 기록으로 비교를 통과시키면 관측 근거가 사라집니다.

선택 과제는 자신의 평일·주말 기록 두 개를 비교표로 정리하는 것입니다. 실제 MCP가 준비되지 않았으면 새 서버를 설치해 선택 과제를 수행하지 않고 미검증 항목을 설명합니다.

A62-3 · 필요한 연결 방식만 선택해 인계하기

63일은 필요한 기능의 연결 방식을 선택합니다. 95일의 필요한 도구나 101일의 Skill/API/MCP 채택에도 이 기록을 참고할 수 있지만 모든 팀에 MCP가 필요한 것은 아닙니다. 지금의 가상 도서관 도구가 팀 문제와 무관하다면 채택하지 않은 이유와 기존 경로를 남깁니다. MCP 미채택을 실패로 채점하지 않습니다.
