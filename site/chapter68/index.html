FastAPI 요청 모델과 POST 엔드포인트 심화 읽기

HTTP 요청의 구성

HTTP 요청은 메서드, 경로, 헤더, 본문으로 읽으면 편합니다. GET /health는 프로그램이 어떤 예제인지 읽습니다. POST /ask는 JSON 질문을 전달합니다. POST라는 이유만으로 데이터베이스에 저장되는 것은 아닙니다. 이 장은 저장하지 않습니다.

응답의 HTTP 상태는 요청을 어떻게 처리했는지 알려 줍니다. JSON 안의 result.status는 근거와 생성 답을 어떻게 판단했는지 알려 줍니다. 둘을 하나의 success 변수로 줄이면 다음 장의 실패 기록에서 정보가 사라집니다.

Pydantic 입력 조건

요청 모델은 question과 k만 받습니다. question은 문자열이며 양끝 공백을 제거한 뒤 빈 값을 거부합니다. k는 1~10의 정수이고 기본은 2입니다. Python에서 bool은 int와 가까운 타입이지만 StrictInt는 true를 검색 개수 1로 받지 않습니다.

extra=forbid는 user_id나 model 같은 추가 키를 조용히 무시하지 않고 거부합니다. 클라이언트가 alice를 적었다고 신뢰한 사용자 문맥이 되지 않습니다. 현재 장의 alice는 서버 예제에 고정한 수업 대역입니다.

실행 상태와 답변 필드

A1은 status, answer, sources, generation_calls 네 값입니다. sources 안의 각 객체는 id, text, source, page를 가집니다. source 이름 하나만 반환하면 같은 답의 여러 인용과 페이지를 잃습니다.

S1 외피는 이 A1 바깥에 request_id, run_status, metadata와 실패 정보를 둡니다. completed라면 A1이 있고 error라면 result=null입니다. 읽기 경로는 승인 대기나 action_receipt를 답으로 내보내지 않습니다. metadata의 호출 수와 trace도 보존해야 앞 장과 비교할 수 있습니다.

경로 함수와 서비스 호출

create_app은 앱을 만드는 함수입니다. 경로 함수 ask는 Pydantic이 확인한 요청을 handle_ask로 넘기고 반환의 상태와 JSON을 응답으로 내보냅니다. 실제 FastAPI가 없는 환경에서는 이 앱 생성 자체를 실행한 것으로 기록하지 않습니다.

read_answer는 로컬 TrustedContext를 검수된 S1 AppContext로 바꿉니다. 동일 사용자와 대화 하나의 소유 관계로 서비스를 구성합니다. 69일에는 이 구성 전에 대화 소유 조회가 추가됩니다. owners 내부를 나중에 직접 바꾸는 방식은 사용하지 않습니다.

Python·HTTP 호출의 결과 비교

test_q01_same_s1 검사는 S1Service.answer를 직접 부른 결과와 handle_ask를 거친 결과를 비교합니다. question, k, 자료 버전이 같아야 의미 있는 비교입니다. 요청 ID는 매번 새로 생길 수 있으므로 A1·metadata와 구분합니다.

이 로컬 비교는 “HTTP에서도 같다”는 증거가 아닙니다. check_http_prepared.py는 같은 질문을 TestClient에 보내는 준비 코드입니다. 그 명령이 실제로 통과한 다음에 HTTP 앱 경계의 동등성을 말할 수 있습니다. 현재 기록의 http=not_run을 유지하세요.

빈 근거와 인용 실패 응답

주차 질문처럼 제공 자료에 근거가 없으면 no_evidence와 빈 sources, generation_calls=0을 반환합니다. 검색은 정상 수행됐지만 생성할 근거가 없었다는 뜻입니다. 검색이 시간 초과로 실패한 경우와 다릅니다.

invalid_citation은 생성한 문장의 인용이 허용 근거와 맞지 않아 안전한 검토 문구로 바꾼 결과입니다. 생성은 1회였지만 sources는 비어 있습니다. 이 상태를 answered로 바꾸거나 실패를 숨기는 일반 답을 만들지 않습니다.

요청 검증과 상류 출력 오류

handle_ask는 요청 검증 실패를 422로 분류하고, 서비스가 반환한 불량 외피는 502 service_output으로 분류합니다. 서비스 내부 오류를 사용자가 잘못 입력한 것처럼 처리하지 않습니다. 유효한 S1 error 외피는 metadata까지 보존하며 HTTP 상태만 별도로 선택합니다.

metadata에 Any가 있어도 모든 Python 객체를 JSON으로 보낼 수 있는 것은 아닙니다. 숫자 키나 tuple은 JSON 왕복에서 타입이 바뀌고 NaN은 표준 JSON 숫자가 아닙니다. UTF-8로 인코딩할 수 없는 문자열도 전송 전에 거부합니다. 검사가 끝나기 전에 스트림을 시작하지 않는 이유가 다음 장에서 드러납니다.

실패 상태를 보존하는 요약 함수

student_task.py의 summarize(response)를 구현합니다. 입력은 status_code와 body가 있는 순수 경계 결과입니다. 출력은 http_status, run_status, a1_status, source_ids, error_type, failure_stage입니다. result=null일 때 A1 필드를 억지로 만들어 채우지 않습니다.

입력 객체를 변경하지 않는 것도 과제 조건입니다. 요약 함수 때문에 원래 metadata나 sources를 지우면 원본 결과를 비교할 수 없습니다. 요약은 화면 기록용이고 전체 응답을 대신 저장하는 계약이 아닙니다.
