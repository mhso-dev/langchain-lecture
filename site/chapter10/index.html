실행을 확인한 커널은 Python 3.12.15입니다.

대화 UI와 API 입력

서비스 UI는 사람이 화면에서 입력하고 결과를 읽는 제품입니다. API는 프로그램이 정해진 요청 형식으로 외부 기능을 호출하는 접점입니다. UI에서 편리하게 제공되는 검색·파일·대화 기록이 API에서도 자동으로 같은 방식으로 제공된다고 가정하지 않습니다.

예를 들어 UI에서는 사용자가 파일을 선택하고 답변을 읽지만 프로그램에서는 어떤 입력을 보낼지, 응답을 어디에 저장할지, 오류와 사용량을 어떻게 처리할지를 코드로 정해야 합니다. API 사용 조건과 비용도 해당 서비스의 별도 안내를 확인해야 합니다. 오늘은 API 키를 발급하거나 결제하지 않습니다.

02

주장과 출처 문장 대응

답변을 검증할 때는 한 문장을 확인 가능한 주장으로 나누고 각 주장을 뒷받침하는 원문을 찾습니다.

가상 원문에 줄 번호를 매겨 두면 다른 사람이 어디를 확인해야 하는지 알 수 있습니다. 자료 이름까지 함께 남겨 같은 번호가 다른 문서를 가리키는 일을 막습니다.

공유 가능한 입력 고르기

예제의 가상 안내문에서 정원과 예약일에 관한 문장만 골라 봅니다. 실제 업무 자료를 사용할 때는 연락처나 계정 정보처럼 이 판단에 필요 없는 부분을 제외하세요.

셀 01 · 원문에서 정원 근거 추출

원문 3행에서 학생이 확인할 수 있는 사실을 읽으세요.

실행 결과

참가 대상은 성인 20명이다. 참가비는 없다.

성인 20명과 무료 참가비가 나옵니다. 원문의 줄 번호는 1부터, 리스트 인덱스는 0부터 세므로 3행을 읽을 때는 [2]를 씁니다.

하나의 주장을 하나의 근거와 짝짓기

한 답에 정원과 예약 가능일이 함께 적혀 있으면 둘을 떼어 확인합니다. 정원을 입증하는 문장을 찾았더라도 예약 가능일까지 확인한 것은 아닙니다.

셀 02 · 예약일 주장의 근거 검사

초안이 ‘예약은 12월 1일부터’라고 했습니다. 신청 관련 원문을 직접 고릅니다.

실행 결과

예약 시작일과 신청 링크는 아직 정하지 않았다.

시작일과 링크는 아직 정하지 않았습니다. 날짜를 지울 때는 예약 제도 자체까지 지우지 말고 확인된 상태를 밝혀 주세요.

검색 결과와 1차 출처

검색 결과의 짧은 설명은 원문 전체가 아닙니다. 결과에 표시된 제목·날짜만 보고 사실을 확정하지 말고 연결된 페이지를 열어 해당 내용을 읽습니다. 검색 엔진이 보여 주는 날짜와 정책의 적용 날짜가 다를 수 있으므로 둘을 구분합니다.

가상 행사 세부사항은 웹에서 확인할 수 없습니다. 검색 실습은 실제 사용하는 서비스의 공식 도움말에서 지원 파일 형식을 확인하는 별도 과제로 진행합니다. 가상 행사 날짜를 인터넷에서 찾으려 하지 않습니다.

공식 문서 두 개가 다르게 보이면 최신 문서인지, 제품과 계정 유형이 같은지, 적용 지역이나 플랫폼이 같은지 확인합니다. 해결하지 못하면 어느 조건에서 충돌하는지를 기록하고 확정 표현을 보류합니다.

03

근거 부재와 미확정 정보 구분

‘예약 날짜는 미정이다’는 원문 상태를 전달하는 문장입니다. 반면 ‘12월 1일부터 예약 가능’은 이 자료에서 뒷받침할 수 없습니다. 같은 항목이어도 기록할 상태가 다릅니다.

과제 03 · 검증된 사실과 출처 기록

행사장의 위치를 claim, source, location, status로 기록하고 위치가 든 근거를 출력하세요.

신청 링크 행은 두 칸으로 판단합니다. ‘원문 근거’에는 5행에서 링크 안내를 확인했다고 쓰고, ‘실제 URL’에는 아직 미정이라고 씁니다. 원문에 안내가 있다는 사실만으로 링크 주소를 채울 수는 없습니다.

셀 04 · 문서 간 수치의 의미 비교

아래 시설 카드도 수업용 가상 자료입니다. 세미나실에 30명이 앉을 수 있다는 문장을 읽고, 행사 정원을 30명으로 고칠 근거인지 판단하세요.

실행 결과

20명은 이번 행사에서 받을 인원이고 30석은 방의 좌석 수입니다. 두 숫자를 비교하려면 먼저 항목이 같은지 확인해야 합니다. 출처를 한 건 더 찾았어도 정원을 바꿀 근거는 생기지 않았습니다.

이미지 판독 결과와 원문 대조

이미지는 글자뿐 아니라 위치·색·도형을 함께 보여 줍니다. 작은 글씨, 흐린 사진, 표의 행과 열 때문에 내용이 잘못 읽힐 수 있습니다. 모델이 읽은 문장을 원본의 해당 영역과 나란히 비교하세요.

실습에서는 가상 안내문을 본인 컴퓨터에서 화면 캡처하거나 강사가 제공한 가상 포스터 이미지를 사용합니다. 개인정보가 보이는 바탕화면이나 다른 창이 캡처되지 않도록 범위를 먼저 확인합니다.

첫 요청에서는 이미지를 바탕으로 문서를 새로 꾸미기보다 보이는 항목을 그대로 추출하도록 합니다. 읽을 수 없는 부분을 추측하지 말고 확인 필요라고 표시하도록 요청하세요. 정확한 숫자가 중요한 항목은 사람이 확대해서 다시 읽습니다.

게시 전 검토 기준과 인계
