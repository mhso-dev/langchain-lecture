입력·실행 순서·기대 출력 명시

재현 기록에는 다른 사람이 같은 입력을 준비하고 기대 출력을 확인할 만큼의 정보가 있어야 합니다.

README 실행 예시 · 50장 노트북에서 Q03의 답에 ‘담당 강사에게 문의’와 [course-guide-v1:p3]가 있는지 확인하세요. Q01도 같은 장에서 대조할 수 있습니다. Q02의 점수 질문은 이 노트북의 실행 사례에 포함되지 않으므로, 이를 시연하려면 팀이 별도의 질문과 실행 기록을 준비합니다.

셀 01 · 기대 답변의 재현 조건

README에 적을 기대 답변에서 ‘담당 강사에게 문의’와 [course-guide-v1:p3]를 찾아보세요. 50장 Q03의 실행 결과를 함께 열면 실제 답에도 두 문구가 있는지 따로 대조할 수 있습니다.

실행 결과

True

True는 이 문장에 두 확인 조건이 있다는 뜻입니다. 사용자한테도 이해되는지는 동료가 직접 답과 원문을 읽어야 알 수 있습니다.

03

재실행 기록과 환경 범위

제공 재현 기록은 같은 컴퓨터의 같은 인터프리터에서 후보 파일을 새 폴더로 복사해 회귀 출력을 비교했습니다. 새로 설치했거나 동료의 Windows에서 성공했다는 뜻으로 기록하면 다음 사람이 실패 지점을 찾기 어렵습니다.

셀 02 · 동일 환경 재실행의 검증 범위

제공 기록의 환경과 비교 결과를 꺼냅니다. 이 셀은 과거 관찰을 읽으며 현재 컴퓨터에 패키지를 설치하지 않습니다.

실행 결과

{'same_regression_bytes': True, 'clean_install': 'not_run', 'new_os': 'not_run', 'peer_reproduction': 'not_run'}

회귀 파일은 같고 새 설치·다른 OS·동료 재현은 not_run입니다. 팀 발표에서 실행이 막혔다면 기록을 대신 열어 “제공 결과 분석”이라고 알리고, 실패한 셀과 오류 내용을 남기세요.

같은 회귀 결과를 바이트 단위로 재현했더라도 clean_install과 new_os에는 not_run이 남습니다. 인수인계 자료에는 사용한 환경과 실행 명령을 싣고, 새 설치 환경에서 같은 절차를 수행한 기록은 별도 항목으로 둡니다.

재현 기록이 증명하는 범위

same_regression_bytes가 True이면 비교한 회귀 결과 파일이 같습니다. 그러나 clean_install, new_os, peer_reproduction은 각각 not_run입니다. 같은 파일이라는 관찰로 다른 운영체제에서도 재현됐다고 결론낼 수는 없습니다.
