MCP 도구와 LangChain 에이전트 연결

61장의 MCP 서버에 LangChain 도구를 연결합니다. 주말 운영 시간 요청을 열린 세션으로 전달하고 응답의 요일·시간과 도구 메시지를 대조합니다.

입문교육일 062 · 8H55–56일 create_agent·실행 정책 · 61일 MCP 함수·결과
01

실습 노트북과 실행 환경

↓62장 수업 노트북 (.ipynb)Jupyter에서 열고 Python 커널을 선택한 뒤 위에서부터 실행하세요.↗

실행을 확인한 커널은 Python 3.12.15입니다. 예제에 사용한 외부 패키지는 langchain 1.4.6, langchain-core 1.6.12, langsmith 0.14.11, mcp 1.30.0입니다.

02

클라이언트 세션과 도구 어댑터

LangChain 도구가 MCP 서버의 함수를 호출하려면 클라이언트 세션이 열려 있어야 합니다. 응답의 형식과 요청에 해당하는 값이 돌아왔는지를 따로 확인합니다.

제공 셀에는 두 가지 코드가 있습니다. 위쪽은 서버의 시간표이고, 다음 셀의 어댑터는 LangChain 도구의 day 인자를 MCP 요청으로 바꿉니다. 메모리 전송이므로 원격 서버 배포나 인증 설정 없이 왕복을 확인할 수 있습니다.

셀 01 · FastMCP 도구 서버 준비

같은 서버, 같은 두 요일, 같은 자료 버전을 유지합니다.

지금은 도구를 등록했습니다. 다음 셀에서 연결을 열 때까지 요청 횟수는 늘지 않습니다.

셀 02 · LangChain 도구에서 MCP 호출

ainvoke로 호출한 도구가 세션을 통해 받은 운영 시간만 돌려주게 합니다.

에이전트에는 lookup이라는 도구가 보입니다. lookup이 받은 day를 session.call_tool로 넘길 때 서버에는 get_library_hours라는 이름을 보냅니다. 서버 결과의 시간이 도구 메시지 내용으로 돌아오는 지점을 찾아보세요.

실행 결과

10:00~16:00

lookup은 생성될 때 전달받은 session으로 get_library_hours를 호출합니다. 따라서 에이전트의 실행까지 async with 블록 안에서 마쳐야 같은 연결로 결과를 받을 수 있습니다.

주말 시간 문자열이 돌아왔어도 어느 경로에서 얻었는지 구분해야 합니다. 여기서는 LangChain 쪽 도구 호출이 MCP 서버의 함수를 거칩니다. 연결 코드를 수정한 뒤에는 사람이 읽는 시간뿐 아니라 요청한 요일과 응답의 요일도 대조합니다.

LangChain 도구가 호출하는 MCP 도구

lookup.ainvoke에 weekend를 주면 어댑터가 같은 day를 MCP의 get_library_hours에 보냅니다. Python 쪽 lookup과 서버에서 등록한 도구의 이름은 서로 달라도 됩니다.

셀 04 · 평일 운영 시간이 도구 메시지에 담기는 과정

셀 02에서는 주말을 직접 요청했습니다. 여기서는 셀 04의 모델이 평일을 요청합니다. 같은 hours-1을 요청과 결과에서 찾아보세요.

STEP 01 · 모델

평일 인자의 도구 요청

대본 모델이 lookup에 전달할 요일과 호출 ID를 만듭니다.

lookup(day="weekday") · id=hours-1
STEP 02 · 어댑터

MCP 세션의 호출 전달

lookup은 현재 열린 세션에서 서버 도구를 부릅니다.

session.call_tool("get_library_hours", {"day": "weekday"})
STEP 03 · 서버

서버의 시간표 조회

서버가 요청 요일과 시간을 돌려줍니다. 어댑터가 요일을 확인하고 hours를 반환합니다.

day = weekday
hours = 09:00~18:00
STEP 04 · 프레임워크

입력 요일과 반환값 대조

도구가 돌려준 시간이 같은 ID의 도구 메시지 본문에 들어갑니다.

ToolMessage · tool_call_id=hours-1
content = 09:00~18:00
STEP 05 · 셀 04

ToolMessage로 결과 반환

마지막 모델 문장은 대본에 들어 있습니다. 실제로 받은 시간은 메시지의 호출 ID와 함께 출력합니다.

hours-1 09:00~18:00

응답의 어느 값을 모델에 넘길까?

MCP는 day와 hours 등이 담긴 결과를 돌려줍니다. lookup은 reply.isError를 먼저 확인하고 반환된 day가 요청과 일치할 때에만 hours 문자열을 넘깁니다.

열린 세션의 수명

make_lookup(session)은 도구가 쓸 세션을 기억합니다. 실제 lookup.ainvoke도 async with 블록 안에서 실행해야 합니다. 블록이 끝나면 연결 수명도 끝납니다.

03

구조화된 도구 결과의 값 검증

운영 시간이 문자열인지 확인하는 것만으로 어느 날의 시간인지 보장할 수 없습니다. 받은 요일과 요청한 요일을 같이 검사합니다. 시간 초과는 이 검사보다 앞서 통신 단계에서 처리해야 합니다.

과제 03 · 요청 인자와 반환값 대조

주말 요청에 돌아온 응답이 평일입니다. 요일 불일치를 찾아내는 조건을 작성하세요.

풀이와 실행 결과 보기

실행 결과

False

요일 비교 결과는 False입니다. 서버가 반환한 값 자체는 ‘09:00~18:00’으로 정상처럼 보이지만 주말 요청에는 쓸 수 없습니다. make_lookup에서 이 경우에 해당하는 오류 이름은 result_day_mismatch입니다.

정상처럼 보이는 다른 요일의 결과

받은 hours가 그럴듯해도 requested가 weekend이고 받은 day가 weekday이면 해당 요청의 답으로 쓸 수 없습니다. 이 경우 어댑터는 result_day_mismatch로 중단합니다.

04

create_agent와 ToolMessage의 결과 전달

평일 요청 한 건을 내는 대본 모델을 실제 create_agent에 연결합니다. 최종 답안은 대본에 고정했으므로 도구가 어디에서 무엇을 가져왔는지는 도구 메시지로 확인하세요.

셀 04 · ToolMessage에서 도구 응답 추출

lookup에 등록한 실행 함수가 MCP를 한 번 부릅니다. 수업용 모델과 서버 모두 네트워크를 사용하지 않습니다.

실행 결과

hours-1 09:00~18:00

hours-1은 에이전트가 요청과 결과를 연결하는 호출 ID입니다. 뒤의 09:00~18:00이 MCP가 반환한 시간입니다. 외부 HTTP 접속 시간이나 원격 인증을 확인한 기록은 아닙니다.

최종 문장과 도구의 반환값

고정 모델의 마지막 답은 ‘조회가 끝났습니다.’입니다. 실제 운영 시간은 요청 hours-1과 짝인 ToolMessage의 content에서 읽습니다.

05

복습과 실습 점검

과제 05 · 서버가 다른 요일을 보냈을 때 거절하기

주말 조회에 평일 값을 돌려주는 응답을 재현하세요. 아래 대역은 네트워크 없이 그 응답만 전달합니다. make_lookup의 요일 검사에서 어떤 오류가 발생하는지 확인하세요.

풀이와 실행 결과 보기

실행 결과

result_day_mismatch

응답에는 정상적인 시간 문자열이 들어 있지만 요청은 주말이고 응답은 평일입니다. 이 검사를 빼면 에이전트는 평일 시간을 주말 답으로 받습니다. 이 과제는 어댑터의 오류 분기만 실행하며 MCP 연결은 앞선 셀에서 확인합니다.
