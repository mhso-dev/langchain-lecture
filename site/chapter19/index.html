03

파이프를 연결하고 한 번 실행하기

LangChain Expression Language(LCEL)의 |는 앞 구성 요소가 돌려준 값을 다음 요소에 건넵니다. 수업 환경에 langchain-core가 설치되어 있으면 아래 셀로 실제 체인을 만듭니다. FakeListChatModel은 고정 답변을 내는 수업용 모델입니다.

셀 03 · 완성된 프롬프트의 마지막 메시지

모델을 부르기 전에 ChatPromptTemplate이 만든 값에서 질문을 먼저 꺼내 봅니다.

실행 결과

대출은 며칠인가요?

마지막 메시지에는 ‘대출은 며칠인가요?’라는 질문이 들어 있습니다. prompt의 반환값 안에는 system 메시지도 들어 있습니다. 둘을 합친 메시지 묶음이 모델 입력입니다.

셀 04 · invoke로 문자열 받기

고정 모델 뒤에 문자열 파서를 이어 실제 LCEL 경로를 실행합니다.

모델 뒤에서 멈추면 답은 메시지 객체에 담겨 있습니다. 뒤에 StrOutputParser를 연결하면 invoke의 반환값으로 본문 문자열을 얻습니다. 이 노트북의 실행 기록은 langchain-core 1.6.12 기준이고 더 읽기의 1.8.0은 별도 기록입니다.

실행 결과

체인이 실행되면 ‘가상 도서관의 대출 기간은 14일입니다.’라는 문자열이 나옵니다. 파서는 모델이 만든 메시지에서 글을 꺼내고, 지정한 고정 모델은 원문의 사실 여부를 검증하지 않습니다.

06

관련 개념 더 읽기

LCEL은 무엇을 연결하나요?

LCEL은 LangChain 구성 요소의 입출력을 연결하는 표현 방식입니다. Runnable은 invoke 같은 공통 실행 방법으로 사용할 수 있는 구성 요소입니다. 이번 장에서는 복잡한 추상화보다 프롬프트, 모델, 출력 파서 세 개만 연결합니다.

prompt | model | parser에서 |는 문자열을 합치는 기호가 아니라 구성 요소를 순서대로 연결하는 연산입니다. 한 요소의 출력이 다음 요소의 입력으로 들어갑니다. 13장에서 Python 함수로 만든 순차 흐름과 같은 입출력 관점으로 읽으세요.

context는 모델에게 제공할 사실이고 question은 사용자의 질문입니다. 템플릿에 {context}와 {question}을 사용했으므로 invoke 입력에도 두 키가 있어야 합니다. 이름이 다르거나 빠지면 모델을 호출하기 전에 오류가 날 수 있습니다.

system 메시지에 넣는 자료도 자동으로 사실이 되는 것은 아닙니다. 이 예제는 명시된 가상 자료만 사용합니다. 이후 문서 검색 수업에서 context를 직접 작성하는 대신 검색한 문서로 만들 것입니다.

고정 응답 모델로 연결 확인하기

FakeListChatModel은 지정한 응답을 반환하는 테스트용 모델입니다. 여기서는 실제 LLM 서버나 API 키 없이 체인과 파서가 연결되는지 확인하기 위해 사용합니다. 질문을 바꿔도 준비된 답이 나올 수 있으므로 답변 정확도 평가에는 사용할 수 없습니다.

실제 모델을 연결할 때는 같은 채팅 모델 인터페이스를 지원하는 구성 요소로 바꿉니다. 계정 모델·지원 옵션·버전·비용을 확인하고 응답 결과를 별도로 검증해야 합니다.

invoke로 한 번 실행하기

invoke의 결과는 StrOutputParser를 거친 문자열입니다. 파서를 빼고 모델까지만 연결하면 메시지 객체를 받습니다. 문자열과 메시지 객체의 차이를 출력 타입으로 확인하면 뒤 단계에서 잘못된 필드를 읽는 실수를 줄일 수 있습니다.

stream의 조각을 합쳐 비교하기

stream은 출력 조각을 순서대로 받을 수 있는 실행 방법입니다. 조각을 문자열로 합치면 전체 결과와 비교할 수 있습니다. 이번 가짜 모델은 테스트용 방식으로 조각을 내보내며 실제 모델의 토큰 경계나 네트워크 지연을 재현하지 않습니다.

체인에 stream을 호출했다고 모든 구성 요소가 바로 부분 출력을 전달하는 것은 아닙니다. 중간 요소가 전체 입력을 기다린다면 그 지점에서 출력이 모일 수 있습니다. 이번 장은 기본 세 요소의 결과를 관찰하는 범위로 제한합니다.

invoke와 stream은 같은 응답을 두 방식으로 보는 동작이 아니라 서로 다른 두 번의 실행입니다. 이 예제의 FakeListChatModel은 응답 한 개를 반복하므로 두 결과가 같습니다. 실제 모델은 두 번 다른 답을 만들 수 있으며 각각 호출 비용이 생길 수 있습니다. 조각 수 22는 이 고정 문자열을 나눈 결과이지 실제 토큰 수가 아닙니다.

중간 값을 한 단계씩 꺼내 보기

ChatPromptValue는 메시지를 담은 프롬프트 값이며 to_messages()로 system과 human 메시지를 볼 수 있습니다. 채팅 모델의 AIMessage에는 content가 있습니다. StrOutputParser를 거친 뒤에는 문자열 자체를 사용합니다. 설치한 1.8.0에서 표시되는 타입명은 TextAccessor이지만 str의 하위 타입이므로 isinstance(parsed, str)는 True이고 문자열처럼 사용합니다.

이 문자열 파서는 12일에 배운 JSON 스키마 검사나 내용 검증을 수행하지 않습니다. 18일의 입력 검사 책임도 사라지지 않습니다. 모델이 돌려준 문장이 사실인지 확인하려면 별도 근거와 평가가 필요합니다.
