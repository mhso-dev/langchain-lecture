LangGraph StateGraph의 상태와 노드

질문 정리·문서 검색·답변 작성을 StateGraph의 세 노드로 연결합니다. 각 함수의 반환값과 갱신된 전체 상태를 비교합니다. Python 커널에 LangGraph와 langchain-core가 필요하며 검색과 답변은 로컬 규칙을 사용합니다.

02

TypedDict와 노드의 부분 갱신

StateGraph의 노드는 현재 상태를 읽고 바꿀 필드를 반환합니다. 간선은 그 변경을 반영한 뒤 어느 노드를 실행할지 정합니다.

State는 한 질문을 처리하면서 여러 단계가 함께 읽는 값입니다. 여기서는 question에 질문, documents에 찾은 문장 목록, answer에 최종 안내를 담습니다. 노드가 값을 읽어 바꿀 부분만 돌려주면 그래프가 앞 상태에 합칩니다.

노드 실행 순서와 공유 상태

Node는 이번에 실행할 Python 함수입니다. Edge는 어떤 함수 다음에 어떤 함수를 실행할지 정한 연결입니다. State는 실행 중 공유하는 값의 묶음입니다. 문서가 어디에 저장되는지와 어느 함수가 다음에 호출되는지를 한 용어로 섞으면 오류 원인을 찾기 어렵습니다.

예를 들어 질문의 공백을 지우는 normalize는 question을 읽고 question만 갱신합니다. 문서를 고르는 lookup은 question을 읽고 documents를 갱신합니다. 답변을 만드는 compose는 documents를 읽고 answer를 갱신합니다. 이번 그래프에서는 모델이 다음 노드를 고르지 않고 코드의 고정된 연결을 따릅니다.

세 요소를 코드에 대응하기
요소예제변경의 의미
Nodenormalize, lookup, compose처리할 계산을 바꿈
Edgenormalize → lookup실행 순서를 바꿈
Statequestion, documents, answer전달하고 보관할 값을 바꿈

셀 01 · normalize()의 공백 정리

초기 상태를 normalize에 직접 전달해 반환된 필드를 확인합니다.

실행 결과

{'question': '대출 기간은?'}

strip()이 앞뒤 공백을 제거해 {"question": "대출 기간은?"}을 반환했습니다.

normalize(initial)을 직접 호출한 줄에서 결과의 documents를 읽으려고 하면 키가 없습니다. 반환한 것은 이 노드가 바꾼 항목 하나뿐입니다. 그래프에서는 그 항목을 기존 상태에 반영하므로 다음 노드는 정리된 질문과 처음의 빈 문서 목록을 함께 받습니다.

TypedDict 상태 스키마

State는 실행 중 사용할 딕셔너리의 키와 값 형태를 적은 타입입니다. question은 질문 문자열, documents는 문장 문자열의 리스트, answer는 답변 문자열입니다. 실제 값은 graph.invoke에 넘기는 initial에 들어 있습니다. 타입 선언만으로 질문이 자동 생성되지는 않습니다.

TypedDict는 정적 타입 확인을 돕는 선언입니다. 잘못된 자료형이나 빈 입력을 모든 경우 자동으로 막아 주는 런타임 검증기로 생각하지 마세요. 이번 예제는 question.strip() 결과가 비었는지 노드에서 직접 검사합니다.

셀 02 · 노드 반환값과 상태 병합

직접 호출에서는 딕셔너리를 합쳐 그래프가 하는 일을 한 번 따라 해 봅니다.

실행 결과

{'question': '대출 기간은?', 'documents': [], 'answer': ''}

documents와 answer의 빈 값이 남습니다. 두 필드는 이제 검색과 답변 노드가 채울 자리입니다.

노드 하나의 반환값과 그래프의 상태

normalize가 question만 반환해도 기존 documents와 answer는 상태에 남습니다. 직접 호출한 결과와 다음 셀의 병합 결과를 나란히 보세요. 그래프에서는 간선을 따라 다음 노드가 실행될 때 이미 갱신한 질문을 읽습니다. compile()은 연결을 준비하고 첫 실행은 invoke(initial)에서 시작합니다.

선수 개념 · 24장 LCEL로 구성하는 RAG와 인용 검증

노드 함수의 부분 갱신

normalize가 반환한 딕셔너리에는 question 하나만 있습니다. 반환에서 빠진 documents와 answer를 지우라는 뜻이 아닙니다. 이번처럼 별도 갱신 규칙을 지정하지 않은 필드는 해당 키가 반환되면 새 값으로 바뀌며, 반환하지 않은 필드는 유지됩니다.

lookup은 documents만, compose는 answer만 반환합니다. 양쪽이 입력 상태를 직접 바꾸지 않으므로 각 함수를 따로 호출해 어떤 필드를 썼는지 확인할 수 있습니다.

03

add_node()·add_edge()·compile()로 그래프 연결

엣지는 어떤 함수를 다음에 부를지 정하는 연결입니다. START에서 normalize, lookup, compose 순으로 연결한 뒤 END에서 멈춥니다. 검색 결과를 미리 써 넣지 않고 질문에 들어 있는 낱말을 자료와 대조합니다.

셀 03 · StateGraph의 노드와 간선

이번 셀의 lookup은 노트북 안에 넣어 둔 두 가상 문장에서 찾습니다. 등록된 노드 이름과 엣지의 이름을 맞춰 보세요.

초기값부터 normalize, lookup, compose 순서로 따라가세요. 한 노드가 돌려주는 사전은 이번에 바꿀 칸만 담습니다. 나머지 두 칸은 앞 상태의 값을 유지합니다.

실행 결과

도서 대출 기간은 14일입니다.

14일이라는 문장이 나옵니다. lookup이 대출 문장을 골라 documents에 넣었고 compose는 그대로 이어 붙였습니다. 모델에 날짜를 묻는 과정은 없습니다.

노드·간선 등록과 컴파일

StateGraph는 그래프를 만드는 빌더입니다. add_node의 첫 인자는 그래프에서 사용하는 이름이고 두 번째 인자는 실행할 함수입니다. add_edge는 등록한 이름으로 연결합니다. START는 입력을 받은 시작 위치, END는 종료 위치입니다.

compile()은 등록된 노드와 간선을 실행 가능한 그래프로 묶습니다. 이때 lookup의 본문은 아직 실행되지 않습니다. 어느 문장을 골랐는지는 invoke() 뒤의 documents에서 확인합니다.
