02

기본 덮어쓰기와 add_messages의 누적

리듀서는 상태에 새 값이 들어왔을 때 기존 값과 결합하는 규칙입니다. add_messages는 메시지 ID에 따라 새 메시지를 추가하거나 기존 메시지를 갱신합니다.

03

동일한 메시지 ID로 내용 갱신

내용이 비슷해도 ID가 다르면 새 발화입니다. 반대로 ID를 그대로 쓰면 그 발화를 수정할 수 있습니다. 같은 답변 ID를 계속 재사용하면 새 대화가 쌓이지 않는 이유도 여기에 있습니다.

수정 답변의 ID를 바꾸면 새 턴이 생길까요?

초기 목록에 h1과 a1이 있습니다. 같은 수정 답변을 보내면서 리듀서와 ID를 바꾸고 어느 칸이 남는지 보세요.

add_messages에서 같은 a1은 기존 칸을 고쳐 2개, 새 a2는 추가되어 3개입니다. 기본 덮어쓰기에서는 받은 a1만 남습니다.

05

LangGraph의 메시지 리듀서 add_messages 심화 읽기

문자열 목록과 메시지 객체

HumanMessage는 사용자 발화, AIMessage는 모델 측 발화의 역할을 표현합니다. 이 예제는 LLM 없이도 AIMessage 객체를 생성하므로 객체 타입만 보고 실제 모델 호출이 있었다고 판단하지 않습니다. content는 내용, id는 메시지를 구별하고 수정할 때 쓰는 식별자입니다.

역할과 내용을 함께 보존하면 뒤에서 모델에 입력을 구성하거나 도구 결과를 다룰 때 어떤 발화인지 구분할 수 있습니다. 도구 호출 메시지까지 한꺼번에 추가하지 않고 이번에는 human과 ai 두 역할만 사용합니다.

리듀서의 리스트 결합 규칙

PlainState의 messages는 새 리스트를 반환하면 이전 값이 교체됩니다. ChatState의 Annotated 표기는 messages의 타입과 함께 add_messages 갱신 규칙을 지정합니다. Python의 Annotated가 스스로 저장하거나 대화를 이어 주는 것은 아닙니다. LangGraph가 그 규칙을 읽어 상태 업데이트에 적용합니다.

add_messages는 새 ID를 가진 메시지를 추가하고 기존 ID와 같은 메시지는 해당 위치의 내용을 갱신합니다. 문자열이 같은지 비교해 중복을 제거하는 기능으로 이해하면 안 됩니다. 단순 리스트 덧셈과도 다릅니다.

새 응답 메시지의 부분 갱신

respond는 현재 메시지 목록에서 마지막 사용자 메시지를 찾아 응답 한 개를 반환합니다. messages에는 새 응답만 들어 있습니다. ChatState의 갱신 규칙이 기존 사용자 발화와 이 변경분을 합칩니다.

상태의 목록을 직접 append한 뒤 전체 목록을 반환하는 방식은 어떤 변경분을 적용했는지 흐리게 만듭니다. 이 예제처럼 입력은 읽고 새 목록을 반환하면 단위 검사가 쉬워집니다. 응답 ID a1은 단일 응답 비교용 고정값입니다. 다중 응답에 그대로 재사용하는 정책은 아닙니다.

기본 갱신과 리듀서 비교

Python 3.12.x, langgraph 1.2.22, langchain-core 1.8.0 기준입니다. 실제 API 키는 필요 없습니다. 두 그래프는 같은 initial을 받지만 서로 다른 스키마를 사용합니다. 실행 전에 최종 메시지의 개수와 역할을 예상하세요.

메시지 ID에 따른 교체·추가

corrected는 h1 메시지의 내용을 바꿉니다. appended는 h2를 새로 추가하므로 내용이 같아도 두 메시지가 됩니다. 수정하려던 메시지에 새로운 ID를 주면 기존 기록은 남고 새 항목이 추가됩니다. 반대로 새로운 답변에 기존 ID를 재사용하면 이전 답변이 교체될 수 있습니다.
