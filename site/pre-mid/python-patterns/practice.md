# 분실물 게시판 변경 요청서

같은 물건을 직원 화면과 게시판에 올리는 작은 프로그램을 고칩니다. 입력 자료와 기존 동작은 아래에 있습니다. 노트북에서 그날의 변경 요청을 풀고, 펼친 답안과 자신의 결과를 대조하세요. 답이 다르면 처음 다르게 나온 값과 바꾼 줄을 적으세요.

## 접수 기록

| 접수 순서 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 원래 이름 | 텀블러 | 키 | 우산 | 장갑 |

직원은 접수 순서를 언제든 다시 조회할 수 있어야 합니다. 길이가 같거나 우선순위가 같은 물건끼리는 먼저 접수한 물건을 먼저 보여 주세요. 화면을 정렬한 뒤에도 위 표를 원래대로 조회할 수 있어야 합니다.

## 다섯 번의 변경 요청

| 실습 | 직원 요청 | 짝이 건네는 추가 입력 | 제출할 증거 |
|---|---|---|---|
| 1. 정렬 함수 | 같은 자료를 길이순과 사전순으로 조회합니다. | ‘우산’과 ‘장갑’의 접수 순서를 맞바꿉니다. | 두 조회 결과와 원본 보존 테스트, 순서가 달라진 이유 한 문장 |
| 2. 우선 목록 | 비 오는 날은 ‘우산’, 신고 데스크는 ‘장갑’과 ‘키’를 먼저 봅니다. | 신고 데스크의 우선 목록을 비웁니다. | 두 데스크의 첫 물건과 빈 목록에서의 결과 |
| 3. 새 출력 형식 | 일반 텍스트와 굵은 제목에 항목 기호가 붙는 bullet을 추가합니다. | 등록되지 않은 pdf로 출력합니다. | 세 형식의 문자열과 예외가 발생한 함수 이름 |
| 4. 기존 게시판 연결 | 기존 게시판은 이름 주위를 대괄호로 감쌉니다. 출력할 때 양 끝 공백을 지우고 호출도 기록해 주세요. | ‘ 장갑 ’을 입력하고 한 조합에서만 ‘ 키 ’를 다시 호출합니다. | 같은 출력, 두 조합의 서로 다른 기록, 감싼 순서 |
| 5. 운영 코드 선택 | tag 형식과 사용자가 켜고 끄는 호출 기록을 지원합니다. | 형식을 pdf로 바꾸고 기록을 켭니다. | 같은 테스트를 통과한 두 구현과 새 요구 한 건에서 바뀔 위치 |

## 담당자가 확인할 예시

| 요청 | 기대하는 게시 원문 | 기대하는 호출 기록 |
|---|---|---|
| 처음에 기록이 비어 있고, tag로 ‘우산’ 한 줄 출력, 기록 끄기 | #우산 | 빈 목록 |
| 같은 상태에서 tag로 ‘키’ 한 줄 출력, 기록 켜기 | #키 | ‘키’ 한 건 |
| 다시 빈 기록에서 미등록 pdf로 ‘키’ 출력, 기록 켜기 | 예외 발생 | 빈 목록 |

테스트가 멈추면 실패한 줄의 실제 문자열부터 확인하세요. 출력에 성공했는데 기록이 두 번 남았다면 어느 함수에서 목록에 추가하는지 따라갑니다. 두 객체를 겹쳤다면 같은 부가 기능을 두 번 붙였는지도 살펴보세요.

## 팀의 cases.md에 넘길 한 줄

마지막 실습에서 직접 고른 물건과 형식으로 실행하세요. 실제값에는 화면에 보인 문자열과 호출 기록을 함께 써 주세요. 완성한 한 줄을 다음 Git 실습의 cases.md로 옮깁니다.

| 입력(이름·형식·기록·초기 목록) | 기대값(출력·기록) | 실제값(출력·기록) |
|---|---|---|
|  |  |  |

예를 들어 초기 기록이 비어 있고 입력이 물병, tag, 기록 켜기라면 기대하는 문자열은 ‘#물병’이고 목록에는 ‘물병’ 한 건이 남습니다. 자신이 고른 입력과 실행값으로 위 칸을 채우세요.
