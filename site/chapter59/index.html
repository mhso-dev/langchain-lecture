대화에서 꼭 남겨야 할 사실 정하기

이 장의 응답기는 네 사실의 문자열이 입력에 있는지만 찾는 제공 코드입니다. 실제 Graph와 create_agent를 실행하지만 외부 LLM이나 자동 요약 모델을 호출하지 않습니다. 결과를 언어 이해 성능으로 해석하지 않습니다.

29·55·56장의 경계를 같은 질문으로 확인하기

29장에서는 thread_id로 같은 저장소의 대화를 고릅니다. 제공 관찰을 다시 실행하면 A에 두 번 질문한 뒤 메시지 4개, B에 한 번 질문한 뒤 2개가 남습니다. 아직 시작하지 않은 C와 새 저장소의 A에는 메시지가 없습니다. 이 구분은 사용자 인증을 뜻하지 않습니다.

55장의 run_framework와 56장의 run_agent_case는 같은 대출 질문에서 실제 인용된 A1 출처를 유지합니다. 56장의 정상 빈 검색은 no_evidence와 생성 0회이고, Timeout은 result=null인 실행 오류입니다. 질문 내용이나 기억 요약이 호출 허용 목록을 바꾸어서는 안 됩니다.

저장 State와 모델 입력은 다른 목록입니다

State는 현재 실행이 읽고 갱신하는 값입니다. 체크포인터는 같은 thread에서 그 State를 다시 찾을 수 있게 합니다. 이 예제의 turns에는 완료한 과거 턴을 저장하고 question에는 현재 질문을 둡니다. selection은 그중 모델에게 보낼 부분, probe는 이번 관찰 결과입니다.

turns의 add는 새 목록을 뒤에 붙이는 제공 reducer입니다. 같은 턴 ID를 덮어쓰는 방식이 아니므로 이미 저장한 턴을 다음 요청에 다시 넣지 않습니다. 현재 질문만 다시 확인할 때는 turns=[]를 전달합니다. 모델 입력을 줄여도 원본 4턴은 그대로 남습니다.

fixture.json의 한 턴은 id와 messages를 가집니다. T1은 발표 장소를 말한 질문과 확인 응답이고, T4는 분량을 말한 질문과 확인 응답입니다. 최근 두 턴을 선택하면 T3와 T4 전체가 들어갑니다.

도구를 사용한 대화는 사용자 질문, AI의 도구 요청, 같은 호출 ID의 ToolMessage, 마지막 AI 응답까지 묶습니다. 메시지 수만 맞추려고 중간을 자르면 도구 응답만 남거나 요청의 응답이 없어질 수 있습니다. 제공 validate_turns가 중복 턴 ID와 끊긴 왕복을 거부합니다. 이 장의 기본 fixture는 텍스트 대화이며, 56장의 구조화 응답 전체를 그대로 범용 변환하는 기능은 아닙니다.

최근 두 턴에서 사라지는 정보 찾기

full은 완료한 모든 턴을 전달하고 recent는 끝에서 recent개를 고릅니다. 현재 질문은 두 경우 모두 마지막에 붙습니다. 기본 recent=2이면 T3/T4가 남아 기한과 분량은 전달되지만 장소와 언어는 빠집니다.

최근 대화가 짧다는 사실만으로 잘못된 정책은 아닙니다. 이번 작업에서 장소를 다시 확인해야 한다면 이 선택만으로 부족하다는 뜻입니다. 필요한 정보가 빠졌을 때 사용자에게 다시 묻는 조건까지 정책에 포함합니다.

요약은 과거 내용을 짧은 표현으로 바꿉니다. 이 예제는 T1~T3을 대상으로 만든 수작업 요약과 최근 T4를 붙입니다. 제공 요약에는 회의실 B와 한국어가 있지만 금요일 18시는 없습니다. 요약 범위가 T1~T3이라고 적혀 있어도 모든 사실을 보존했다는 뜻은 아닙니다.

요약 대상 ID 검사는 제외한 과거 턴 ID와 요약에 적힌 대상 ID가 같은지 확인합니다. ID가 같아도 내용의 출처와 의미가 맞는지는 원문 대조가 필요합니다. 요약을 원래 시스템 지시로 올리지 않고 과거 대화 자료로 전달합니다. 문서 속 명령을 실행 권한으로 해석하지 않습니다.

토큰은 모델이 입력을 나누어 처리하는 단위입니다. 글자 수와 같지 않으며 모델별 방식도 다를 수 있습니다. 여기서는 설치된 count_tokens_approximately로 입력 크기만 추정합니다. estimate는 고정 SYSTEM과 선택한 대화, 현재 질문을 모두 셉니다.

budget=65는 이 가상 입력에서 오래된 완료 턴을 빼기 위한 수업용 기준입니다. 최신 턴부터 묶음 전체를 넣고, 다음 묶음이 예산을 넘으면 멈춥니다. 현재 질문과 지시만으로도 넘으면 ValueError입니다. 질문을 조용히 자르지 않습니다.

FactProbeModel은 55장의 제공 ScriptedChatModel을 상속합니다. received에는 실제 프레임워크가 넘긴 메시지를 기록하고, 네 사실의 고정 문자열이 있으면 그 값을, 없으면 null을 돌려줍니다. 이 탐침은 의미가 같은 다른 표현을 이해하지 못하고 사실의 참·거짓을 판단하지도 않습니다.

make_memory_graph의 respond는 저장 턴에서 입력을 선택한 뒤 create_agent를 한 번 실행합니다. 56장의 RunContext/BasicPolicy를 그대로 사용하고 허용 도구를 빈 tuple로 두므로 이 관찰에서 도구를 추가 실행하지 않습니다. 각 실행의 정책 객체를 새로 만들어 호출 수가 새지 않게 합니다.

새 결과는 runs/latest/comparison.json에 저장됩니다. examples/observations.json은 작성자가 제공한 고정 관찰입니다. 관찰의 rows 네 행과 entry29, entry55, entry56을 함께 읽으면 선수 경계와 오늘의 실험 범위를 구분할 수 있습니다.

기억 누락과 잘못된 입력을 구분하기

입력이 작아져 고정 사실을 찾지 못하는 일은 비교 결과입니다. 반면 공백 질문, bool을 넣은 상한, 중복 턴 ID, 도구 왕복 누락은 실행 전에 고칠 입력 오류입니다. 둘을 모두 기억 없음으로 적으면 어떤 조치가 필요한지 알 수 없습니다.

validate_turns는 제공 검사 코드입니다. 전체를 새로 구현하는 것이 기본 과제는 아닙니다. 반복문에서 pending이 요청 ID를 넣고 도구 응답 뒤 지우는 위치를 찾아 읽고, 실패 예시 한 곳을 바꾸어 결과를 설명합니다.

기록 양식에는 목표별 근거 위치와 자신의 설명을 씁니다. 제공 정책 예시는 작성자가 가상 자료를 읽은 예시이며 학생의 정책 선택이나 동료 실행을 대신하지 않습니다. 근거가 없으면 미확인으로 남기고 설명과 관찰이 어긋나면 수정합니다.
