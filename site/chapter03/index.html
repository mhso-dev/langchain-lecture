02

print()와 return의 차이

함수의 반환값은 호출한 쪽에서 다시 계산에 쓸 수 있는 값입니다. 어떤 입력을 받을지, 처리할 수 없는 입력을 만나면 어떤 예외를 낼지도 함께 설계합니다.

함수 안에서 결과를 출력하는 것과 결과를 호출한 곳으로 돌려주는 일은 따로 일어납니다. 다음 계산에 쓸 값은 return으로 보냅니다.

06

함수의 반환값·타입 힌트·예외 처리 심화 읽기

함수의 매개변수와 return

def는 함수 이름과 매개변수를 정해 처리 내용을 묶습니다. 정의만으로는 본문이 실행되지 않습니다. add_minutes(25, 35)처럼 호출할 때 25와 35가 first·second에 전달됩니다. 호출하며 넘긴 값은 인자라고 부릅니다.

return은 결과를 호출한 자리로 돌려주고 해당 함수 실행을 끝냅니다. print는 화면에 보여 줄 뿐 호출자에게 계산 결과를 돌려주는 역할을 하지 않습니다. return을 쓰지 않은 함수의 반환값은 None입니다.

함수 안에서 만든 result는 그 호출 안에서 사용하는 지역 변수입니다. 함수 밖에서는 combined처럼 반환값을 저장한 이름을 사용합니다.

타입 힌트와 입력 검증

title: str은 문자열을 받을 의도, -> str은 문자열을 반환할 의도를 나타내는 타입 힌트입니다. 실행기가 이 표기만 보고 값을 자동 변환하거나 잘못된 타입을 모두 막지는 않습니다. 입력 규칙과 검사 코드를 함께 작성해야 합니다.

normalize_title은 공백으로 나눈 단어들을 공백 하나로 다시 합칩니다. " ".join(목록)은 문자열 목록 사이에 공백을 넣어 연결합니다. parse_minutes는 정수로 바꾼 뒤 이 수업 예제의 허용 범위인 0~480분인지 확인합니다. 이 범위는 Python의 제한이 아니라 과제 규칙입니다.

함수별 입출력 계약
함수허용 입력결과·실패
normalize_title문자열공백을 정리한 문자열, 빈 입력이면 빈 문자열
parse_minutes정수를 나타내는 문자열0~480 정수; 변환 실패·범위 밖이면 ValueError
호출자의 try/except

raise ValueError(...)는 현재 입력을 처리할 수 없다는 사실을 호출한 쪽에 알립니다. 호출자는 try 안에서 실행하고 except ValueError에서 그 종류의 실패를 처리합니다. 실패하면 try 안의 남은 문장은 건너뜁니다. else는 예외가 없을 때만 실행합니다.

from contracts import parse_minutes는 같은 폴더의 contracts.py에서 함수를 가져옵니다. 이 파일은 앞 절의 함수를 그대로 담은 제공 파일입니다. 모듈을 직접 나누는 방법은 4장에서 연습합니다.

여기서는 잘못된 입력을 알려 주고 다음 기록으로 넘어가는 정책을 택했습니다. 실패를 0분으로 바꾸면 실제 0분 기록과 구분할 수 없으므로 그렇게 처리하지 않습니다. except:처럼 모든 실패를 묶으면 철자 오류까지 숨길 수 있습니다.

오류를 만났을 때
종류의미대응
SyntaxError코드를 읽을 수 없는 문법실행 전 문법 수정
ValueError종류는 맞지만 값이 조건을 위반입력 안내·재시도 또는 해당 기록 제외
NameError정의하지 않은 이름 사용변수·함수 철자와 정의 확인
TypeError지원하지 않는 종류의 연산호출자와 함수의 계약 대조
계산 로직과 입출력 함수 분리

순수 함수는 같은 입력에 같은 결과를 반환하고 파일·화면·네트워크 같은 바깥 상태를 바꾸지 않습니다. normalize_title·parse_minutes·make_summary는 이 입력 계약 안에서 결과를 계산합니다. input()과 print()는 사용자·화면과 상호작용하므로 바깥쪽에 둡니다.

외부 API 호출은 네트워크나 서버 상태에 따라 실패할 수 있습니다. 6장에서 실제 호출을 다루기 전에 지금은 콘솔 입력을 경계로 삼습니다. 계산 부분이 input()을 직접 부르지 않으면 값을 넣어 반복 검사하기 쉽습니다.

정상값·경곗값·예외 테스트

assert 뒤의 조건이 거짓이면 AssertionError가 발생합니다. 정답을 눈으로 보는 대신 예상 결과를 코드에 적어 바뀐 동작을 빠르게 찾습니다. assert는 개발용 검사에 사용하며 운영 입력 검증은 앞서 작성한 if와 raise로 유지합니다. Python 최적화 옵션에서는 assert가 생략될 수 있습니다.

실패 검사는 오류가 발생해야 통과합니다. except의 pass는 이 실패가 예상됐다는 뜻입니다. else로 들어왔다는 것은 거부해야 할 입력이 통과했다는 뜻이므로 AssertionError를 냅니다. pytest로 검사를 모으는 방법은 7장에서 배웁니다.
