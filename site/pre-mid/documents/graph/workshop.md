# LangGraph 실습 수첩 · 원고 편집에서 녹음기 상담까지

33~35장은 아래 원고와 대화 카드를 사용합니다. 36~39장은 [녹음기 설명서 원본과 적용 기간](../recorder-practice.md)을 엽니다. 표의 빈칸은 노트북의 Markdown 셀에 복사해서 사용하세요. 코드는 자신의 입력에서 실제로 나온 값과 함께 남깁니다.

## 33장 · 같은 길이, 다른 표시 상태

`stream_mode="updates"`로 한 번 실행해 어느 노드가 길이를 쓰고 어느 노드가 판정을 쓰는지 확인하세요. 이어서 표에 적을 최종 상태와 비교합니다.

전광판은 공백을 포함해 최대 열 글자를 표시합니다. 원고 담당자는 “동문 개방”을 보냈고 다음 담당자는 “오늘 오후 두 시 동문 개방”을 보냈습니다. 두 원고를 종이에 옮겨 공백도 한 칸씩 표시하고, 노트북을 실행하기 전에 어느 쪽이 통과할지 예상하세요. 이번에는 10자와 11자로 된 자기 원고 두 개를 만들어 경계에서 확인합니다. 편집자는 남은 칸 수를 원합니다. 길이를 세는 노드와 상태를 판정하는 노드 중 어느 값을 읽어 계산할지 결정하세요.

|---|---|---|---|---|
| 동문 개방 | | | | |
| 오늘 오후 두 시 동문 개방 | | | | |
| 내가 만든 경계 원고 | | | | |

## 34장 · 편집 반려 쪽지

시설팀이 보낸 원문입니다.

> 오후 2시부터 4시까지 동문을 닫습니다. 방문자는 서문으로 들어오세요. 물품 배송은 지하 반입구를 사용하세요.

학생은 **방문자**가 읽을 게시문을 만듭니다. 모범 답을 보기 전에 반드시 전달할 사실과 빼도 되는 사실을 고르세요. 초안과 수정본의 글자 수, 방문한 노드, 포기한 조건을 한 줄씩 씁니다. 이번에는 **배송 기사**에게 보낼 문장을 만들어 같은 그래프를 사용합니다. 두 사람에게 같은 답을 보내면 누구의 행동이 어긋나는지 설명하세요.

|---|---|---|---|---|
| 방문자 | | | | |

## 35장 · 창구 두 곳에서 같은 질문 받기

첫 창구에서는 “제 이름은 봄이고 오늘 오후에 방문합니다.”, 두 번째 창구에서는 “제 이름은 가을이고 내일 오전에 방문합니다.”라고 말합니다. 두 창구 모두에 “제 이름과 방문 예정은 무엇인가요?”라고 묻습니다. A 창구만 새 대화로 바꿔 같은 질문을 한 번 더 합니다. 각 질문 직전 모델이 받는 발화를 보여 주세요. 모델이 이름을 맞혔더라도 입력에 그 정보가 없었다면 근거가 없다고 표시합니다.

## 36장 · 귀로 들은 답을 파일에서 검증하기

담당자의 메모에는 “연속 녹음은 30분마다 파일이 나뉜다”라고만 적혀 있습니다. 2027년 3월 A형, 4월 A형, 5월 B형으로 바꿔 각각 어느 설명서를 열지 고르고 2쪽을 읽습니다. 이제 같은 질문·같은 색인·같은 k로 LCEL과 LangGraph를 실행합니다. 후보가 다를 때와 후보는 같은데 답의 숫자가 다를 때를 구별합니다.

## 37장 · 설명서에서 문장 하나 가져오기

> 4월 A형의 화면 밝기를 낮추면 녹음 중 앞면의 표시등도 꺼지나요?

먼저 인용하고 싶은 한 문장을 찾으세요. 같은 문장이 3월 판본에도 있다면 실제 상담에 어느 쪽을 붙일지 정합니다. 이제 짝이 B형 1.0판을 건네며 “여기에는 숨김 설정이 있어”라고 말합니다. 그 조언이 A형에 적용되는지, 이유가 문구·기종·판본 중 어디에 있는지 짚으세요. 제출할 기록은 유효한 인용 한 건과 제외한 후보 두 건입니다.

## 38장 · 검색이 빗나갈 때 두 번째 기회를 주기

첫 검색에서 틀린 제품만 찾은 경우, 맞는 제품의 다른 기능이 나온 경우, 답이 있는 후보가 나온 경우를 각각 넣으세요. 노트북의 고정 후보로 세 경로를 먼저 재현한 뒤 실제 검색기를 연결합니다. 수업용으로 순서를 지정한 후보와 실제 순위는 다른 칸에 적고, 첫 검색과 두 번째 검색에서 파일 ID가 달라졌는지 설명합니다.

|---|---|---|---|---|
| | | | | |

## 39장 · 짝이 처음 만든 문의로 인계하기

문제 출제자는 설명서에서 추측하기 쉬운 기능 하나를 고릅니다. 정답 문서와 쪽은 별도로 보관하고 상담자에게 질문·제품·시점만 알려 줍니다. 상담자는 화면을 실행해 원문과 답을 확인하고, 두 사람은 마지막에 기대 답을 공개합니다. 보류할 질문을 하나 더 만들어, 근거를 못 찾았다는 말을 제품에 기능이 없다는 말로 바꾸지 않았는지도 확인하세요.

다음 팀이 다시 실행할 수 있도록 질문 원문, 색인 버전, k, 선택 기종·판본, 후보 ID와 순위, 종료 이유, 최종 인용, 사람이 표시한 원문을 넘깁니다. 화면에 보인 답과 노트북에서 다시 받은 답이 다르면 각각 별도의 실행으로 기록합니다.
