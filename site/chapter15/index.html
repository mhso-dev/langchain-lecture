Function Calling의 도구 명세와 호출 요청

주말 운영 시간 조회를 예로 들어 도구 이름, 인자 스키마, 모델의 호출 요청을 본뜬 예시 데이터를 읽습니다. 시간표를 조회하는 함수 실행은 16장에서 다룹니다.

입문교육일 015 · 8H14장 분기·JSON·12장 스키마
01

실습 노트북과 실행 환경

↓15장 수업 노트북 (.ipynb)Jupyter에서 열고 Python 커널을 선택한 뒤 위에서부터 실행하세요.↗

실행을 확인한 커널은 Python 3.12.15입니다.

02

JSON Schema의 enum과 required

도구 명세에는 함수 이름과 받을 인자의 규칙을 적습니다. 모델이 도구 호출을 요청하면 프로그램은 응답에서 함수 이름과 인자를 읽을 수 있습니다.

도구 명세에는 함수 이름, 기능 설명, 허용 인자를 적습니다. 수업용 가상 도서관은 day 하나만 받고, 평일이나 주말 중 하나를 고르게 했습니다.

출력 형식과 호출할 함수

12장의 출력 스키마가 응답 데이터의 모양을 정했다면, 여기서는 get_library_hours가 받을 인자의 모양을 기술합니다. parameters에서 day가 필수인지, 어떤 값을 받을 수 있는지 찾아보세요.

셀 01 · parameters의 enum

아래 사전은 함수의 파이썬 본문 없이도 모델에 보낼 수 있는 기능 설명입니다.

실행 결과

['weekday', 'weekend']

weekday와 weekend가 허용됩니다. 이 명세는 주소나 실제 개관 시간을 제공하지 않습니다. 운영 시간을 조회하는 함수는 다음 장에서 실행합니다.

사용자가 ‘토요일 몇 시까지 열어요?’라고 물어도 인자 day에 ‘토요일’을 그대로 넣으면 이 명세와 맞지 않습니다. 모델이 weekend를 골랐다면 요일 분류까지 마친 셈입니다. 몇 시에 문을 닫는지는 여전히 함수의 시간표를 읽어야 알 수 있습니다.

함수 구현과 호출 명세

Python 함수는 프로그램이 실행할 코드입니다. 도구 명세는 모델에게 어떤 기능이 있고 어떤 인자를 받는지 알려 주는 설명입니다. Function Calling에서 모델은 이 명세를 보고 함수 이름과 인자를 포함한 요청을 만들 수 있습니다.

여기서 사용자가 만든 함수는 애플리케이션이 실행해야 합니다. 모델 응답 안에 함수 이름이 나타났다고 내 컴퓨터에서 함수가 실행된 것은 아닙니다. 이번 장은 요청 관찰까지 다루며 실행·결과 반환은 다음 장에서 구현합니다.

서로 다른 세 가지
대상내용이번 장
구현실제로 실행되는 Python 코드아직 실행하지 않음
명세이름·설명·인자 스키마작성
호출 요청선택한 함수 이름과 인자읽기·관찰

과제 02 · 필수 필드 목록 required

parameters의 어느 칸에 필수 이름 목록이 있는지 찾아 출력하세요.

풀이와 실행 결과 보기

실행 결과

['day']

day가 필수입니다. description은 무엇을 조회할지 설명하지만 입력의 필수 여부는 required에서 읽습니다.

도서관 도구의 인자 스키마

name은 코드에서 찾을 기능의 식별자입니다. description에는 언제 사용하는지와 하지 않는 일을 설명합니다. parameters는 인자의 모양을 정합니다. 이번 day는 weekday와 weekend만 받습니다.

required는 day가 필요함을 뜻하고 additionalProperties=False는 다른 필드 추가를 허용하지 않는 스키마 설정입니다. strict=True를 사용해 지원되는 형식 제약을 요청하지만 실제 실행 전에는 애플리케이션도 입력을 검사해야 합니다.

03

function_call의 arguments와 call_id

호출 요청의 arguments는 JSON이 적힌 문자열입니다. 프로그램이 함수에 넘기기 전에 내용을 풀고 명세에 맞는지 검사해야 합니다.

요청의 tools와 응답의 호출 항목

모델에 전달할 tools 목록에는 이 장의 TOOL처럼 이름·설명·인자 규칙을 담습니다. 모델이 도구를 요청하면 응답 항목에서 name, arguments, call_id를 읽습니다. 이 장의 예제는 준비된 응답 항목을 직접 검사합니다.

셀 03 · arguments의 JSON 디코딩

모델 응답의 모양을 본떠 만든 요청입니다. 호출 ID와 함수명을 그대로 보관합니다.

실행 결과

weekend

weekend는 확인해 달라고 제안한 인자입니다. 실제 함수가 지금까지 한 번도 실행되지 않았으므로 주말 운영 시간은 아직 모릅니다.

호출 ID와 JSON 인자 문자열

call의 arguments는 문자열이라 json.loads를 거쳐야 day를 읽을 수 있습니다. call_id는 그대로 남겨 둡니다. 모델이 같은 이름의 함수를 두 번 요청해도 각각의 결과가 원래 요청으로 돌아가려면 ID가 필요합니다.

셀 04 · function_call과 call_id 추출

응답 목록의 첫 항목은 호출 요청이 아닙니다. type을 기준으로 골라야 합니다.

args는 arguments를 풀어서 읽은 값입니다. 다음 단계에서 어느 요청에 답했는지 찾으려면 name·arguments·call_id가 든 호출 원본도 보관해야 합니다. 여기까지는 요청을 읽었을 뿐, 허용된 함수인지와 요일이 올바른지는 실행 전에 검사합니다.

실행 결과

call_demo_1

call_demo_1은 요청 한 건의 식별자입니다. 이 값이 있다는 사실만으로 함수가 실행됐다는 뜻은 아닙니다. 같은 함수를 두 번 요청했다면 결과를 돌려줄 때 각 요청의 call_id를 그대로 사용해야 합니다.

출력 목록에서 호출 선별

모델 응답의 output에는 여러 종류의 항목이 들어갈 수 있습니다. 각 항목의 type을 보고 function_call만 읽습니다. 일반 문장에 “함수를 실행했습니다”라고 쓰여 있어도 호출 요청으로 처리하지 않습니다.

inspect_calls는 인자가 JSON 객체인지까지만 검사합니다. day의 허용값이나 name의 실행 가능 여부는 아직 검사하지 않으며 어떤 함수도 실행하지 않습니다. 이 범위를 다음 장의 실행 검증과 혼동하지 마세요.

04

메시지와 도구 호출 구분

모델의 응답에는 사용자에게 보여 줄 문장만 있을 수도 있습니다. 그런 응답을 inspect_calls에 넣으면 함수 이름이나 인자를 임의로 만들지 않고 빈 목록을 돌려줍니다.

모호한 도구 설명의 영향

설명에 “모든 질문을 처리한다”라고 적으면 기능의 경계가 사라집니다. 운영 시간만 조회하는 도구에는 날짜별 예약 가능 여부나 도서 재고를 처리한다고 적지 않습니다. 실제 구현이 할 수 있는 일만 설명하세요.

인자가 필요한 이유도 분명해야 합니다. day가 요일 이름인지 평일/주말 구분인지 설명되지 않으면 사용자 질문과 스키마가 어긋날 수 있습니다. 허용값과 설명을 함께 읽고 지원하지 않는 질문은 추가 확인 대상으로 남깁니다.

호출 요청의 관찰 기록
