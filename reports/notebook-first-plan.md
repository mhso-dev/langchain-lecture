## 한 장을 고치는 방법

1. 학생이 수업 후 혼자 해내야 할 일을 한 문장으로 쓴다. 예를 들어 “스캔한 공지에서 대출 기간을 못 찾았을 때 원본 쪽과 추출문을 대조한다”라고 적으면 필요한 자료와 실패 조건이 드러난다.
2. 강의자용 노트북에서 같은 기술을 쓰는 셀을 열고, 입력이 어떤 호출을 거쳐 어떤 결과로 바뀌는지 확인한다. 현행 교육일의 목표와 대조해 학생에게 제공할 준비 코드와 학생이 직접 작성할 코드를 정한다. 입력 자료와 답안의 배포 가능 여부도 이때 확인한다.
3. 예제 하나를 처음부터 끝까지 완성한다. 준비 코드는 제공하고, 학습 목표에 해당하는 변환·호출·검증은 학생이 한 번 직접 쓴다. 한 조건을 바꿔 실패를 관찰한 뒤 코드를 고쳐 다시 실행한다. 과제 바로 아래에서 정답·출력·이유를 펼쳐 볼 수 있게 한다.
4. 학생용 HTML에는 같은 입력과 코드, 실제 출력, 그 출력으로 판단할 수 있는 내용을 싣는다. 설명은 본문에 펼쳐 놓는다. 모의 응답을 쓴 셀에서는 어떤 입력을 넣었고 어느 호출을 모의 응답으로 대신했는지 밝힌다. 외부 API를 호출한 셀에는 사용한 모델과 관찰한 결과를 기록한다.
5. 새 실행 환경에서 시작본과 정답을 채운 사본을 차례로 실행한다. 독립 검수자는 새 입력으로 학생 과제를 다시 풀고 HTML의 표·영상·조작값과 대조한다. 장 사이에 넘기는 파일·키·쪽 번호가 바뀌면 받는 장에서도 확인한다.

장마다 영상 수를 정하지 않는다. 집필자는 학생이 조작할 입력과 조작 후 확인할 값을 먼저 적는다. 그 값이 기존 영상에서 보이면 영상을 살리고, 문장을 순서대로 띄우기만 하는 장면은 해당 셀의 코드·오류·출력으로 바꾼다.

## 확인 필요 항목

SDK·실제 모델·재정렬기 대조표에 적은 과제는 후속 장에서 집필한다. 이번 원자료 분석을 위해 외부 모델을 호출하거나 옛 노트북 전체를 재실행하지 않았다. 개편한 장에서 사용한 커널·패키지·실행 입력·출력을 해당 장 검수 기록에 적는다. 수강생의 과제 완료 시간과 스스로 수정한 비율은 첫 수업에서 확인한다. 장별 계획표는 집필 제안이며, 개별 장의 실행·화면 검수 결과는 해당 장의 개정 기록에서 확인한다.
