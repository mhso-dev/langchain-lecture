# 팀 프로젝트 41장 개정·검수

중간 프로젝트는 가상 과정의 과제 제출 안내, 최종 프로젝트는 장비실 규정 조회를 예시로 쓴다. 각 장은 이전 팀 파일을 읽고 새 코드로 결과를 만들어 다음 장이 열 JSON을 남긴다. 도중에 합류한 팀은 해당 장의 시작 예시 JSON을 내려받을 수 있다. 같은 이름의 파일에 다른 결과가 있으면 저장을 중단해 팀의 선택을 보존한다.

기존 빌드는 팀 참고 절의 완성 코드·시연표·팀별 변형을 지우고 판단 문장만 배포했다. 이제 완성 예시를 그대로 싣는다. 기존 개인 연습 셀은 준비 변수와 답이 들어 있는 팀 참고 예시로 바꿨다. 별도의 공통 숙제를 부과하지 않는다.

## 독립 교육 검수와 수정

- 45~52장. 후보 검색 결과와 기준선 화면을 한 실행처럼 비교하던 초안을 고쳤다. 47장이 같은 문항을 두 경로에 넣고 48~50장은 동일한 후보 실행에서 검색과 표시를 비교한다. Q03은 후보가 p3을 찾았으나 화면에서 빠졌고, 수정 뒤 그 요청의 p3을 표시했다. 후보의 로컬 회귀 결과와 정식 기준선 유지 결정을 나누어 인계한다.
- 89~92장. 공개 문서의 장비명과 위치를 기준선에 넘긴다. 91장에서 전날의 평가표에 있는 질문만 FastAPI 테스트 클라이언트로 보내고 92장에서 반환값으로 통과 수와 전체 행 수를 센다. 기본 팀의 결과는 1/3이다. 본문의 옛 7건 사례 2/7과 구분했다.
- 90·108장. 실제 응답에서 가져온 문장을 기대값으로 다시 쓰던 초안을 고쳤다. 실행 전에 고정한 정답 원문을 수업 단계 내내 보존한다. 108장에서 화면 문장만 바꾸면 문서 판정은 참, 사실 판정은 거짓이 된다.
- 47·93장. 그래프 조립·호출 코드 곁 Mermaid에 등록 이름과 분기·종료를 표시했다. 93장의 교체 일정 질문은 classify만 방문한다. 최종 대조에서 47장 인사말 실행 곁에 있던 노트북 도식이 HTML에 빠진 것을 찾아 보완했다. 두 매체의 도식 네 개는 정의와 배치 순서가 같다. 별도 검수자는 code-3의 등록 경로와 code-4의 인사말 분기 finish → END 및 검색 0회를 재확인했다.

별도의 읽기 전용 검수자가 41장을 모두 새 커널에서 실행하고 수정 사항을 재확인했다. 교육 판정은 accept다. 프로젝트의 실제 팀 회의·리허설·운영 결과와 로컬 참고 사례는 구분한다.

## 실행 조건과 근거

[재현 검사](../scripts/check_project_handoffs.py)는 장마다 별도 프로세스의 Jupyter 커널을 열어 모든 코드·저장 출력을 대조한다. 앞 파일을 직접 넘기는 41회와 복귀 예시에서 시작하는 41회를 실행했다. 시작 셀은 읽은 파일의 종류·이름과 그 안의 데이터 값을 따로 대조한다. 각 장의 출력 JSON은 다음 장의 복귀 파일과 값이 같았다. 소스 검증 명령은 python scripts/check_project_handoffs.py --source site이며, 배포 파일을 읽으려면 --source dist를 사용한다.

네트워크 기반 커널은 포트 사용 권한이 없어 InProcessKernelManager로 실행했다. 47·93장은 로컬 LangGraph, 91장은 실제 TestClient, 102장의 전송 오류는 MockTransport, 106·113장은 임시 SQLite·JSON에서 확인했다. 원자료 06_LLM의 Reliability Engineering 노트북에서 판단 전후 입력과 결과 설명 방식을 참조했다. 12장의 출력 아래 풀이와 14·33장의 시작 예시·단계별 실행을 대조했다.

macOS-27.0.1-arm64-arm-64bit / Python 3.12.15 · ipykernel 7.4.0, IPython 9.17.1, nbformat 5.11.1, langgraph 1.2.16, fastapi 0.165.0, httpx 0.28.1, langchain-core 1.6.12

별도로 빈 작업 폴더에서 42·43·85·86장의 전체 학생 노트북도 각각 새 커널로 열었다. 42장이 계정 없이 기록 읽기로 내보낸 ‘검토 대기’, A형 1.1 설명서 2쪽과 질문을 43장이 자기 시작 예시보다 먼저 읽었다. 85장이 실제로 계산한 july-deadline의 기대·관찰 90, edition-sort-v2와 인계 결정을 86장이 그대로 받았다. 두 경우 모두 팀 기록 파일에서 읽었다.

입력 변형도 확인했다. 42→43 팀 질문·보류 근거 유지, 44→45 p2 제거 후 Q01 검색 누락·비통과 재현, 45 재실행 때 기존 팀 결정 보존·충돌 알림, 85→86 다른 릴리스 버전·관찰 내용 원형 보존.

산문 S1 검수에서는 출력 설명과 끝 문장에서 제목을 그대로 반복하던 표현을 줄였다. 장마다 윤문 전후의 경로·숫자·인용·실행 판정을 대조했다. 변경량이 5% 미만이라는 기계 경고를 검토하고, 교육 내용을 보존하는 국소 수정으로 최종 판정했다. 공개 범위가 확인되지 않아 외부 맞춤법 서비스에는 전송하지 않았다.

## 확인 필요 항목

학생 Windows/WSL, 실제 사용자 관찰·팀 리허설·운영 지표·외부 배포·원격 복구는 수업 표본으로 확인할 수 없다. Chrome과 Chromium은 운영체제의 프로세스 등록 권한으로 직접 기동이 막혔다. 위 확인은 화면 검사를 포함하지 않는다. 최신 배포본의 브라우저 확인 범위는 전체 검수 기록을 따른다.
