02

제출 이벤트와 검색 결과 갱신

Streamlit의 폼은 입력을 모았다가 제출 시점에 처리합니다. 작성 중인 질문과 마지막으로 제출한 질문을 구분하면 화면의 답변이 언제 바뀌어야 하는지 알 수 있습니다.

Streamlit은 위젯을 조작하면 화면 코드를 다시 실행합니다. form으로 묶은 입력은 제출 버튼을 누르는 시점에 함께 받습니다. 새 실행을 지나도 보여 줄 값은 session_state에 남깁니다. 먼저 노트북에서 상태에 어떤 값이 들어가야 하는지 확인합니다.

03

Streamlit 폼과 AppTest 입력

다음 문자열은 실제 Streamlit 앱 코드입니다. 실습 범위를 입력·출력 위젯으로 좁히려고 대출과 휴관 원문 두 건만 씁니다. 수업 커널에 Streamlit이 있으면 AppTest가 앱을 메모리에서 실행해 위젯을 조작합니다. AppTest는 브라우저 화면을 그리지 않습니다.

Streamlit 재실행 시점

Streamlit은 Python 스크립트로 화면을 만드는 도구입니다. 기본 동작에서는 위젯과 상호작용하면 스크립트를 위에서 아래로 다시 실행합니다. 일반 변수는 그 실행에서 다시 만들어집니다. 같은 브라우저 세션에서 이어서 보관할 값은 session_state에 둡니다.

스크립트 재실행은 서버 프로세스를 새로 시작하는 일과 다릅니다. 현재 앱의 메모리에 있던 세션 상태는 일반 재실행 사이에 유지할 수 있지만, 탭 새로고침이나 서버 재시작 뒤에도 기록이 영구 보관된다고 약속하지 않습니다. 일시적인 연결 끊김은 별도 세션 정책의 영향을 받을 수 있습니다.

질문 함수 호출을 스크립트 맨 아래에 조건 없이 두면 결과를 다시 그리기 위한 실행에서도 검색을 반복할 수 있습니다. 이 장의 앱은 submitted가 참일 때만 submit_question을 부릅니다. 결과를 보여 주는 부분은 이미 저장한 view를 읽습니다. 화면을 그리는 일과 새 질문을 처리하는 일을 구분하는 것입니다.

asked와 last로 현재 화면 결정하기

asked는 폼을 제출한 적이 있는지, last는 방금 찾은 문서가 무엇인지 담습니다. 첫 화면과 답을 찾지 못한 화면은 last가 비어 있을 수 있지만 asked 값으로 구별됩니다.

셀 03 · AppTest로 폼 제출

Streamlit이 설치된 수업 커널에서는 첫 입력칸과 제출 버튼을 실제로 조작합니다. 설치 여부에 따라 출력이 달라집니다.

AppTest는 Jupyter 출력에서 폼에 값을 넣고 제출 동작을 확인합니다. 서비스 화면을 수업에서 함께 열었다면 ‘대출’을 제출한 다음 ‘주차’를 제출해 보세요. 두 번째 답에 첫 질문의 출처가 남아 있는지 확인합니다. 설치 안내만 출력된 커널에서는 폼 동작을 관찰한 것이 아닙니다.

실행 결과

Streamlit이 설치된 수업 커널에서 폼 실습을 실행하세요.

설치된 환경에서는 대출 기간과 1쪽 출처가 표시돼야 합니다. 설치 안내가 나온 경우 실제 앱 실행은 남아 있습니다. 위에서 확인한 상태 갱신 실습은 그대로 마칠 수 있습니다.

AppTest에서 제출을 재현할 때

질문 입력란에 값을 설정한 뒤 버튼을 누르고 run()으로 다시 실행합니다. 대출 질문에서는 답변 본문과 1쪽 출처가 함께 나와야 합니다. Streamlit이 없는 커널에서는 설치 안내가 출력됩니다.
