02

경로 매개변수와 요청 ID

HTTP 요청에서는 경로가 대상을 지정하고 상태 코드가 처리 결과를 알려 줍니다. 성공 응답을 받아도 본문이 예상한 JSON인지 따로 확인해야 합니다.

GET은 값을 읽어 달라는 요청입니다. /todos/1에서 /todos는 자료 종류, 마지막 1은 요청한 기록 번호입니다. 서버는 상태 코드와 본문을 돌려줍니다.

선택 실습 · 공개 API 요청

timeout=5.0은 연결·읽기 등 네트워크 단계의 대기 제한에 사용됩니다. 전체 프로그램이 반드시 5초 안에 끝난다는 보장은 아닙니다. 무제한 대기를 피하려는 설정이며 상세 시간 측정은 별도로 해야 합니다.

실행 결과

/todos/1입니다. 뒤에서 받은 데이터의 id가 1인지 다시 확인할 때 같은 todo_id를 사용합니다.

HTTP 리소스와 응답

HTTP 요청은 서버에 어떤 자원을 어떻게 다룰지 전달하는 메시지입니다. URL은 주소, GET은 조회 방법입니다. 서버는 상태 코드·헤더·본문을 응답합니다. JSON은 응답 본문에 담길 수 있는 데이터 형식이며 HTTP 자체와 같은 뜻은 아닙니다.

기본 실습에서는 /todos/1이라는 요청 경로를 만들고 미리 적어 둔 JSON 본문을 읽습니다. 셀 05에서 HTTPX가 받는 404도 수업용 함수가 만든 응답입니다. 실제 서버에 접속하는 경우는 공개 API 선택 실습으로 구분합니다.

03

HTTP 상태 오류와 JSONDecodeError

404는 요청에 응답했지만 해당 자원을 찾지 못했다는 상태입니다. 타임아웃이면 읽을 응답 본문조차 없을 수 있습니다. 상태 확인을 먼저 하고 성공했을 때만 JSON을 읽습니다.

모의 응답별 분기 테스트

셀 05의 missing은 어떤 경로를 받아도 상태 코드 404를 반환합니다. 주소만 바꾸어서는 성공 응답이 나오지 않습니다. 응답을 만드는 함수가 무엇을 돌려주는지와 클라이언트가 그 상태를 어떻게 처리하는지를 따로 읽으세요.

응답이 도착했기 때문에 이 예외에는 error.response가 있습니다. 서버에서 아무 응답도 받지 못한 시간 초과라면 이곳에서 404를 읽을 수 없습니다.

셀 04 · JSONDecodeError 처리

상태 코드는 200인데 본문에는 HTML이 담겼다고 가정합니다. 어떤 변환에서 실패하는지 확인하세요.

실행 결과

JSONDecodeError

JSONDecodeError가 나옵니다. URL을 다시 요청하기 전에 이미 받은 본문의 종류와 형식을 점검할 수 있습니다.

HTTP 상태와 JSON 디코딩 따로 확인하기

서버 상태를 확인하는 raise_for_status()와 본문을 해석하는 json.loads()는 실패 지점이 다릅니다. 점검용 HTML처럼 JSON이 아닌 본문은 JSONDecodeError 경로에서 확인합니다.

셀 05 · HTTPX의 상태 코드 예외

httpx가 설치된 수업 커널에서는 MockTransport가 정한 상태로 응답합니다. 네트워크 연결은 없습니다.

client.get(path)를 호출하면 MockTransport가 이 셀의 missing(request)를 대신 부릅니다. Response(404)를 만든 곳은 바로 그 함수입니다. 인터넷을 끊어도 이 404를 관찰할 수 있습니다.

실행 결과

404

HTTPX를 사용한 출력은 404입니다. 연결 실패 예외와 달리 error.response에서 서버의 상태 값을 읽습니다. 외부 서버의 가동 여부는 이 모의 요청으로 알 수 없습니다.

MockTransport가 돌려준 HTTP 응답

예제의 missing 함수는 요청을 받으면 상태 404인 httpx.Response를 만듭니다. 클라이언트의 raise_for_status()에서 HTTPStatusError가 발생하며, except 블록에서 error.response.status_code를 읽으면 404입니다.

04

JSON 불리언과 문자열 구분

JSON의 false는 파이썬의 False가 되지만 따옴표가 있는 "false"는 비어 있지 않은 문자열입니다. 자료형을 먼저 검사하면 잘못된 완료 표시를 막을 수 있습니다.

과제 06 · bool 타입 검사

잘못 들어온 문자열을 bool()로 바꾸지 말고 완료 값이 실제 bool인지 확인하세요.

풀이와 실행 결과 보기

실행 결과

False

False가 나옵니다. 응답 형식 오류로 기록할 입력입니다. bool(completed)를 쓰면 내용과 관계없이 비어 있지 않은 문자열이어서 True가 됩니다.

JSON 구조와 필드 검증

과제 03은 요청과 응답의 id가 일치하는지, 과제 06은 completed가 파이썬 bool인지 검사합니다. 두 조건은 독립적입니다. 번호가 일치해도 completed가 문자열이면 완료 상태로 사용할 수 없습니다.

isinstance(값, 종류)는 해당 종류인지 검사합니다. bool은 Python에서 int의 하위 종류이므로 id에 True가 들어오는 것을 막으려면 type(todo_id) is int처럼 정확한 종류를 확인할 수 있습니다. 여기서는 숫자와 bool을 구분하는 과제 규칙에 사용합니다.

문자열 "false"를 bool(...)로 바꾸면 비어 있지 않아 True가 됩니다. completed를 임의 변환하지 말고 JSON의 true/false가 Python bool로 읽혔는지 확인합니다.
