## 원자료와 수업 산출물

강사 ZIP의 PDF 로더와 TXT 로더 노트북에서는 파일을 열어 본문과 메타데이터를 읽는다. 개정 전 20장에는 미리 적어 둔 PDF 추출값과 한 문장을 넣어 만든 PDF가 있었다. 이번 실습에서 학생은 배포된 두 TXT와 두 PDF를 열어 LangChain `Document`에 본문과 출처를 보관한다. 마지막에는 새 분실물 안내로 `chapter20-output/desk-handoff.json`을 만들고, 상대 팀이 기대 답의 문서 ID에서 원문 문장까지 되짚는다. 검색용 벡터를 만드는 일은 22장에 배치돼 있다.

## 교육 검수와 수정

| 처음 발견한 문제 | 동결판에서 확인한 결과 |
|---|---|
| 스캔 쪽의 빈 추출문을 설명하면서 반납함 안내 전체가 검색 대상에서 빠진다고 읽힐 수 있었다. | 동일 공지의 1쪽은 남고, 2쪽의 파일명과 쪽수만 보류 목록에 들어간다. 공백만 있는 추가 쪽도 보류하는지 별도 입력으로 확인했다. |
| 휴관일 정답 셀의 첫 변수가 시작 코드에만 있었고 노트북에는 예제 실행 출력이 저장되지 않았다. | 정답 셀에서 필요한 질문 레코드를 마련한다. 배포 노트북에는 깨끗한 시작 상태에서 관찰한 출력이 셀 아래에 들어 있다. |
| 짧은 예제 관찰 뒤에 새 원문으로 끝까지 진행하는 과업이 없었다. | 학생이 분실물 안내 파일을 읽고 답할 수 있는 질문과 근거가 없는 택배 질문을 만들도록 했다. 저장한 JSON에서 출처와 “2층 안내 데스크”를 다시 찾는 데까지 실행했다. |
| 노트북에서 사진을 관찰하라는 문장 옆에 이용 시간이 쓰인 공지만 있었다. | 글자가 없는 반납함 사진을 별도로 넣었다. 사진·영상에서 본 동작과 공지로 확인할 수 있는 24시간을 구분한다. |

읽기 전용 교육 검수자가 학생판과 정답을 별도로 실행하고 21장 첫 입력을 대조했다. 20장 수정본에 대한 교육 판정은 **수정 후 통과**다.

## 코드와 자료 대조

| 확인 대상 | 관찰한 결과 |
|---|---|
| 노트북 시작본·풀이본 | macOS, Python 3.12.15, `pypdf` 6.21.4, `langchain-core` 1.6.12. 별도 Python 프로세스에서 Jupyter 인프로세스 커널을 시작해 각각 준비 셀을 포함한 12개 코드 셀을 실행했다. HTML 11개 예제·과제 출력과 일치했다. |
| 노트북 단독·ZIP | 이름을 바꾼 노트북에서 내장 자료 4개를 복원했다. ZIP으로 푼 노트북과 파일도 개별 다운로드와 바이트가 일치했다. |
| 비교용 PDF | 두 쪽을 같은 배율로 그린 픽셀이 일치했다. 1쪽에서 제목과 이용 시간 두 줄이 추출됐고, 2쪽에서 빈 문자열이 나왔다. 이 예시의 2쪽은 OCR 텍스트가 없는 이미지 한 장이다. |
| 다음 교육일 | 21장의 첫 문서는 `library-1`, 가상 도서관 이용 안내 1쪽, “도서 대출 기간은 14일입니다.”였다. 20장의 문서 레코드와 일치한다. |
| 매체 | Higgsfield에서 반납함 사진과 이를 바탕으로 한 영상을 각각 생성했다. 무음 영상은 3.04초로 책이 들어가고 덮개가 닫히는 것을 확인했다. 이미지 0.75, 영상 4.5로 합계 5.25크레딧을 사용했다. Three.js 실습은 같은 PDF의 페이지 이미지와 추출값을 사용한다. |
| 오프라인 HTML | 영상 2개, CSS·스크립트, 노트북·ZIP·원본 다운로드 6개를 내장했다. 스크립트와 다운로드 바이트를 대조했고, DOM 검사에서 Three.js 초기화와 두 쪽 전환을 확인했다. |

재현할 때는 저장소에서 `node scripts/build.mjs`, `python3 scripts/check.py`를 실행하고, 위 패키지와 `ipykernel`, `nbformat`, `PyMuPDF`가 있는 검수 커널의 Python으로 `scripts/check_chapter20.py`를 실행한다. 학생은 내려받은 노트북을 연다.
