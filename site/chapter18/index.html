02

JSON 객체와 빈 호출 ID 구분

도구를 실행하기 전에 이름과 호출 ID, 인자의 형식을 검사하면 잘못된 요청이 어느 조건에서 막혔는지 기록할 수 있습니다.

get_loan_rule은 입력 칸이 없는 도구입니다. 요청에는 이름과 비어 있지 않은 호출 ID가 있어야 하고 arguments에는 빈 JSON 객체를 적은 문자열이 와야 합니다.

요청에서 확인할 세 필드

get_loan_rule 요청 한 건을 놓고 name과 call_id, arguments를 각각 읽어 보세요. 도구에 인자가 없어도 요청을 식별하는 ID는 필요합니다.

셀 01 · arguments의 빈 JSON 객체

겉보기에는 내용이 없어도 문자열을 풀었을 때 어떤 값이 남는지가 중요합니다.

실행 결과

True

True가 나옵니다. 빈 문자열은 JSON 문서가 아니어서 같은 변환을 통과할 수 없습니다. []는 읽을 수 있는 JSON이지만 이 도구가 정한 객체 모양과 다릅니다.

도구에 건넬 인자가 하나도 없더라도 '{}'는 읽을 수 있는 JSON 객체입니다. 반면 call_id가 비어 있으면 실행 뒤 결과를 되돌려 줄 대상을 특정할 수 없습니다. 두 값 모두 화면에서는 ‘빈 값’처럼 보여도 검사하는 지점이 다릅니다.

셀 02 · strip()으로 빈 call_id 검사

ID에 공백 세 칸만 들어온 경우를 따로 확인합니다.

실행 결과

False

False이므로 결과를 연결할 이름이 없습니다. strip을 빼면 원래 세 칸의 길이 때문에 유효하다고 잘못 판단할 수 있습니다.

빈 인자 객체와 빈 호출 ID

get_loan_rule은 별도로 받을 인자가 없어 문자열 '{}'를 풀면 빈 딕셔너리가 됩니다. 반면 공백만 있는 call_id는 strip()한 뒤 비어 있으므로 나중에 결과와 짝지을 수 없습니다.

03

validate_request()의 필드별 검사

요청의 바깥 자료형부터 확인하고 안쪽 칸을 읽습니다. 유효하지 않은 입력이면 함수 안에서 False를 돌려주면 됩니다. 사전의 값을 덮어쓰지 않으면 실패 원인을 나중에도 다시 읽을 수 있습니다.

call_id가 같은 요청의 필드별 오류

원본에서 바꾼 부분풀이 함수의 반환이유
원본 arguments는 문자열 "{}"True도구에 전달할 인자가 없음
arguments를 문자열 {"day":"weekend"}로 변경FalseJSON을 푼 안쪽 객체에 인자가 생김
바깥 item에만 day를 추가하고 arguments는 "{}" 유지True풀이 함수는 바깥의 부가 필드를 읽지 않음

검사 함수의 입력·출력 계약

validate_request는 호출 요청을 검사해 bool을 반환합니다. 딕셔너리가 아닌 값이나 잘못된 요청에는 False를 반환합니다. 실제 도구나 모델을 실행하지 않고 입력도 수정하지 않습니다.

허용 이름은 get_loan_rule 하나입니다. call_id는 공백이 아닌 문자열, arguments는 JSON 문자열이며 파싱 결과가 빈 객체 {}여야 합니다. bytes나 이미 만들어진 딕셔너리는 JSON 문자열이 아니므로 거부합니다. 잘못된 JSON·추가 인자·누락된 필드에도 False를 반환합니다.

과제 03 · validate_request() 완성

사전, 도구 이름, 공백이 아닌 문자열 ID, 문자열로 온 빈 JSON 객체 순서로 검사하세요. 변환에 실패해도 예외 대신 False를 돌려줍니다.

get_loan_rule은 인자를 받지 않습니다. 요청 바깥에서 name과 call_id를 읽고, arguments 문자열을 풀어 빈 객체인지 확인하세요. day를 어느 쪽에 넣었는지에 따라 검사 결과가 달라집니다.

풀이와 실행 결과 보기

원래 c1 요청은 True입니다. 먼저 자료형을 검사해 None이나 목록이 들어와도 .get을 잘못 호출하는 오류를 피할 수 있습니다. 문자열로 온 {}만 허용하므로 파이썬 사전 자체를 넣은 요청도 거부합니다.

요청 필드의 검증 순서

처음부터 한 줄로 모든 조건을 쓰지 말고 이름, ID, JSON 파싱, 객체 내용의 순서로 나누세요. JSON 읽기가 실패하는 경우는 try/except로 처리합니다. 파싱이 성공해도 리스트나 숫자이면 객체 조건을 통과하지 못해야 합니다.

각 조건을 추가할 때 하나의 정상 사례와 하나의 실패 사례를 직접 호출해 봅니다. True와 "True"는 다릅니다. 이 함수는 문자열이 아닌 bool을 반환해야 합니다.
