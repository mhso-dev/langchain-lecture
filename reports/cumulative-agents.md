# 53~67장 · SQL 조회부터 에이전트 서비스 평가까지

## 검수 결과

독립 교육 검수자가 53장부터 67장까지 매번 새 IPython 커널에서 누적 실습과 접힌 풀이를 실행했다. 54장 변경값 21일이 55장 도구·61장 MCP·64장 승인·67장 API 시험 파일까지 유지됐다. 58장에서는 선택 조건이 지침 설명을 읽도록 고친 뒤 다시 확인했다. 67장의 기본 경로와 역순 실패도 재확인했다.

주 노트북 전체를 시작본과 풀이본으로 실행한 결과는 10장 통과, 5장 실모델 단계 보류다. 53·54·60장은 SQLite 경로를 실행했다. 선택 PostgreSQL 연결은 수업 DB가 필요하다. 학생 Windows/WSL과 실제 8시간 수업에서의 소요 시간은 미확인이다.

최종 빌드에서 15장 모두 배포용 장 노트북, 일일 과제, 압축 파일에 들어간 누적 절을 대조했다. 일일 노트북 15개와 ZIP 안의 파일이 바이트 단위로 같았다. 배포용 노트북에서 누적 절을 골라 **30개 새 커널**로 기본·풀이 인계를 재실행했다. 기본 사례는 14일, 54장의 값을 고친 실행은 21일을 67장에서 넘겼다.

## 주요 변경과 확인 필요 항목

55·56·62·63·66장은 같은 프로젝트의 실모델판을 대조해 기존 대본 모델 수업을 실제 ChatOpenAI 호출로 교체했다. 기초 원리를 확인하는 직접 함수 호출과 모델이 선택해서 실행한 도구를 본문에서 구분했다. 59장 상태 보존 노드와 64장 승인·재개에는 코드 가까이에 실행 경로를 그렸다. 55·64·66장의 개별 과제에 쓰이는 에이전트·승인 자료도 같은 실모델판을 사용한다.

실행 기준은 macOS, CPython 3.12.15, 각 노트북 또는 풀이마다 새 프로세스와 ipykernel.inprocess 커널이다. 신규 누적 실습의 기본 14일과 학생 변경 21일을 별도 폴더에서 53~67장 순서대로 실행했다. 전체 본문은 각 장의 복귀 자료에서도 따로 실행했다. 모델 키를 해당 프로세스에만 읽었으며 OpenAI 접속이 실패했다. 이번 환경에서 모델의 실제 도구 선택·결과를 확인한 것으로 표시하지 않았다. 61장의 새 FastMCP는 인메모리 전송을 실제 실행했고 기존 stdio 서버도 별도 프로세스로 실행했다.

교육 검수에서 58장 설명이 바뀌어도 선택이 달라지지 않던 점을 수정했다. 57장의 실제 파일에서 읽은 description 첫 단어가 58장의 선택에 쓰인다. 67장 순서 검사는 응답 원문만 보고 추정하지 않고 62장의 실제 MCP 호출 이름·인자와 64장에서 재개한 결정을 읽는다. 비교 기준은 이 서비스의 조회 후 승인 한 번이며 모든 에이전트에 동일한 경로를 요구하지 않는다.

한국어 검수는 개정 절과 교체한 기술 설명의 역할·입력·출력·수치를 원문 및 실행 결과와 대조했다. 파일을 실행한다는 표현을 저장 셀 실행으로 고쳤다. 구조 검사가 제시한 저변경률과 일부 단문 신호는 소유자 조건, 빈 결과와 호출 실패, 조회와 승인 횟수를 분리해 읽는 문장에서 재검토했다. 외부 맞춤법 전송은 문서 공개 범위 미확정으로 생략했다.

참고한 강사용 파일은 06_LLM의 03_LangChain_v1/02_Agent/강의자료 안에 있는 Create-Agent, MCP-Server-Basics, MCP-Agent-Integration, Human-In-The-Loop-V1, Short-Term-Memory 수업이다. 12장의 접힌 풀이, 14장의 함수 호출 전후 비교, 33장의 작은 예와 그래프 경로를 이번 장의 셀과 대조했다.

배포용 빌드는 작업트리 루트에서 `node scripts/build.mjs`로 만든다. 새 커널 인계 검사는 `python scripts/check_agent_handoffs.py`다. 웹·ZIP의 최종 전달 판정은 전체 과정의 통합 검수 기록을 따른다. [장별 셀과 실행 결과](cumulative-agents.json)
