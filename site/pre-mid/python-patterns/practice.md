# 분실물 게시판 변경 요청서

자료를 열어 두세요. [야간 분실물 센터의 변경 요청](change-requests.md)

예제에 익숙해지면 같은 장 번호의 새 센터 요청을 해결하세요. 접수 순서와 운영 규칙이 달라져도 기존 결과가 맞는지 동료가 판단할 자료입니다.

같은 물건을 직원 화면과 게시판에 올리는 작은 프로그램을 고칩니다. 입력 자료와 기존 동작은 아래에 있습니다. 노트북에서 그날의 변경 요청을 풀고, 펼친 답안과 자신의 결과를 대조하세요. 답이 다르면 처음 다르게 나온 값과 바꾼 줄을 적으세요.

## 변경 회의를 운영하는 순서

이 과정은 기본 문법으로 직접 구현할 수 있는 학생을 위한 선택 수업입니다. 각 블록의 첫 시도는 지금 알고 있는 방법으로 작성하세요. 변경 요청이 도착하면 고쳐야 할 위치를 먼저 찾고 구현을 바꿉니다. 팀에서 코드를 넘겨받는 사람은 새 입력으로 같은 동작을 검수합니다.

| 주제와 편성 | 변화가 생기는 지점 | 검수자에게 넘길 것 |
| --- | --- | --- |
| 진단·설계 준비 6시간 | 접수 순서를 보존하면서 화면만 다른 순서로 표시 | 원본·두 화면의 기대 순서와 각각의 테스트 |
| Strategy 8시간 | 같은 정렬 코드에 다른 기준을 전달하고 우선표가 언제 확정되는지 선택 | 원본 우선표를 수정하기 전후의 두 데스크 결과 |
| Factory 8시간 | 새 형식을 추가하면서 기존 게시 호출과 오류 처리를 유지 | 새 형식·기존 형식·미등록 형식에 대한 호출 기록 |
| Adapter·Decorator 10시간 | 기존 게시판을 연결하고 원문·공백 정리·성공 기록의 순서를 바꿈 | 출력은 같고 기록이 달라지는 입력, 거절되는 입력 |
| 선택·리팩터링 8시간 | 새로운 데스크 설정을 어느 호출 또는 객체에 보관할지 결정 | 분기·조합 두 방식의 같은 입력 결과와 유지할 구현 한 가지 |

## 접수 기록

| 접수 순서 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 원래 이름 | 텀블러 | 키 | 우산 | 장갑 |

직원은 접수 순서를 언제든 다시 조회할 수 있어야 합니다. 길이가 같거나 우선순위가 같은 물건끼리는 먼저 접수한 물건을 먼저 보여 주세요. 화면을 정렬한 뒤에도 위 표를 원래대로 조회할 수 있어야 합니다.

## 다섯 번의 변경 요청

| 실습 | 직원 요청 | 짝이 건네는 추가 입력 | 제출할 증거 |
|---|---|---|---|
| 1장 · 정렬 함수 | 같은 자료를 길이순과 사전순으로 조회합니다. | ‘우산’과 ‘장갑’의 접수 순서를 맞바꿉니다. | 두 조회 결과와 원본 보존 테스트, 순서가 달라진 이유 한 문장 |
| 2장 · 우선 목록 | 비 오는 날은 ‘우산’, 신고 데스크는 ‘장갑’과 ‘키’를 먼저 봅니다. | 신고 데스크의 우선 목록을 비웁니다. | 두 데스크의 첫 물건과 빈 목록에서의 결과 |
| 3장 · 새 출력 형식 | 일반 텍스트와 굵은 제목에 항목 기호가 붙는 bullet을 추가합니다. | 등록되지 않은 pdf로 출력합니다. | 세 형식의 문자열과 예외가 발생한 함수 이름 |
| 4장 · 기존 게시판 연결 | 기존 게시판은 이름 주위를 대괄호로 감쌉니다. 출력할 때 양 끝 공백을 지우고 호출도 기록해 주세요. | ‘ 장갑 ’을 입력하고 한 조합에서만 ‘ 키 ’를 다시 호출합니다. | 같은 출력, 두 조합의 서로 다른 기록, 감싼 순서 |
| 5장 · 운영 코드 선택 | tag 형식과 사용자가 켜고 끄는 호출 기록을 지원합니다. | 형식을 pdf로 바꾸고 기록을 켭니다. | 같은 테스트를 통과한 두 구현과 새 요구 한 건에서 바뀔 위치 |

## 담당자가 확인할 예시

| 요청 | 기대하는 게시 원문 | 기대하는 호출 기록 |
|---|---|---|
| 처음에 기록이 비어 있고, tag로 ‘우산’ 한 줄 출력, 기록 끄기 | #우산 | 빈 목록 |
| 같은 상태에서 tag로 ‘키’ 한 줄 출력, 기록 켜기 | #키 | ‘키’ 한 건 |
| 다시 빈 기록에서 미등록 pdf로 ‘키’ 출력, 기록 켜기 | 예외 발생 | 빈 목록 |

테스트가 멈추면 실패한 줄의 실제 문자열부터 확인하세요. 출력에 성공했는데 기록이 두 번 남았다면 어느 함수에서 목록에 추가하는지 따라갑니다. 두 객체를 겹쳤다면 같은 부가 기능을 두 번 붙였는지도 살펴보세요.

## 팀의 cases.md에 넘길 한 줄

마지막 실습에서 직접 고른 물건과 형식으로 실행하세요. 실제값에는 화면에 보인 문자열과 호출 기록을 함께 써 주세요. 완성한 한 줄을 다음 Git 실습의 cases.md로 옮깁니다.

| 입력(이름·형식·기록·초기 목록) | 기대값(출력·기록) | 실제값(출력·기록) |
|---|---|---|
|  |  |  |

예를 들어 초기 기록이 비어 있고 입력이 물병, tag, 기록 켜기라면 기대하는 문자열은 ‘#물병’이고 목록에는 ‘물병’ 한 건이 남습니다. 자신이 고른 입력과 실행값으로 위 칸을 채우세요.
