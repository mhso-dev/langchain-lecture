03

route_request()의 분기와 실패 처리

허용하는 작성 규칙은 billing과 technical 둘입니다. 규칙을 찾을 수 있으면 한 번 쓰고, 그렇지 않으면 추가 설명을 요청합니다. write는 선택된 분기의 지시문과 원문을 실제 모델에 전달합니다.

문의 유형과 호출 횟수

영수증과 오류의 포함 여부로 분류 경로를 선택합니다. 추가 확인이 필요한 입력에서는 안내 작성 함수를 호출하지 않습니다.

두 단서 중 하나만 있을 때는 해당 경로에서 1회 작성합니다. 둘 다 있거나 모두 없으면 clarify로 이동하고 작성 횟수는 0입니다.

순차 실행에서 조건부 실행으로

13장의 작성 단계 앞에 조건이 생겼습니다. technical이면 작성기를 부르고, clarify면 추가 질문을 돌려줍니다.

셀 03 · route_request()로 실행 경로 선택

제공 함수의 writes는 최종 안내 작성 함수를 실제로 몇 번 불렀는지 표시합니다.

분류기가 빈 문자열을 그대로 반환하면 작성 규칙을 찾지 못해 needs_clarification으로 끝납니다. SDK 연결부가 먼저 빈 응답을 예외로 처리하면 route_request는 classification_error를 기록합니다. 어느 쪽도 작성 함수를 부르지 않습니다.

분류 예외와 정상적인 추가 질문

분류 함수가 TimeoutError를 내면 reason은 classification_error입니다. 두 분야의 단서가 함께 있어 분류 함수가 clarify를 돌려주면 needs_clarification입니다. 두 경우 모두 writes는 0이지만 원인 기록이 다릅니다.

04

clarify 경로와 추가 질문

복합 문의와 시스템 오류의 화면 문구가 같으면 사용자가 올바른 다음 행동을 고르기 어렵습니다. 한 건의 분류 기록에서 이유와 안내를 함께 읽습니다.

경계 입력과 원인별 로그

분류는 쉬운 질문보다 모호·복합·범위 밖 입력에서 설계 차이가 드러납니다. 두 분야를 동시에 묻는 질문에 하나만 골라 답하면 나머지 요청이 사라질 수 있습니다. 이번 수업에서는 복합 입력을 추가 질문으로 돌려 범위를 좁힙니다.

등록되지 않은 경로가 반환되면 route not in WRITING_RULES가 참입니다. clarify를 받은 경우와 같은 추가 질문을 돌려주며 write는 호출하지 않습니다.
