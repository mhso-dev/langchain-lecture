06

관련 개념 더 읽기

21장 기준 청크를 같은 벡터로 표현하기

전반 데이터 점검 1H 중 15분 동안 library-1의 본문·원문 ID·page1을 찾아 봅니다. 이전 실습이 실패했다면 이 장의 시작 파일을 사용하세요. 공통 버전과 개별 파일 해시는 course_snapshot.json에 있습니다.

텍스트를 숫자 목록으로 표현하기

임베딩은 텍스트 같은 입력을 숫자 벡터로 표현하는 방법입니다. 의미 임베딩 모델은 학습된 표현을 만들며, 검색 저장소는 그 벡터를 보관하고 가까운 항목을 찾는 역할을 합니다. 저장소 자체가 답변을 생성하는 것은 아닙니다.

이번 계산 실습은 대출·휴관·반납 세 키워드의 존재를 0과1로 표시한 벡터를 사용합니다. 학습된 의미 임베딩이 아니므로 “책을 며칠 빌리나요?”처럼 단어가 달라지면 의미가 같아도 찾지 못할 수 있습니다. 수학과 저장소를 확인하기 위한 기준선입니다.

벡터를 다시 만들 수 있는 조건 기록하기

같은 길이의 숫자 목록이라도 서로 다른 모델로 만들면 같은 의미 공간이라고 볼 수 없습니다. 벡터를 만든 제공자와 모델, 차원, 정규화, 거리 방식, 원문/청크/분할정책의 해시를 함께 기록합니다.

이번 embedding.json은 provider=course-local, model=keyword-presence-v1, dimension=3, normalization=none, distance=squared_l2입니다. semantic_embedding=false는 학습된 의미 임베딩이 아니라는 표시입니다. stored-vectors.json에 기록된 세 벡터를 Chroma와 FAISS 모두 읽어 사용합니다.

거리와 답변 신뢰도는 다릅니다

squared_l2는 같은 위치의 값 차이를 제곱해 더한 거리입니다. 이 예제에서는 작을수록 가깝습니다. 거리0은 벡터가 같다는 뜻이지 문서가 질문에 정확히 답하거나 사실이라는 뜻이 아닙니다.

동일한 벡터가 여러 문서에 있을 수 있고, 동점의 순서는 저장소마다 다를 수 있습니다. 최고 순위 하나만 보고 검색 품질 전체를 판단하지 않습니다.

키워드가 하나도 없는 질문은 교육용 규칙에 따라 검색 결과를 빈 목록으로 돌려줍니다. 이것은 의미가 없다는 수학적 결론이 아닙니다. 실제 의미 임베딩 모델에 같은 영벡터 규칙을 그대로 적용하지 않습니다. 빈 질문과 bool k는 입력 오류로 거부합니다.

Chroma에 문서와 벡터를 함께 저장하기

PersistentClient는 지정 폴더에 데이터를 보관합니다. collection은 관련 문서를 묶는 단위입니다. id·document·embedding·metadata 목록은 같은 순서와 같은 길이를 유지해야 합니다.

configuration의 hnsw.space를 l2로 정해 제곱 L2 거리를 명시합니다. 여기서는 HNSW 내부 구조를 학습 목표에 넣지 않습니다. 컬렉션의 E1 기록이 입력 자료와 다르면 오류를 내므로 모델이나 원문을 바꾸어 기존 컬렉션과 섞지 않습니다.

질의 벡터와 결과의 중첩 목록 읽기

query_embeddings에는 질문 벡터의 목록을 넣습니다. 질문 한 개도 바깥 목록 안에 넣으므로 결과의 ids·documents·metadatas·distances도 질문별 목록으로 돌아옵니다. 첫 질문의 결과는 각 필드의 [0]에 있습니다.

n_results는 반환할 최대 후보 수입니다. 후보를 두 개 받았다고 둘 다 관련 문서라는 뜻은 아닙니다. 문서 본문과 거리를 함께 읽어 필요한 근거가 포함되었는지 확인하세요.

영속화와 메타데이터 2H 실습

ingest 명령은 적재 후 끝납니다. 다음 query 명령은 별도 Python 프로세스에서 같은 chroma-data 폴더와 library_course_v1_e1 컬렉션을 다시 엽니다. 새 실행에서 문서 수와 본문·출처가 유지되는지 확인해야 영속화의 증거가 됩니다.

where={"page":1}은 출처 페이지를 제한하는 메타데이터 필터입니다. 의미 유사도와 다릅니다. 23장에서 같은 저장소를 이어 쓸 때는 실제 폴더와 컬렉션 이름도 넘겨야 합니다. 코드만 다른 폴더에 복사했다고 저장 데이터가 함께 옮겨지지 않습니다.

FAISS로 같은 벡터 검색하기

IndexFlatL2는 같은 차원의 float32 벡터를 추가하고 제곱 L2 거리로 검색합니다. 이 예제의 문서·출처는 docs 목록이 관리하고 FAISS는 벡터의 위치 번호를 반환합니다. 위치와 문서 목록 순서가 어긋나면 다른 원문을 출처로 연결할 수 있습니다.

이번 비교는 같은 벡터·같은 질문·같은 거리 기준으로 수행합니다. Chroma의 영속 문서 관리와 FAISS의 검색 인덱스를 같은 종류의 완성 서비스로 취급하지 않습니다. 실제 속도·규모 우위는 여기서 측정하지 않습니다.

기본 비교는 고유한 정답이 있는 대출 질문의 k=1 결과입니다. 예상 첫 ID는 library-1이고 제곱거리는 0입니다. k=2에서 나머지 두 문서는 동점이므로 순서가 달라도 조건을 먼저 확인하세요. compare_stores.py의 not_run_missing_dependency는 성공이 아니며 --require-stores는 미실행이나 실패가 있으면 종료 코드 2를 반환합니다.

학습된 의미 임베딩으로 바꿀 때

real_embedding.py에는 준비된 클라이언트와 모델 이름으로 텍스트 목록을 임베딩하는 함수가 있습니다. 실제 호출은 수행하지 않았으며 모델 지원·사용 비용·반환 차원을 확인해야 합니다.

문서와 질문은 같은 임베딩 체계로 만들어야 합니다. 문서는 교육용3차원 벡터, 질문은 다른 모델 벡터로 만들면 차원이나 의미 공간이 맞지 않습니다. 모델을 바꾸면 기존 문서 벡터도 다시 만들어 비교 조건을 기록하세요.

실제 API로 전환할 때는 문서와 질문에 같은 모델을 쓰고 문서 벡터도 모두 다시 만듭니다. 학습된 모델의 반환 차원·정규화·거리와 새 원문 해시를 E1에 기록하고 별도 컬렉션으로 검증합니다. 이 장에서는 키를 읽거나 외부 API를 호출하지 않았습니다.
