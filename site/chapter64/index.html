02

interrupt()로 승인 대기

승인이 필요한 그래프는 외부 작업 직전에 실행을 멈추고 상태를 저장합니다. 승인 또는 거절을 전달하면 그 실행을 이어갑니다.

셀 01 · 승인 노드와 체크포인터 구성

노드에서 부수 효과가 생기는 줄은 interrupt 다음에만 둡니다. 같은 승인 번호로 두 번 저장하지 않도록 메모리 사전에서 확인합니다.

처음 interrupt에 닿으면 제안만 보이고 문의 등록은 0건입니다. 같은 작업을 재개하면 이 줄이 승인 또는 거절 값을 반환합니다. 승인 경로만 등록 줄을 지나므로 거절 뒤에는 등록 건수가 0으로 남습니다.

실행 순서를 연결했습니다. 아직 invoke하지 않았으므로 대기 중인 요청도, 등록된 문의도 없습니다.

문의를 보여 주는 시점과 등록하는 시점

문의 내용은 먼저 상태에 담깁니다. inquiries에 등록되는 줄은 interrupt 뒤에 있습니다. 학생이 문의 내용을 볼 수 있어도 아직 등록 건수는 0일 수 있습니다.

셀 02 · interrupt()의 대기 상태

대기 응답이 보여 주는 본문과 실제로 기록된 문의 건수를 확인하세요.

문의 본문 다음에 0이 나옵니다. 승인 화면에 문구를 띄울 수 있지만 등록 함수는 아직 호출되지 않았습니다.

요청 내용이 화면에 나타난 시점의 실행 횟수는 0입니다. 승인 대기 중에 이미 쓰기 작업을 해 버리면 이후의 거절은 효력이 없습니다. 승인으로 재개한 경로와 거절한 경로에서 실제 실행 횟수를 각각 비교해야 합니다.

사람에게 보이는 승인 대상

interrupt는 approval_id와 inquiry_text를 담아 호출자에게 돌려줍니다. 호출자는 __interrupt__의 value에서 문구를 읽고 이 문의를 등록할지 판단합니다.

confirm에서 멈춘 실행

그래프에는 START → confirm → END가 등록되어 있지만 첫 invoke는 confirm 안에서 중단됩니다. InMemorySaver가 대기 상태를 보관하고, chat-a-demo는 그 상태를 다시 찾을 때 쓰는 thread_id입니다.

A1 승인과 A2 거절의 결과 읽기

chat-a-demo에서 A1을 보낸 첫 invoke는 문의 문구를 돌려주고 멈춥니다. 등록은 0건입니다. 같은 config에 Command(resume="approve")를 전달하면 confirm 노드가 재실행되고 A1이 저장됩니다. 별도의 chat-decline에서 A2를 거절하면 declined가 반환되며 A2는 inquiries에 없습니다.

Command(resume=…)와 체크포인트

승인 상태와 등록 건수

각 선택은 문의가 아직 등록되지 않은 같은 초기 조건에서 시작합니다.

대기와 거절은 등록 0건입니다. 승인으로 재개한 실행에서만 completed가 되고 문의가 1건 생깁니다.

같은 thread_id로 Command를 보내면 confirm 안의 interrupt가 결정을 반환합니다. 등록은 그 뒤에 한 번 일어납니다.

셀 03 · Command(resume=…)로 승인 전달

기존 대기 요청에 Command를 보냅니다. 같은 질문을 새로 시작하지 않습니다.

승인 뒤에 다시 실행되는 코드

같은 thread_id로 재개하면 confirm 노드가 처음부터 다시 실행됩니다. 처음에는 interrupt에서 기다리므로 문의가 저장되지 않습니다. 재개하면 승인값을 읽고 저장하거나 거절로 끝납니다. 저장을 interrupt 앞으로 옮기면 승인 전에 쓰기가 일어납니다.

선수 개념 · 35장 메시지 상태와 대화별 체크포인트

같은 스레드에서 결정을 전달하기

Command(resume="approve")를 처음과 같은 config로 전달합니다. 중단됐던 confirm 노드는 처음부터 다시 실행되고 interrupt 자리는 이번에 받은 결정을 돌려줍니다. 등록 코드를 그 뒤에 두면 대기 시점에 부작용이 생기지 않습니다.

같은 승인 ID가 가리키는 항목

inquiries.setdefault는 해당 ID가 없을 때만 새 값을 넣습니다. 이 예제의 중복 방지는 현재 커널의 딕셔너리 안에서 같은 키를 다시 쓸 때의 동작입니다.

interrupt와 Command로 저장 전에 승인받기

63장의 답변을 도서관 문의 기록에 남길지 담당자가 정합니다. 같은 스레드에서 승인 전후의 저장 건수를 읽으세요. 문서 번호와 원문은 63장에서 읽은 값 그대로 씁니다.

from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt, Command
class DeskState(TypedDict, total=False):
    answer: str
    saved: list[str]
approval_events = []
def confirm(state):
    decision = interrupt({"draft": state["answer"]})
    approval_events.append({"name": "confirm", "args": {"decision": decision}})
    return {"saved": [state["answer"]] if decision == "approve" else []}
desk_builder = StateGraph(DeskState)
desk_builder.add_node("confirm", confirm)
desk_builder.add_edge(START, "confirm")
desk_builder.add_edge("confirm", END)
desk_graph = desk_builder.compile(checkpointer=InMemorySaver())
def decide(thread, decision):
    config = {"configurable": {"thread_id": thread}}
    waiting = desk_graph.invoke({"answer": previous["response"]["answer"], "saved": []}, config)
    done = desk_graph.invoke(Command(resume=decision), config)
    return len(waiting["saved"]), done["saved"]
before, saved = decide("loan-approve", "approve")
approved_events = previous["events"] + list(approval_events)
print(before, len(saved), saved[0])
