관련 개념 더 읽기

접속 성공 다음에 확인할 것

74일에는 같은 앱과 자료를 새 호스트로 이어갈 조건을 정했습니다. 오늘은 그 경로의 전송 보호와 데이터 보존을 확인합니다. 접속 주소가 생겼다는 사실, 앱이 응답했다는 사실, 원래 데이터가 남았다는 사실은 서로 다른 근거를 요구합니다.

첫 15분에 74일 examples/student/manual-record.md와 resource-record.json을 읽습니다. 이미지 digest·플랫폼·실제 볼륨·원본 자료 근거가 비어 있으면 먼저 미확인으로 표시합니다. 같은 73일 서비스의 질문과 B1 소유권 경계를 유지하며 새 검색 알고리즘을 만들지는 않습니다.

HTTPS의 보호 구간을 그리기

HTTPS는 HTTP를 TLS로 보호하는 연결입니다. 클라이언트가 접속한 도메인과 인증서의 이름, 신뢰 경로와 유효 기간을 확인합니다. 인증서는 서버의 공개 정보를 전달하고 개인키는 서버가 관리하는 비밀입니다. 개인키 내용을 교재나 과제에 붙이지 않습니다.

기본 구조는 참여자 → HTTPS 프록시 → 내부 API입니다. TLS가 끝나는 프록시와 API 사이의 신뢰 구간도 강사가 검토합니다. HTTPS를 사용해도 공개 수업 토큰이 실제 사용자 인증으로 바뀌지는 않습니다. 이 앱은 승인된 실습 참여자에게만 접근을 제한하는 준비 예제입니다.

프록시가 전달하는 요청과 스트림

프록시는 받은 요청을 내부 api:8000으로 전달합니다. Host와 전달된 프로토콜·접속원 헤더는 경로를 이해하는 정보이며 그 자체로 신뢰된 사용자 신원이 되지 않습니다. 기존 H1의 신원 처리와 소유 조회를 건너뛰는 용도로 사용하지 않습니다.

제공 nginx 설정은 인증서 경로와 도메인을 강사가 채워야 하는 준비 파일입니다. proxy_buffering off는 프록시 버퍼링을 끄는 설정이고, 타임아웃은 실제 응답 시간을 측정한 뒤 정합니다. 이 두 줄만으로 스트림의 취소·완료·저장 시점까지 검증한 것은 아닙니다.

환경변수는 값 대신 주입 경로를 검토하기

이미지 안에 비밀번호를 복사하거나 Dockerfile의 평문 값으로 고정하지 않습니다. 실제 Compose 해석 결과나 환경변수 전체를 출력하면 값이 드러날 수 있으므로 제공 명령은 구성의 조용한 검사와 제한된 식별 정보 확인을 구분합니다. 이 교재에는 실제 환경 파일이나 자격증명이 포함되지 않습니다.

RDS를 선택하면 DB 운영 책임이 일부 AWS로 옮겨가지만 같은 자료의 식별·소유권·검색·인용 검사는 남습니다. 기존 볼륨이 RDS에 자동 연결되지 않습니다. 이번 필수 실습에서는 RDS 자원이나 새 연결 어댑터를 만들지 않고 private 연결·역할/확장·버전·복구 호환·비용의 추가 검증표를 읽습니다.

스트림은 조각을 받았다는 사실과 전체 결과를 받았다는 사실을 나눕니다. 클라이언트 취소·비완료 응답·저장 여부는 기존 H1의 경계로 확인합니다. 제공 로컬 검사와 실제 프록시를 통과한 스트림 관측은 서로 다른 증거입니다.

재시작과 데이터 보존은 다른 검사

컨테이너 재시작은 프로세스를 다시 실행하는 작업입니다. 이미지를 교체하거나 환경 설정을 바꿨다면 기존 컨테이너의 단순 restart와 새 구성으로 재생성하는 작업을 구분해야 합니다. 어느 경우든 같은 물리 저장소를 확인해야 데이터 보존을 설명할 수 있습니다.

전후 비교에서는 문서·대화·turn의 같은 ID와 owner, 상태, 전체 A1과 source 매핑을 확인합니다. 행 개수가 같아도 내용이 바뀔 수 있습니다. 새 호스트에 같은 볼륨 이름만 적었거나 새 샘플을 다시 넣은 것은 원래 자료의 보존이 아닙니다.

백업 파일이 보장하는 범위

pg_dump는 한 데이터베이스의 논리 백업을 만들 수 있습니다. 그 파일에 운영체제·인증서·환경변수·다른 DB·전역 역할이 모두 들어간다고 가정하지 않습니다. 역할·확장·스키마 버전과 앱 이미지의 재현 정보를 따로 보존합니다.

제공 준비 명령은 custom 형식과 압축 없음으로 백업을 만들고 목록을 읽는 절차입니다. 백업 경로·해시·읽기 가능 여부·보관 권한은 실제 생성 후 기록합니다. 백업에 문서 원문이나 사용자 자료가 들어갈 수 있으므로 교재 폴더에 실제 운영 백업을 올리지 않습니다.

원본을 보존한 별도 빈 대상

복구 대상은 원본과 다른 DB 이름뿐 아니라 실제 호스트/저장 위치도 구분한 빈 대상이어야 합니다. 강사가 대상이 비어 있고 앱 쓰기가 멈췄다는 근거를 먼저 확인합니다. 원본 DB를 지우거나 그 위에 덮어써 연습하지 않습니다.

제공 계획은 --clean·--create·원본 덮어쓰기를 사용하지 않습니다. 이미 준비된 별도 빈 DB에 --exit-on-error와 --single-transaction으로 복구를 시도하는 절차를 설명합니다. 이것은 실행한 결과가 아니며 연결 대상·역할·확장·용량·버전 검증을 대신하지 않습니다.

이 장 폴더에서 다음 명령을 시작합니다. 이미 examples/cloud에 있으면 cd를 반복하지 않습니다. 합성 계획의 성공은 필드와 조합이 맞는다는 뜻이며 backup_read=false와 actual_restore_verified=false는 그대로입니다. 빈 학생 입력의 실패는 미작성 상태를 보여 줍니다.

검증 항목에는 행 수뿐 아니라 같은 ID·owner·업로드 상태·전체 A1 출처·스키마·원문/청크/벡터 매핑·같은 질문과 필터·실패/소유권 사례·원본 불변이 포함됩니다. 하나라도 실제로 수행하지 않았다면 그 칸을 통과로 채우지 않습니다.

복구 후에는 원래 B1의 문서·대화·turn과 73일의 검색 매핑을 함께 읽습니다. 동일 질문이 비슷한 답을 냈다는 이유만으로 같은 출처와 소유권이 보존되었다고 말할 수 없습니다. result.sources의 원문 ID·page·내용과 저장된 전체 A1을 비교합니다.
