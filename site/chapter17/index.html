02

도구 결과를 대화 기록에 누적

도구 호출 루프는 모델이 다음 도구를 요청할 때마다 실행 결과를 기록하고 다시 호출합니다. 최종 답변과 호출 상한은 서로 다른 종료 사유입니다.

두 도구를 쓰기 위해 이 장에서는 이름을 get_hours와 get_loan_rule로 정했습니다. 함수 이름이 달라도 각 요청과 결과를 같은 call_id로 연결한다는 원칙은 16장과 같습니다.

제공된 execute는 이름·인자를 검사하고 조회 값을 JSON으로 묶습니다. 하나의 도구 결과부터 읽으세요.

10:00~16:00

원래 질문은 주말 운영 시간과 대출 기간을 함께 요구합니다. 첫 도구 결과에는 10:00~16:00만 있습니다. 이 시점에 루프를 끝내면 대출 기간은 비어 있습니다. 실제 에이전트에서는 모델이 다음 호출을 결정합니다. 이 실습에서는 미리 정해 둔 두 번째 요청 c2로 대출 기간을 조회합니다.

16장의 시간표에 대출 규칙을 더했습니다. 시간표는 day를 받지만 대출 규칙은 빈 객체를 받습니다.

03

최종 응답과 최대 호출 횟수

모델 호출과 도구 실행은 따로 셉니다. 이번 대본의 첫 두 응답은 도구 호출이고 세 번째 응답은 답변입니다. 아래 함수는 진짜 모델 대신 준비된 응답을 순서대로 읽는 작은 루프입니다. 잘못된 ID와 중복을 검사하는 전체 수업 예제는 같은 종료 규칙을 더 엄격하게 적용합니다.

도구를 실행한 뒤의 다음 응답

주말 시간과 대출 기간을 함께 묻는 질문에 첫 응답은 운영 시간, 둘째 응답은 대출 규칙을 요청합니다. 이 장은 세 모델 응답을 script에 미리 담아 두고, 어떤 입력에서 history가 늘어나거나 루프가 끝나는지 관찰합니다.

셀 03 · 최종 메시지에서 루프 종료

회차마다 먼저 응답 종류를 읽습니다. 최종 응답을 받거나 상한에 닿으면 함수를 빠져나갑니다.

모델이 더 요청할 도구가 없다고 답하면 이 루프는 끝납니다. 요청 ID 중복을 막으려면 execute(item)를 부르기 전에 이미 처리한 ID인지 확인해야 합니다. 실행 뒤에 ID를 비교하면 같은 도구가 이미 두 번 작동했을 수 있습니다.

실행 결과

세 번째 응답은 message이므로 반복을 끝냅니다. 응답 목록이 먼저 바닥나면 함수 마지막 줄에서 incomplete를 반환합니다. 외부 모델을 부르지 않고도 두 종료 경로를 따로 재현할 수 있습니다.

응답 종류와 호출 상한 검사 순서

run_script는 응답 항목을 history에 넣은 뒤 type을 확인합니다. message이면 completed로 끝납니다. 도구 요청이고 이미 max_calls에 도달했다면 model_limit을 반환합니다. 예산이 남을 때만 도구를 실행해 결과를 history에 붙입니다.

복수 도구 실행 로그

script의 각 항목은 미리 작성한 응답입니다. 반면 function_call_output은 execute를 실행한 자리에서 만들어집니다. history에서 두 종류를 구분하면 도구를 실제로 몇 번 실행했는지 셀 수 있습니다.

06

한 번의 모델 응답에 도구 요청이 두 개라면?

기존 예제에서는 모델 응답 한 개마다 도구 요청이 하나씩 왔습니다. 이제 첫 응답에 주말 시간과 대출 기간 요청이 같이 들어옵니다. 모델이 답한 횟수와 프로그램이 도구를 실행한 횟수를 따로 세어 보세요.

셀 08 · 두 도구를 요청하는 첫 응답 읽기

수업용 결정 함수는 아직 도구 결과가 없으면 요청 두 건을 한꺼번에 돌려줍니다. 결과가 오면 두 요청 ID를 찾아 조회값으로 최종 문장을 만듭니다.

실행 결과

['c1', 'c2']

첫 응답 한 번에 c1과 c2가 들어 있습니다. 두 도구는 아직 실행되지 않았습니다. decide_turn은 재현을 위해 응답을 정한 함수이며 실제 모델을 호출하지 않습니다.

과제 09 · 두 도구 결과를 넣은 뒤 다시 판단하기

첫 응답의 요청을 각각 execute로 실행해 요청과 결과를 기록하세요. 그 기록으로 decide_turn을 한 번 더 호출하고, 모델 응답 수·도구 결과 수·최종 문장을 출력하세요. 첫 응답과 최종 응답은 각각 한 번으로 셉니다.
