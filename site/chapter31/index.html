검색 서버가 응답하지 않았을 때 no_evidence를 반환하면 사용자는 없는 자료를 보완하려고 할 수 있습니다. 운영 오류는 search_status=error와 result=None으로 남깁니다. A1의 answered/no_evidence/invalid_citation 세 결과와 섞지 않습니다.

answered는 인용 형식 검사 통과를 뜻합니다. “대출은 999일입니다. [library-1]”처럼 올바른 ID에 틀린 문장을 붙여도 이 검사만으로는 거절하지 못합니다. 내용의 사실성은 원문 대조나 별도 평가가 필요합니다.

예상 오류만 상태로 바꾸기

입력 검사는 연결 오류 처리보다 앞에 있습니다. 공백 질문과 bool k는 잘못된 요청이므로 ValueError를 그대로 보여 줍니다. 검색 데이터에 text나 source가 없으면 DataContractError로 중단합니다. 이 오류까지 검색 장애로 삼으면 원본 문제를 고치지 못합니다.

이 예제는 TimeoutError와 ConnectionError만 예상 연결 오류로 처리합니다. 실제 라이브러리는 다른 예외 타입을 사용할 수 있으므로 해당 어댑터에서 명시적으로 매핑해야 합니다. 예외 원문에는 주소나 내부 정보가 들어 있을 수 있어 상태에는 종류만 남깁니다. 실제 서비스에서 비공개 운영 로그를 어떻게 남길지는 별도 설계입니다.

답변과 원문을 연결하는 필드 유지하기

A1은 answer의 대괄호 인용을 모으고 이번 documents의 ID 집합과 비교합니다. 인용이 없거나 목록 밖 ID가 하나라도 섞이면 invalid_citation입니다. 전체 문서 저장소에 존재하는 ID여도 이번 검색에서 받지 않았다면 허용하지 않습니다.

sources의 각 항목은 id·text·source·page가 모두 있는 원문 객체입니다. 같은 ID를 여러 번 인용해도 출처 목록에는 한 번만 남습니다. 답변을 만드는 데 실제 쓰지 않은 검색 결과는 sources에 넣지 않습니다. 고정 생성기는 첫 문서 문장만 반환하므로 기본 k=2에서 검색 두 개와 인용 한 개가 정상입니다.
