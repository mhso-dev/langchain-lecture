06

관련 개념 더 읽기

15일 원본 호출과 관찰용 딕셔너리 구분

첫 1H 중 15분에 본인의 tool-schema/request-observation.json을 엽니다. 기록이 없으면 제공 tool_request.py의 교육용 호출을 다시 관찰하고 그 사실을 표시합니다. raw_output의 function_call.arguments는 JSON 문자열이고 parsed_calls의 arguments는 읽기 편하게 파싱한 딕셔너리입니다. execute_call에는 완료된 응답의 원본 function_call을 넘깁니다. 관찰용 딕셔너리는 실행 요청을 대신하지 않습니다.

한 번의 왕복에서 누가 일하나요?

모델이 get_library_hours와 day=weekend를 요청하면 Python 코드가 이름과 인자를 검사합니다. 조건에 맞으면 Python 함수가 실제로 실행되고 결과를 JSON 문자열로 바꿉니다. 이후 모델이 그 결과를 받아 답변을 작성합니다.

여기서 실제로 실행되는 함수는 교육용 정적 시간표를 반환합니다. 실제 도서관 서버나 예약 시스템에 접속하지 않습니다. 기본 모델 응답은 모의 자료지만 도구 함수 실행과 메시지 연결 코드는 실제로 실행합니다.

함수는 day를 받아 정해진 시간표에서 값을 읽습니다. 데이터는 가상의 수업 자료입니다. 이 함수를 실행했다는 사실과 실제 기관 운영 시간이 맞는다는 주장은 구분해야 합니다.

실행 전에 이름과 인자를 검사하기

call_id가 없거나 문자열이 아니거나 공백뿐이면 결과 연결이 불가능해 도구 실행 전에 중단합니다. 유효한 ID는 앞뒤 공백을 포함해 원래 문자열 그대로 결과에 연결합니다. 이름이 허용한 함수와 다르거나, 인자가 JSON 객체가 아니거나, day 외의 필드가 있으면 함수 실행 대신 오류 결과를 만듭니다.

모델에 strict 스키마를 주었더라도 애플리케이션의 실행 경계는 유지합니다. 검사는 입력이 어디서 왔는지와 관계없이 함수의 약속을 지키게 합니다. 이 예제는 ValueError·TypeError·KeyError를 알려진 입력 실패로 처리합니다.

15일 raw_output 안의 원본 function_call을 사용하세요. parsed_calls 안의 arguments는 이미 딕셔너리이므로 이 함수가 기대하는 JSON 문자열과 다릅니다. 잘못 넘기면 invalid_tool_request가 되며 도구는 실행되지 않습니다.

함수 결과를 같은 호출 ID로 반환하기

위 모양은 주요 필드를 설명하기 위해 data의 일부만 보인 예시입니다. 실행 파일은 day·hours·source를 포함한 전체 결과를 반환합니다. output은 JSON 문자열이며 call_id는 원래 호출 요청의 값과 같아야 합니다.

오류도 결과로 돌려줄 수 있지만 ok=False처럼 실패가 드러나야 합니다. 도구 실행에 실패했는데 정상 조회 문장을 대신 만들어 주면 모델과 사용자 모두 실패를 알기 어렵습니다.

응답 항목과 결과를 순서대로 이어 붙이기

completed만으로 최종 답변이 있는 것은 아닙니다. read_final은 assistant의 텍스트 또는 명시적인 거절을 확인합니다. 빈 output과 공백 텍스트는 오류이며, 명시적인 거절은 final_reply.response_kind가 refusal인 종료 결과입니다. 답변과 거절을 모두 정상 답변으로 합치지 않습니다.

run_turn은 도구 호출이 없는 첫 응답과 도구 결과를 보낸 뒤의 최종 응답에 같은 검사를 적용합니다. final_reply에서 사용자에게 전달할 내용을 찾고 history에서 같은 근거를 확인하세요.

history에는 사용자 질문, 첫 모델 응답의 모든 output 항목, 도구 결과, 마지막 모델 응답이 순서대로 들어갑니다. 호출 항목만 골라 남기고 다른 필요한 항목을 버리지 않도록 첫 응답 전체를 이어 붙입니다.

이번 장은 도구 한 개의 한 번 왕복으로 제한합니다. 첫 응답에 호출이 없으면 모델 요청 한 번으로 끝납니다. 호출이 두 개 이상이면 실행하지 않고 중단합니다. 도구 결과 뒤에는 tool_choice=none으로 추가 요청 대신 답변을 요청합니다.
