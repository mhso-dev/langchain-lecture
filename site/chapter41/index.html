제공 검색은 39일의 유지 기준선입니다. 34일의 Graph 도구 흐름에 이 검색 함수를 연결하고, 바깥쪽에는 29일의 메모리 체크포인터를 둡니다. 실제 LLM이 대화를 이해하는 예제가 아니며, 현재 질문을 교육용 규칙으로 처리합니다.

문서를 확인한 뒤 질문을 연결하기

화면 원형은 R1 문서 JSON을 입력받아 먼저 확인합니다. id/text/source/page가 있어야 하며,39일에 유지하기로 한 고정 문서와 같아야 연결합니다. 이 단계는 파일에서 새 임베딩을 만들거나 임의 문서를 검색하는 범용 업로드 기능이 아닙니다.

JSON의 줄바꿈이나 들여쓰기가 달라도 객체로 읽은 내용이 같으면 괜찮습니다. 하지만 본문·순서·출처·page를 바꾸면 기존 인덱스와 평가 조건을 유지했다고 볼 수 없습니다. 준비 단계에서 자료가 달라졌다는 사실을 드러내고 별도 자료 준비로 돌아갑니다.

자료를 다시 연결할 때는 이전 current/history를 비우고 새 engine을 만듭니다. 이 동작은 “새 대화” 버튼과 다릅니다. 새 대화는 같은 engine에서 새 thread를 선택하지만, 자료 재연결은 이 원형의 메모리 저장소 자체도 새로 시작합니다.

한 질문의 Graph 흐름을 대화 안에서 실행하기

GraphSession은 메모리 체크포인터가 있는 바깥 Graph를 만듭니다. respond 노드는 현재 question을 34일 run_tool_graph에 넘깁니다. 검색은 39일 기준선으로 주입하고, 결과의 result/error_type/search_status/trace를 latest에 담습니다.

이 바깥 노드는 질문마다 documents와 latest를 새 결과로 교체합니다. messages에는 새 사용자 메시지와 새 응답 메시지를 추가합니다. 이전 검색 문서를 자동으로 다음 질문의 근거로 넘기지 않는 것이 현재 예제의 정책입니다.

invoke의 입력에 documents=[]와 latest=None을 명시한 이유를 보세요. 새 질문이 시작될 때 현재 근거와 현재 결과를 비웁니다. 검색이 실패하더라도 과거 정상 답변을 새 질문의 결과로 가져오지 않게 하는 경계입니다. inspect는 저장 상태를 읽기만 하며 질문 처리를 다시 실행하지 않습니다.

화면 handler가 Graph에 넘기는 값

submit_turn은 화면의 session, 새 question, 그리고 invoke 함수를 받습니다. invoke(thread_id, question)가 result와 error_type을 돌려주는 경계입니다. 화면 로직은 Graph 내부 구현을 알 필요 없이 이 결과를 검사해 표시할 수 있습니다.

함수는 입력 session을 deepcopy해 다음 상태를 만듭니다. 기존 관찰을 제자리에서 덮지 않으므로 이전 결과와 새 결과를 나란히 비교할 수 있습니다. 현재 view는 실행 전에 빈 상태로 바뀌며, 실행 결과가 오류이면 result=None을 유지합니다.

같은 대화·다른 대화·새 대화를 비교하기

같은 engine에서 A로 두 번 질문하면 A의 사용자 발화가 두 개가 됩니다. B로 한 번 질문하면 B에는 한 번의 기록이 쌓입니다. 아직 시작하지 않은 C는 비어 있습니다. 서로 다른 thread의 기록이 섞이지 않았는지는 같은 engine의 저장 상태를 읽어 확인합니다.

새 대화 함수는 새 UUID와 빈 current/history를 만듭니다. UUID의 구체적인 문자열을 외울 필요는 없습니다. 이미 쓰던 ID를 다시 넘기면 같은 Graph 대화를 선택하므로, 사용자가 새 대화를 누를 때는 기본 생성 경로를 사용합니다.

과거 대화의 출처와 현재 답변의 출처를 구분하기

history의 첫 정상 답변에 출처가 남아 있어도 현재 질문이 자료 없음이면 현재 영역에는 출처가 없어야 합니다. 과거 기록 자체를 지울 필요는 없지만, 현재 질문의 근거처럼 표시하지 않아야 합니다. 현재 영역은 current.result의 sources만 읽습니다.

39일 기준선의 반납 문장 잘림은 여기에서도 남아 있습니다. 실제 인용과 페이지가 표시되더라도 답변이 완결됐다고 단정할 수 없습니다. 출처 확인은 ID/필드 검사와 문장 의미 검토를 함께 요구합니다.

정상 다음 오류가 나도 이전 답변을 되살리지 않기

검색 TimeoutError 진단은 실제 외부 네트워크 장애를 일으킨 것이 아니라, 제공 검색 함수가 예외를 내도록 주입한 로컬 검사입니다. Graph는 그 실패를 error_type으로 남기고 result=None으로 종료합니다. 화면 handler도 별도 실행 오류로 표시합니다.

일부 통신 예외는 Graph가 결과 객체로 반환할 수 있고, 입력·계약 오류는 invoke에서 직접 예외가 될 수도 있습니다. submit_turn은 두 경로를 모두 error 상태로 정리합니다. 자료 없음으로 바꾸거나 이전 정상 result를 대체값으로 쓰지 않습니다.
