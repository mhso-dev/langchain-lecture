06

관련 개념 더 읽기

오늘 만들 것과 학습 범위

결제 영수증과 API 오류 문의를 처리하는 작은 안내 봇을 만듭니다. 같은 질문을 네 가지 방식으로 실행하고, 누가 경로를 골랐으며 어떤 도구가 실제로 실행됐는지 비교합니다.

이 장은 create_agent와 Function Calling을 배운 뒤의 65일차 교재입니다. 새 프레임워크를 많이 익히기보다 분류 결과가 실행 경로로 이어지는 지점을 확인합니다. Jev는 2시간 선택 실습이며 필수 프로젝트 기술이 아닙니다.

누가 선택하고 누가 실행하나요?

모델은 함수 이름과 인자를 요청할 수 있지만 Python 함수를 직접 실행하지는 않습니다. create_agent가 요청을 받아 등록된 도구를 실행하고 결과를 모델에 돌려줍니다. 도구 이름을 답변 문장에 썼다는 사실만으로 실제 실행을 확인할 수는 없습니다.

기본 에이전트에는 두 도구를 모두 줍니다. 분류를 추가한 예제는 Python 코드가 먼저 분야를 정하고 그 분야의 도구만 create_agent에 넘깁니다. 이 외부 분류 단계는 매 요청마다 실행되며, 에이전트가 선택적으로 호출하는 도구가 아닙니다.

두 도구의 이름, 설명, 입력 형태부터 확인합니다. 아래 query는 모델이 생성할 문자열 인자입니다. 함수 설명은 모델이 도구를 고를 때 참고하고, 실제 반환 값은 Python 코드가 만듭니다.

규칙과 LLM으로 먼저 분류하기

규칙 분류는 지정한 단어를 찾습니다. 단어가 없는 표현이나 두 분야가 섞인 질문에서는 추가 질문으로 보냅니다. 규칙을 복잡하게 늘리기 전에 어떤 문장에서 실패하는지 기록합니다.

LLM 분류는 RouteLabel 양식으로 결과를 받습니다. 허용된 문자열을 반환한다는 것은 출력 형식이 맞다는 뜻입니다. 의미상 올바른 분야를 골랐는지는 별도로 비교해야 합니다.

선택 실습: Jev로 한 가지 판단 맡기기

Jev는 이 예제에서 답변 문장을 작성하지 않습니다. 주어진 선택지 중 어느 분야에 해당하는지 판단한 결과를 받고, 답변 생성은 GPT가 맡습니다. TypeSafeClassifier는 LangChain의 Runnable이므로 invoke로 실행하지만 ChatOpenAI의 채팅 응답 형태와는 다릅니다.

먼저 Choice 하나만 사용합니다. Noul은 예/아니오의 확률, Score는 순서가 있는 수준을 평가할 때 쓰지만 이번 필수 코딩에는 추가하지 않습니다.

분류 결과를 create_agent에 연결하기

prepare_request가 입력을 검사하고 분류합니다. baseline에서는 두 도구를 모두 넘기고, 나머지 방식에서는 고정된 TOOL_GROUPS에서 한 그룹만 고릅니다. 모델이 돌려준 문자열을 eval이나 임의 함수 실행에 사용하지 않습니다.

decision은 이번 요청의 Python 지역 변수입니다. agent.invoke가 반환한 state의 messages에는 사용자 메시지, 도구 호출을 포함한 AIMessage, 도구 결과 ToolMessage, 마지막 AIMessage가 들어갑니다. 이 예제는 호출마다 새 에이전트를 만들며 체크포인트·장기 기억을 저장하지 않습니다.

classify_request를 앞에서 직접 호출했으므로 분류가 반드시 선행됩니다. 같은 분류 함수를 에이전트 Tool로만 등록하면 호출 여부를 모델이 선택하게 됩니다. 분류가 필수인 요구에는 앞단 워크플로우나 before_agent 훅을 검토할 수 있습니다. 이번에는 실행 순서가 드러나는 Python 분기로 익힙니다.

위 출력은 2026년 11월 15일 실제 실행 결과에서 사용량·소요 시간 필드를 제외한 발췌입니다. 문장과 분류 수치는 실행마다 달라질 수 있습니다. probability와 confidence가 1.0으로 나와도 모든 질문을 정확하게 분류한다는 뜻은 아닙니다. model_calls는 답변 에이전트 안의 호출 수이므로 clarify 결과의 0에도 앞단 Jev 분류 1회는 포함되지 않습니다.

정답·호출 수·실패 경로 확인하기

네트워크 없는 검사와 실제 API 실행을 나누어 확인합니다. 로컬 검사는 정해진 경계 조건을 검사하며 Jev 모델의 정확도를 증명하지 않습니다. 실제 API 결과도 소수 사례의 연결 확인과 전체 성능 평가를 구분합니다.

같은 프로젝트에 분류를 연결하기

결제·기술 문의에서 분류와 실행을 구분했다면 같은 경계를 과정 안내 프로젝트로 옮겨 봅니다. Q03의 질문·p3 원문·출처를 그대로 두고 요청 의도만 별도 입력으로 전달합니다. 분류 결과는 안내 읽기 또는 모의 문의 제안의 후보 경로입니다. 사용자 신원이나 승인을 만들지 않습니다.

이 예제의 분류는 고정 로컬 규칙이며 자연어 전체를 이해하는 모델이 아닙니다. 실제 create_agent와 LangGraph는 실행하지만 내부 모델 판단은 고정 대본입니다. 앞의 실제 API 7사례와는 다른 관측입니다.
