02

검색 결과의 중첩 목록

Retriever는 질문을 받아 관련 문서를 돌려주는 구성 요소입니다. 몇 건을 반환할지와 어떤 출처를 허용할지도 입력 조건이 됩니다.

Chroma의 질의 응답은 여러 질문을 한 번에 받을 수 있게 질문별로 다시 묶여 있습니다. 아래 자료는 실제 서버를 호출하지 않고 그 모양만 담아 둔 한 질문의 응답 예시입니다.

셀 01 · 중첩 검색 결과의 인덱싱

첫 질문의 검색 결과에서 1위 후보의 문서 ID를 읽습니다.

실행 결과

library-1

library-1이 나옵니다. [0]을 한 번만 쓰면 문자열이 아니라 첫 질문의 ID 목록이 남습니다.

질문 두 개를 한 번에 검색하면 결과의 바깥 목록에도 항목이 두 개 생깁니다. 바깥쪽 인덱스는 어느 질문인지, 안쪽 인덱스는 그 질문에서 몇 번째 후보인지 고릅니다. 첫 질문의 첫 답에 쪽 번호를 붙일 때는 ids와 metadatas 양쪽에서 같은 두 위치를 읽어야 합니다.

질의 번호와 결과 순위 읽기

raw['ids'][0][0]에서 첫 번째 0은 첫 질의, 두 번째 0은 첫 후보를 뜻합니다. 본문과 메타데이터에서도 같은 두 위치를 골라야 한 문서의 정보가 됩니다.

세 열의 같은 위치를 사용해 id, text, source, page가 있는 사전을 만드세요.

풀이와 실행 결과 보기

실행 결과

{'id': 'library-1', 'text': '도서 대출 기간은 14일입니다.', 'source': '가상 도서관 이용 안내', 'page': 1}

library-1과 1쪽이 같은 사전에 들어갑니다. 여러 결과를 합칠 때는 각 열의 길이가 같은지도 확인합니다. 출처가 누락된 행을 앞 행의 출처로 채우면 안 됩니다.

준비된 결과로 반환 모양 확인하기

raw는 첫 검색 결과를 미리 담아 둔 딕셔너리입니다. 이 값으로 ID·본문·출처·쪽을 연결하는 코드를 먼저 확인한 뒤, 다음 셀에서 retrieve가 실제 후보 순서를 정하는 과정을 살펴봅니다.

03

retrieve()의 k와 메타데이터 필터

retrieve(question, k)는 문서 목록을 돌려줍니다. 여기서는 세 키워드의 거리로 계산하는 로컬 검색을 실행합니다. 앞의 Chroma 모양 예시를 실제 조회했다는 뜻은 아닙니다.

Retriever 함수의 역할

검색을 화면이나 답변 생성 코드 안에 섞으면 저장소를 바꾸거나 실패 원인을 찾기 어려워집니다. retrieve(question,k)는 질문과 최대 후보 수를 받아 문서 목록을 반환하는 경계로 둡니다.

반환 문서는 id·text·source·page 네 필드를 유지합니다. 이후 LCEL과 LangGraph에서 같은 계약을 사용하면 검색 결과를 처리하는 부분을 재사용할 수 있습니다. 계약이 같아도 실제 검색 알고리즘과 품질이 같다는 뜻은 아닙니다.

공통 계약
입력·출력뜻
question: str검색할 질문
k: int반환 후보 수의 상한
list[dict]검색된 문서들, 없으면 빈 목록
id/text/source/page식별자·본문·출처·원문 위치

공백을 제거한 질문이 비어 있으면 입력 오류입니다. k는 1 이상의 정수이며 bool은 제외합니다. Python의 True가 정수처럼 취급될 수 있어 따로 확인합니다. 검색 결과가 없는 정상 상황은 []이고, 출처가 잘못되거나 저장소가 응답하지 않는 상황은 예외입니다.

셀 03 · retrieve()의 검색 개수

자료의 원문 ID를 유지합니다. k는 최대 후보 수이고, 질문은 공백을 제외한 문자열이어야 합니다.

휴관 질문에서는 결과 한 건이 있지만 주차 요금에는 대응하는 단어가 없어 빈 목록이 돌아옵니다. 질문을 바꾸면 첫 항목을 읽기 전 목록에 문서가 있는지 확인하세요.

실행 결과

library-2

library-2는 둘째 쪽의 휴관 안내입니다. k=1은 하나만 가져오라는 입력이지, 그 한 건으로 모든 질문에 답할 수 있다는 보장이 아닙니다.

후보를 거른 뒤 거리순으로 정렬하기

retrieve는 documents에서 page 조건에 맞는 후보를 고른 뒤 질의와의 제곱 거리, 문서 ID 순으로 정렬하고 앞의 k개를 반환합니다. page=1이면 휴관 문서가 정렬 대상에서 이미 빠집니다.

셀 04 · 메타데이터 필터의 page

휴관 질문은 그대로 두고 검색할 수 있는 쪽만 바꿉니다.

실행 결과

library-1 도서 대출 기간은 14일입니다.

1쪽에 남은 library-1은 대출 문장입니다. 진짜 근거가 필터 밖에 있어서 상위 한 건이 질문과 어긋납니다. k만 크게 바꿔도 범위 밖 문서는 돌아오지 않습니다.

top-k와 필터

k를 늘리면 더 많은 후보를 받을 수 있지만 그만큼 관련 없는 문서도 함께 들어올 수 있습니다. 반환 후보 수가 늘었다는 사실만으로 답변 품질 향상을 주장하지 않습니다.

where는 메타데이터 조건입니다. 같은 질문에 page=1 필터를 주면 해당 페이지 범위만 검색합니다. 잘못된 필터로 필요한 문서를 제외하면 질문이 맞아도 근거를 찾지 못할 수 있습니다.

대출 질문의 k=1에서는 library-1을 기대합니다. k=2에는 거리 동점의 무관한 문서가 들어갈 수 있습니다. page=1 필터는 검색 범위를 1페이지로 제한하는 조건이며 답변의 사실성 점수가 아닙니다. 대역 객체가 필터 인수를 받는지 검사하는 것과 실제 저장소가 필터를 적용하는 것은 서로 다른 검사입니다.

과제 05 · 검색 결과의 표시 형식

hits의 첫 문서에서 ID를 꺼내 대괄호로 감싸고 출처와 쪽을 붙인 다음 줄에 본문을 출력하세요.

풀이와 실행 결과 보기

실행 결과

[library-2] 가상 도서관 이용 안내 / p.2
도서관은 월요일에 휴관합니다.

[library-2]와 2쪽이 월요일 휴관 문장 바로 위에 붙습니다. 주차처럼 세 키워드 중 어느 것도 들어 있지 않은 질문에서는 빈 목록이 나오므로 hits[0]을 읽기 전에 목록이 비었는지 확인해야 합니다.

질문과 근거 문맥

문맥은 모델에게 제공할 근거 문서 묶음입니다. 본문 앞에 id와 출처·페이지를 붙이면 생성 답변의 인용 식별자를 다시 원문과 연결할 수 있습니다. 문서에 없는 사실을 출처 이름으로 포장하지 않도록 원문 본문도 함께 전달합니다.

질문은 질문으로, 근거는 근거로 전달합니다. 검색된 문서에 “앞선 지시를 무시하라” 같은 문장이 있어도 서비스의 실행 지침으로 따르지 않도록 경계를 명시합니다. 이 장은 문맥을 만드는 단계이며 모델을 호출하지 않습니다.

ID는 [library-1]처럼 대괄호로 표시합니다. 팀 자료의 team-01:p-01처럼 콜론을 포함한 ID도 허용합니다. 페이지를 모르는데 1로 채우거나 출처가 없는데 임의 이름을 만드는 대신 입력 자료를 검토합니다. 이 장에서는 모델을 호출하지 않습니다.

05

복습과 실습 점검

질문을 ‘주차 요금은?’으로 바꿔 retrieve의 반환값을 확인하세요. 빈 목록은 정상 검색 중 근거를 못 찾은 경우입니다. 저장소 연결 실패를 같은 빈 목록으로 바꾸면 다음 장에서 사용자에게 잘못된 이유를 안내하게 됩니다.
