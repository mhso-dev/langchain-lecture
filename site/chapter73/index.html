셀 01 · 질문과 두 문서의 거리 구하기

검색 질문과 두 문서에 같은 규칙을 적용합니다. 질문과 거리가 가까운 문서부터 정렬합니다.

p2에서 다른 좌표가 두 개이고 각 차이의 크기가 1이면 제곱합은 1²+1²=2입니다. L2 거리는 여기에 제곱근을 취한 약 1.414입니다. 같은 벡터라도 거리와 거리의 제곱은 숫자가 다릅니다.

05

관련 개념 더 읽기

저장소만 비교하려면 무엇을 같게 둘까

저장소를 바꾸면서 문서를 다시 쪼개고 임베딩 모델과 k까지 바꾸면 결과가 왜 달라졌는지 알기 어렵습니다. 오늘은 입력과 규칙을 먼저 고정합니다. 단순히 같은 차원의 숫자 세 개라는 사실만으로 같은 임베딩이라고 부르지 않습니다.

두 예제는 목적이 다릅니다. library-lab는 39일의 가상 도서관 원문 3개·청크 5개와 개발 3문항·공개 확인 2문항을 유지합니다. service는 70일의 같은 가상 TXT·owner·문서 UUID·청크·출처로 B1의 실제 연결 코드를 준비합니다. 도서관 문장을 과정 안내나 업로드 문서의 사실로 섞지 않습니다.

E1은 벡터를 해석하는 약속

벡터 [1,0,0]은 그 자체로 “첫 번째 의미가 강하다”는 뜻이 아닙니다. 어떤 모델이 어떤 문서를 어떤 규칙으로 바꾸었는지 알아야 해석할 수 있습니다. E1에는 provider, model, dimension, normalization, distance와 문서·청크 정책 해시가 들어갑니다.

제공 키워드 벡터는 단어가 있으면 1, 없으면 0인 교육용 값입니다. semantic_embedding=false이므로 문장의 의미를 이해한 모델이라고 쓰지 않습니다. 실제 임베딩으로 교체한다면 모델·차원·정규화와 문서/정책 계약을 함께 새로 기록해야 합니다.

거리 숫자와 순위를 구분하기

[1,0,0]과 [0,1,0]의 각 좌표 차이는 1,-1,0입니다. 차이의 제곱 합은 2이고 그 제곱근인 L2 거리는 √2입니다. 같은 두 벡터라도 squared_l2와 l2의 숫자는 다릅니다. 양수 거리에서는 제곱근을 취해도 크기 순서는 유지됩니다.

기준선과 Chroma의 l2 설정은 제곱 L2를 사용하고 pgvector의 <->는 L2 거리를 돌려줍니다. 원시 거리를 저장한 뒤 공통 척도로 바꾸어 비교합니다. 동률이면 청크 ID 오름차순을 사용합니다. 실제 단정도 벡터 저장·반올림 오차는 별도로 확인하며, 수치 허용 오차를 학생 합격 점수로 쓰지 않습니다.

서비스 UUID와 원문·청크를 연결하기

도서관 lab의 UUID는 실험을 위해 만든 가상 식별자입니다. 기존 B1 문서 UUID를 대체하지 않습니다. 서비스에서는 70일에 만든 문서 UUID와 owner를 그대로 사용하고 원문 ID, 청크 ID, 원문 바이트/내보내기 해시, 청크 해시를 이어받습니다.

document_material은 현재 DB 본문을 같은 70 파서로 읽고 저장된 매핑을 대조합니다. text만 같아도 source나 page가 다르면 다른 출처 계약입니다. 현재 DB 본문을 내보낸 경우의 db-export 원문 ID와 과거 업로드 원본을 구분합니다. TXT 페이지 1은 논리 페이지이며 실제 PDF 페이지 추정이 아닙니다.

같은 B1에 벡터 표만 추가하기

PostgreSQL 이미지를 pgvector가 포함된 것으로 사용했다는 사실과 데이터베이스에서 vector 확장을 활성화했다는 사실은 다릅니다. 73의 추가 migration이 확장과 벡터 표를 준비합니다. vector(3)은 이번 제공 모델의 차원이고 모든 실제 임베딩의 차원이라는 뜻이 아닙니다.

course_vector_indexes는 owner/document별 E1 전체와 해시를 저장합니다. course_chunk_vectors는 같은 owner/document/chunk와 계약 해시를 외래키로 연결합니다. 70의 source map 관계에 필요한 UNIQUE만 추가하고 기존 문서·대화·A1·기억 행을 지우지 않습니다. 기본에는 HNSW/IVFFlat 근사 인덱스를 추가하지 않습니다.

DOCUMENT_UUID는 실제 소유 문서의 관측 값으로 바꿉니다. CLI의 owner는 신뢰한 운영자가 지정하는 값이며 HTTP 인증을 구현한 것이 아닙니다. 업로드→명시 인덱스 준비→질문 순서이고, 인덱스가 없으면 409를 반환합니다.

값 바인딩과 소유 필터를 검색 앞에 놓기

SQL의 %s 자리에는 값 튜플을 별도로 전달합니다. 질문·owner·UUID·벡터를 SQL 문자열에 이어 붙이지 않습니다. 테이블과 열 이름은 코드의 고정 식별자이며 사용자 입력으로 고르지 않습니다.

owner와 허용 문서 조건을 먼저 적용한 집합에서 거리를 정렬하고 LIMIT합니다. 전체 검색 결과에서 타인의 owner를 나중에 숨기는 방식으로 바꾸면 안 됩니다. 저장된 E1이 예상과 같은지도 먼저 확인합니다. 계약이 틀린 인덱스를 해시 필터로 제외해 []로 만드는 것만으로는 오류를 제대로 전달하지 못합니다.

examples/library-lab에서 test_vector_lab과 record_comparison.py를 실행합니다. 이 폴더는 서비스 예제와 별도 Python 프로세스로 사용합니다. 기존 청크 5개·후보 k2·최종 k1을 유지하고 L2 재계산의 R1/A1이 39일 기준선과 같은지 봅니다. 이는 실제 Chroma/pgvector 실행이 아닙니다.

Q1의 expected_document_ids는 원문 ID입니다. 검색된 청크를 source-map으로 원문에 연결한 뒤 Recall을 계산합니다. 정답 집합이 비면 Recall은 NA/empty_gold이고, 검색 오류의 NA는 retrieval_error 등 다른 이유입니다. 공개 확인 holdout-* 문항은 이미 공개되어 있어 비공개 평가라고 부르지 않습니다.

반납함 문항은 최종 청크가 “무인 반납함은 24시간 이용할”에서 끝나는 기존 불완전성을 보존합니다. 원문 ID가 맞고 Recall이 1이어도 문장이 완전하다는 뜻이 아닙니다. 저장소를 바꾸었다고 이 문제를 해결했다고 쓰지 않습니다.

같은 70일 TXT를 S1 서비스에 연결하기

service/input70은 검수된 70일 전체 앱의 바이트 사본입니다. app_pgvector.py는 그 앱에서 검색 factory와 새 벡터 오류 상태만 연결한 파생 코드입니다. 공개 사용자 대역, H1 요청/응답, 문서 상태, A1, 이력, 스트림의 순서를 유지합니다.

서비스 E1은 70일의 같은 두 문단을 사용합니다. 제공 “과제”/k2에서 70일 원래 A1과 73일 A1을 같은 문서 UUID·청크·source/page로 대조했습니다. 새 E1의 Python 계산과 SQL 호출 대역은 8개 조건에서 같습니다. 70의 문자열 포함 검색과 모든 질문에서 같다는 주장이나 품질 개선 주장은 아닙니다.

S1은 사용자 지정 함수의 외부 호출 수를 null로 남깁니다. 실제 작성한 어댑터가 로컬이라는 이유로 S1 metadata를 0으로 덮어쓰지 않습니다. 생성기는 70일과 같은 제공 근거 문맥 반환 함수이고 외부 모델은 사용하지 않습니다.

인덱스 갱신·검색·저장 실패를 따로 관찰하기

index_document는 해당 owner/document의 벡터와 E1만 같은 트랜잭션에서 재준비합니다. 벡터 INSERT가 실패하면 이전 인덱스가 rollback으로 남아야 합니다. 문서·대화·이전 A1을 지우는 재설정과 다릅니다.

검색 결과의 id/text/source/page와 거리·순서도 검사합니다. 잘못된 원문이나 벡터를 저장소가 반환하면 정상 답으로 진행하지 않습니다. 서비스는 이미 생성한 답의 저장 실패에서 A1을 보존하고 persistence.failed_or_unknown을 남깁니다. commit 효과가 미확정일 수 있으므로 자동 재시도하지 않습니다.

실제 저장소 검사 코드는 준비 상태로 제공하기

check_stores_prepared.py는 도서관의 같은 5개 청크를 무작위 임시 schema와 선택 Chroma 메모리 collection에 넣는 실제 실행용 코드입니다. service/check_postgres_prepared.py는 같은 70일/B1→73의 S1·재조회·인덱스 rollback을 확인하는 코드입니다. 두 파일 모두 현재 실행하지 않았습니다.

Chroma 비교는 query_embeddings로 제공 벡터를 직접 넘기고 embedding_function=None으로 별도 모델 호출을 하지 않습니다. 작은 진단 자료 전체를 요청한 뒤 동률 ID를 정리합니다. Chroma의 근사 인덱스와 pgvector 기본 정확검색의 차이를 숨기거나 이 작은 자료로 속도·비용을 일반화하지 않습니다.

같은 DB·볼륨과 미확인 증거를 74일에 넘기기

deploy/input72는 같은 course-b1·course-data·PG*를 유지하는 72일 정본 사본입니다. deploy/compose.vector.yaml은 73일 이미지의 파생 override이며 기존 DB 서비스를 바꾸지 않습니다. 실제 Docker context·project label·volume 식별을 확인하기 전에는 같은 이름만으로 기존 데이터에 연결됐다고 판단하지 않습니다.

API 재시작, DB 재시작/같은 볼륨 재연결, 별도 빈 DB 백업 복구는 다른 검사입니다. 실제 owner/document/conversation/source map/E1/A1과 행 수를 전후 대조해야 합니다. 현재 새 연결 검사 준비는 서버 재시작 성공 기록이 아닙니다.
