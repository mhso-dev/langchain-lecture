## 개정 근거와 재확인

* **25~32장.** 메모나 검토표를 “보관하세요”라고 적은 기존 안내에 실제 쓰기·읽기 셀을 붙였다. 25장은 학생이 만든 `my_case`를 먼저 선택하고 저장한 원문과 초안을 다시 읽어 비교한다. 27장의 순차 검토와 28장의 비동기 검토는 규정과 초안 사이의 구분자까지 같다. 30장은 이전 워커의 부분 답으로 취합한 초안을 검토하고, 31장은 이전 문의를 보존한 채 반복을 시작한다. 32장은 앞 장의 문의를 통합 함수에 넣고 호출 단계를 기록한다. API가 없는 학생은 `cum-readback`에서 제공 예시와 자기 파일 중 어느 쪽을 읽었는지 확인할 수 있다.
* **33~39장.** 작은 예, 노드 등록 함수와 실제 분기 이름을 대조했다. 34장의 first와 revise, 35장의 respond, 36장의 search와 answer, 38장의 별도 연습 search 노드가 코드 곁 그림에 들어간다. 36장은 24장 개인 파일과 복귀 자료를 같은 함수로 읽는다. 37장 독립 검수에서 PDF 줄바꿈 때문에 “파일이”에서 인용이 끊기는 오류가 발견됐다. 원문 공백을 정리한 뒤 45분 간격과 계속 녹음된다는 두 문장이 같은 후보에 있는지 검사하도록 고쳤다. 실제 파일을 38~41장까지 넘겨 두 사실과 인용이 보존됨을 재확인했다. 39장 화면에는 직전 실습의 실행 경로와 새 요청을 함께 볼 수 있다.
* **40~42장.** 개발 사례에 관찰값과 참고 답을 분리하고 41장의 선택을 42장이 읽는다. 개발용 질문을 최종 확인 자료로 섞지 않는다. 팀에 넘길 기록은 실험을 수행하고 실제 확인 실험 ID와 사람의 근거를 입력했을 때만 채택 또는 보류를 적는다. 해당 근거가 없으면 `검토 대기`가 남는다.

## 재현 및 검수 범위

교육 검수는 별도 읽기 전용 검수자가 원본과 개정 셀을 대조했다. 33~42장은 새 커널에서 직접 재실행했고 PDF 인용 수정 뒤 두 문장이 함께 넘어가는 것과 39→40→42 파일을 다시 확인했다. 작성에는 12장의 문제 아래 풀이, 14장의 작은 호출 예, 33장의 상태 변화 설명을 적용했다. 원자료 06_LLM의 SDK 체이닝·라우팅·비동기·작업 분할·개선자 예제를 읽어 함수 인자 및 중간 출력의 깊이를 비교했다.

검증 환경은 macOS 27.0.1 arm64, Python 3.12.15, ipykernel 7.4.0, IPython 9.17.1, LangGraph 1.2.16, langchain-core 1.8.5, LangSmith 0.16.2, Streamlit 1.67.0, OpenAI Python 3.60.0, pypdf 7.1.1이었다. 각 노트북마다 새 프로세스의 `InProcessKernelManager.start_kernel()`을 열어 학생 셀을 순서대로 실행했다. 같은 압축 해제 루트를 다음 커널이 사용했다. 두 번째 루트에서는 새 커널에서 예제와 학생 셀을 실행하고, 바로 아래 접힌 풀이 중 실행 코드가 있는 블록도 순서대로 실행했다. 본문에 쓰인 설명형 판정 예시는 실행 코드가 아니다.

32장의 파일 생성 셀로 쓴 workflow_app.py를 Streamlit AppTest로 열었다. 채팅 입력·체크박스·버튼이 각 1개였고, 체크박스를 바꿔도 메시지는 0개였다. 39장의 앱도 같은 방식으로 열어 38장의 경로를 펼치는 항목을 확인했다. B / 1.0으로 판본만 바꿨을 때 새 답변은 생기지 않았다. 두 화면에서 실제 SDK 답변을 얻었다는 뜻은 아니다.

한국어 검수는 개정한 학생용 산문에서 용어, 원문을 읽는 순서, 수치, 판본, 조건과 확인 방법을 다시 대조했다. 36장의 절대적 서술을 자료 분할에 따라 검색 대상이 달라진다는 설명으로 고쳤다. 37장은 두 사실이 같은 후보에 있어야 인용할 수 있음을 한 문단으로 정리했다. 각 장에 대해 전후 문서의 구조·수치·인용 지표를 확인했다. 짧은 기술 설명에서 수정량이 적거나 문장 수가 적어 자동 게이트는 WARN/INCONCLUSIVE였고, 정독과 직접 대조로 판정했다. 외부 맞춤법 서비스는 문서 공개 여부가 확정되지 않아 사용하지 않았다.

## 확인 필요 항목

25~32장의 실제 모델 첫 요청은 OpenAI SDK에서 APIConnectionError(ConnectError)로 끝났다. 네트워크에 의존하는 출력과 그 출력이 필요한 후속 셀은 미확인이다. 33~42장의 비실서비스 경로는 실행했으며, 실제 Chroma 재색인·모델 호출·LangSmith 원격 평가·비용·추적 ID·모델 응답은 이번 전체 실행 범위 밖이다. 이전에 제공된 실행 기록과 이번 로컬 경로 실험은 본문에서 출처를 구분한다. Windows/WSL, 학생 계정 및 수업 시간은 미확인이다. Chrome 새 프로세스는 현재 검증 환경에서 창을 열기 전에 종료됐다. 전체 빌드에서 확인한 화면·링크·다운로드 범위는 통합 검수 기록을 따른다.
