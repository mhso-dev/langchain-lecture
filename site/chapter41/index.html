02

화면 상태와 그래프 저장 상태

화면에 보이는 현재 답변과 그래프에 쌓이는 대화 기록은 수명이 다릅니다. 어떤 사용자와 스레드의 값을 갱신하는지 확인합니다.

실제 Graph에 InMemorySaver를 붙여 대화별로 고정 질문을 기록합니다. 화면 담당 코드는 현재 대화의 thread_id를 전달합니다. 여기서는 자료 등록 과정이 끝난 뒤의 가상 도서관 고정 자료를 쓰며 새 문서 업로드나 재색인은 실행하지 않습니다.

질문 이력에는 대출 기간과 주차 요금이 둘 다 남았는데 현재 출처 목록은 비었습니다. 화면이 되살려야 할 두 상태의 수명이 다르기 때문입니다. 대화 목록은 이어 가되, 출처 패널은 방금 처리한 질문의 결과로 교체하세요.

이번 질문의 출처와 누적 질문

04

Streamlit 폼에서 그래프 호출

제공 앱은 같은 검색 함수와 체크포인터를 씁니다. 앞서 본 처리 중 UI에서 결정하는 것은 대화 ID와 현재 표시할 결과입니다. 새 대화 버튼은 새 ID를 만듭니다. 수업용 예제에는 로그인·운영 저장소가 없습니다.

셀 04 · 폼 상태와 대화 ID 연결

st.session_state.thread를 설정하는 줄과 engine.invoke에 같은 ID를 건네는 줄을 찾아보세요.

노트북의 앱은 cache_resource로 엔진을 재사용합니다. A에서 B로 전환하면 엔진이 쓰는 저장소는 남지만 현재 화면은 B의 대화 ID와 출처를 기준으로 다시 그립니다. 뒤의 참고 앱은 session_state에 엔진을 두는 별도 구현입니다. 먼저 cache_resource로 그래프를 준비하는 줄과, 제출 뒤 현재 출처를 갱신하는 줄을 찾으세요.

UI 세션 상태와 그래프 상태

session_state는 화면이 현재 선택한 대화와 결과를 보관하는 데 사용합니다. Graph의 체크포인터는 Graph 실행 상태를 thread_id별로 보관합니다. 화면의 history에 질문이 남아 있다는 사실만으로 Graph가 그 내용을 추론 입력으로 사용한다고 말할 수는 없습니다.

같은 session_state에 engine을 한 번 만들어 보관하도록 앱을 작성했습니다. 일반 재실행마다 새 GraphSession을 만들면 이전 대화의 메모리 저장소를 잃게 됩니다. 실제 브라우저에서의 재실행·세션 분리는 별도 UI 검사 대상이며, 로컬 dict 검사를 그 증거로 바꾸지 않습니다.
