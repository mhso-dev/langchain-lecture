데이터·평가 준비 · 방향과 예시

가상 운영 안내 한 건에는 평일 수업, 과제 제출, 업로드 오류를 설명하는 세 문단이 있습니다. 팀은 원문을 먼저 눈으로 읽고 질문별 기대 문단을 붙입니다. 검색 결과를 본 뒤 정답을 바꾸면 어떤 문제가 고쳐졌는지 알기 어렵습니다.

선택형 프로젝트 안내프로젝트 참고 안내 · 시간 배분 자율앞선 수업의 필요한 개념만 선택해 활용합니다. 제공 구현과 자신의 프로젝트는 구분합니다.
01

수업 노트북

↓44장 수업 노트북 (.ipynb)Jupyter에서 열고 Python 커널을 선택한 뒤 위에서부터 실행하세요.↗

실행을 확인한 커널은 Python 3.12.15입니다.

02

문단에 기대 질문 연결하기

Q01 “과제는 어디에 내나요?”는 p2에서 답할 수 있습니다. “과제함”만 들어 있으면 충분한지, 제출 뒤 파일 이름과 등록 시간을 확인하라는 점까지 필요한지 먼저 합의합니다. Q03의 업로드 오류는 p3에 연결합니다. 문단 번호와 실제 쪽수는 구별하세요. 44장 원자료에는 쪽수 필드가 없습니다.

셀 01 · Q01의 정답 근거 찾아 읽기

질문 자료에 적힌 첫 기대 ID로 원문을 고릅니다.

Q01에서 ‘어디에’라는 질문의 필수 답은 과제함입니다. ‘제출 뒤 파일 이름과 등록 시간을 확인하세요’는 추가 안내로 기록하세요. 팀에서 절차 전체를 필수로 채점하려면 질문도 ‘어디에 내고 무엇을 확인하나요?’로 바꿉니다.

실행 결과

과제는 학습 관리 페이지의 과제함에 제출합니다. 제출 뒤 파일 이름과 등록 시간을 확인합니다.

제출 위치와 제출 후 확인 절차가 한 문단에 함께 나옵니다. 검색기가 p3의 “제출 오류”를 골랐다면 단어는 비슷해도 질문의 답은 빠집니다.

03

주말 수업 질문은 어떻게 기록할까요?

Q04는 주말 수업 시작 시각을 묻습니다. p1에 적힌 오전 9시는 평일에만 적용되므로 답변 불가가 이 질문의 기대 결과입니다. 팀의 데이터 표에도 “평일”처럼 답의 적용 범위를 바꾸는 낱말을 남기세요.

셀 02 · Q04에 시간 답변이 없는 이유 읽기

제공 평가 문항의 기대 조건과 p1 원문을 차례로 읽습니다.

실행 결과

['주말 일정은 문서로 확인 불가']
정규 수업은 평일 오전 9시에 시작합니다. 일정 변경은 과정 게시판에서 확인합니다.

평일 시작 시각에서 주말 시각을 추측하면 답을 만들어 낸 셈입니다. 자체 문서로 바꿀 때는 원문 버전과 문항 ID를 남겨 다음 실험도 같은 사례로 재현하세요.
