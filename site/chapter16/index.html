Function Calling의 실행과 결과 반환

15장에서 받은 주말 운영 시간 요청에 실제 조회 결과를 붙입니다. 하나의 호출 요청, 프로그램이 실행한 함수, 모델에 돌려줄 결과를 같은 call_id로 따라가 봅시다.

입문교육일 016 · 8H15장 함수 명세·호출 요청·JSON
01

실습 노트북과 실행 환경

↓16장 수업 노트북 (.ipynb)Jupyter에서 열고 Python 커널을 선택한 뒤 위에서부터 실행하세요.↗

실행을 확인한 커널은 Python 3.12.15입니다.

02

도구 이름과 인자를 함수 호출로 변환

도구 실행을 맡은 프로그램은 인자를 검사하고 함수를 호출한 뒤 결과에 원래 호출 ID를 붙입니다. 모델은 이 ID로 요청과 결과를 짝짓습니다.

명세만 본 모델은 운영 시간을 알 수 없습니다. 읽기 전용 조회 함수 안의 표에서 시간을 꺼내면 비로소 답에 쓸 값이 생깁니다.

호출 요청을 실행 함수로 넘기기

이 장의 call에는 get_library_hours, 문자열 인자, call_1이 있습니다. 이름과 인자를 검사해 주말 시간표를 조회하고, 결과에는 바로 이 call_1을 붙여 원래 요청과 연결합니다.

셀 01 · get_library_hours()의 반환값

이번 셀에서는 모델 없이 파이썬 함수를 직접 부릅니다.

실행 결과

10:00~16:00

10:00~16:00은 주말 표에서 꺼낸 값입니다. 이 함수는 실제 도서관에 접속하지 않습니다. 허용되지 않은 인자가 들어오는지는 함수를 부르기 전에 검사합니다.

읽기 전용 함수 연결

함수는 day를 받아 정해진 시간표에서 값을 읽습니다. 데이터는 가상의 수업 자료입니다. 이 함수를 실행했다는 사실과 실제 기관 운영 시간이 맞는다는 주장은 구분해야 합니다.

셀 02 · execute_call()과 결과 직렬화

제공 함수는 요청의 이름과 인자를 검사합니다. 성공했을 때 어떤 값이 output 안에 담기는지 읽으세요.

이번 노트북은 주말 조회 요청을 새로 만들어 call_1이라는 ID를 붙입니다. 15장의 예제 ID는 call_demo_1이었습니다. 이제부터 이 요청에 답하는 결과는 call_1을 그대로 사용해야 합니다.

실행 결과

10:00~16:00

같은 10:00~16:00이 나오지만 이번 값은 reply의 output에 담긴 JSON 문자열에서 읽었습니다. 모델에 보낼 항목의 type은 function_call_output입니다.

ID와 인자를 거부하는 방법의 차이

execute_call은 호출 ID가 비어 있으면 ValueError를 일으킵니다. ID가 있어 결과를 연결할 수 있지만 이름이나 day가 잘못됐다면, 호출 ID가 포함된 function_call_output에 invalid_tool_request를 담아 반환합니다.

03

function_call_output과 call_id 대응

결과를 돌려주는 쪽은 임의의 새 ID를 붙이지 않습니다. 모델이 보낸 호출 항목의 call_id를 그대로 써야 요청과 결과가 한 쌍이 됩니다.

과제 03 · call_id 일치 여부

원본 call과 결과 reply의 ID가 같은지 확인하고, 같으면 그 ID를 출력하세요.

풀이와 실행 결과 보기

실행 결과

call_1

call_1입니다. 모델에게 다음 답변을 요청할 때는 사용자 질문과 호출 항목 다음에 이 결과를 넣습니다.

function_call_output의 두 층

reply의 call_id는 바깥 딕셔너리에서 바로 읽습니다. 반면 output에는 성공 여부와 조회 데이터가 JSON 문자열로 들어 있습니다. json.loads(reply['output'])을 거치면 data에서 hours를 꺼낼 수 있습니다.

셀 04 · 허용 목록 밖 인자 거부

이번 요청의 ID는 유효하나 day가 명세의 두 선택지 밖에 있습니다.

실행 결과

{'ok': False, 'error': 'invalid_tool_request'}

ok가 False이고 error가 invalid_tool_request입니다. 허용되지 않은 요일로 얻은 시간을 사용자에게 보여 주는 일을 막았습니다.

오류 결과의 전달

실패 사례
입력예상 처리
등록하지 않은 함수 이름오류 결과, 함수 실행 없음
day=holiday오류 결과
JSON으로 읽히지 않는 인자오류 결과
불필요한 extra 필드오류 결과

완료되지 않은 최종 응답성공 반환 대신 예외
04

대화 기록에 호출과 결과 추가

도구 호출을 제안한 응답과 함수 실행 결과를 대화 끝에 차례로 넣습니다. 모델에 다시 보내기 직전에는 결과가 어느 항목인지, 조회 실패를 개관 시간으로 오해하지 않았는지 살펴보세요.

질문 뒤에 호출 항목과 결과 붙이기

history에는 사용자 질문, 모델의 호출 요청, 프로그램이 만든 결과가 차례대로 들어갑니다. 마지막 항목에서 function_call_output을 읽고 같은 call_id의 이전 요청을 찾아 연결해 보세요.

셀 05 · append()로 호출 이력 구성

대화 내역을 만든 뒤 마지막 항목의 유형을 읽습니다.

실행 결과

function_call_output

function_call_output이 나옵니다. 모델의 최종 메시지는 아직 없습니다. 다음 과제에서는 조회 값으로 안내 문장을 직접 만듭니다.

도구 왕복의 모델·프로그램 역할

모델이 get_library_hours와 day=weekend를 요청하면 Python 코드가 이름과 인자를 검사합니다. 조건에 맞으면 Python 함수가 실제로 실행되고 결과를 JSON 문자열로 바꿉니다. 이후 모델이 그 결과를 받아 답변을 작성합니다.

여기서 실제로 실행되는 함수는 교육용 정적 시간표를 반환합니다. 실제 도서관 서버나 예약 시스템에 접속하지 않습니다. 기본 모델 응답은 모의 자료지만 도구 함수 실행과 메시지 연결 코드는 실제로 실행합니다.

실행하기 전에 걸러지는 요청

함수 호출 전에 이름과 요일을 확인합니다. 허용된 요청만 3단계로 계속합니다.

파이썬 함수의 실제 반환값 확인
