06

관련 개념 더 읽기

어느 단계가 막혔는지 구분하기

RAG가 틀린 답을 만들면 모델만 바꾸기 전에 문서·청크·검색·문맥·생성·출처를 나누어 확인합니다. 원문 숫자가 잘못 추출되었다면 검색과 모델을 바꿔도 같은 잘못된 근거가 들어갈 수 있습니다.

review-record.md에 혼자 설명 가능한 단계와 도움이 필요한 단계를 표시합니다. 오늘은 새 기술을 추가하지 않고 같은 가상 도서관 문서를 사용합니다.

보충 경로
경로활동완료 증거
문서·청크20~21장 원문 위치와 조각 비교출처·페이지·범위 일치
검색22~23장 벡터·top-k·필터 비교질문과 검색 id 기록
연결19·24장 LCEL 입력·출처 검사질문·문맥·답변·출처 설명

2시간 보충 구간에서는 가장 필요한 경로 하나를 선택합니다. 계정이나 패키지가 준비되지 않은 경우 계약 모의 실행으로 확인할 수 있는 부분을 진행하고 실제 검색·생성은 미실행으로 남깁니다.

진단 0.5H 중 15분은 24장의 answer-cases.json을 읽습니다. 대출 질문에서 documents는 두 후보인데 sources는 한 객체인 이유와, 주차 질문에서 generation_calls가 0인 이유를 설명하세요. 실제 학생 진단 전에는 특정 보충 경로가 필요하다고 미리 단정하지 않습니다.

공통 자료와 질문을 고정하기

data/documents.json에는 도서 대출 14일, 월요일 휴관, 무인 반납함 24시간이라는 세 가상 규칙이 있습니다. data/questions.json은 공개 개발 질문 3개와 공개 확인 질문 2개로 나뉩니다. 주차 요금과 카페 메뉴는 이 자료에 근거가 없습니다. 원문이나 기대 근거를 과제 답안에 맞춰 바꾸지 않습니다.

공통 버전은 course-v1-rag-1.0.0입니다. Q1의 expected_document_ids는 원문 ID이며 검색 청크의 ID와는 역할이 다릅니다. data/source-map.json의 document_id로 연결합니다. 현재는 한 페이지가 한 청크여서 ID가 같고, 더 잘게 나누면 달라질 수 있습니다.

조건을 비교할 때 자료와 질문을 동시에 바꾸지 않습니다. 검색 설정이나 문맥 함수 가운데 하나만 바꾸고 전후 결과를 같은 질문으로 기록하세요. 이미 공개된 확인 질문과 고정 모델을 사용한 결과를 일반 성능 점수로 표현하지 않습니다.

문맥 생성 함수 직접 구현하기

prepare_inputs는 질문과 문서 목록을 받아 LCEL 입력을 만듭니다. 질문 양끝 공백을 제거하고, 비어 있거나 문자열이 아니면 ValueError로 멈춥니다. 문서 목록도 검사한 뒤 빈 목록이면 None을 반환합니다. 정상 결과에는 question과 context 두 키만 둡니다.

문서의 id·text·source는 비어 있지 않은 문자열, page는 1 이상의 정수여야 합니다. bool 페이지·중복 ID·대괄호가 섞인 ID는 거부합니다. team-01:p-01처럼 콜론이 들어간 ID는 허용합니다. 이런 세부 검사는 23장의 제공 validate_request/validate_documents를 재사용할 수 있습니다.

문맥은 format_context와 같은 순서와 줄바꿈을 사용합니다. 임의로 출처를 채우거나 문서 본문을 줄여 다른 근거를 만들지 않습니다. 오늘의 구현 과제는 검증·빈 근거·정상 입력의 흐름을 연결하는 것입니다.

review_runner.py의 run_review는 R1 검색을 한 번 실행한 뒤 학생의 prepare_inputs를 호출합니다. 빈 문서라면 None인지, 정상 문서라면 question/context가 원문을 보존하는지 확인합니다. 다음으로 같은 문서와 생성 함수를 공통 A1에 넘깁니다.

generate는 학생 함수가 만든 inputs를 LCEL 체인에 전달합니다. 공통 A1은 빈 근거일 때 generate를 호출하지 않고, 생성했다면 인용 검사를 수행합니다. 이렇게 학생 함수의 출력이 실제 호출 지점에 들어가는지 확인하며 24장의 인용·오류 정책을 유지합니다.

모의 연결과 실제 연결을 구분하기

함께 제공한 review-cases.json은 강사 참조 함수로 실행한 예시이며 implementation_kind가 instructor_reference_not_student_submission입니다. 학생은 자신의 함수를 실행한 새 기록과 비교합니다. 이 예시 기록이나 자동검사를 동료가 재현한 증거로 옮겨 쓰지 않습니다.

개인 설명과 다음 학습 준비

다음 26장에서는 함수가 값을 읽고 바꾸는 과정을 question·documents·answer 상태로 나타냅니다. 입문 예제는 documents를 문자열 목록으로 줄여 상태 갱신에 집중하고, 30장에서 출처 객체 목록으로 돌아오는 이유를 설명합니다. 지금의 원문과 출처를 지우거나 모든 계약이 곧바로 같다고 가정하는 과제가 아닙니다.
