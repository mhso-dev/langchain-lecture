02

문서 ID와 쪽 번호로 근거 식별

RAG는 질문과 관련된 자료를 찾아 답변의 근거로 건넵니다. 문서 본문과 원래 위치를 함께 보관하면 답변을 읽은 뒤 근거를 되찾을 수 있습니다.

RAG는 질문을 받았을 때 관련 자료를 찾아 그 내용을 답변 입력에 넣는 방식입니다. 원문을 모아 이름과 위치를 붙이는 일은 미리 해 두고, 어느 자료를 가져올지는 질문을 받은 뒤 결정합니다.

문서 로딩의 선행 입력

이번 장의 documents[0]["text"]에서 대출 기간을 읽으세요. 5장에서 저장한 학습 기록에는 title과 minutes가 있고, 이 도서관 안내에는 text와 page가 있습니다.

진입 확인은 전반 대조 시간 중 15분을 사용합니다. 이전 파일을 찾지 못했다면 이 장의 documents.json으로 시작하세요. 공통 가상 원문 3개는 그대로 두고 개인 확장 자료는 별도 파일에 저장합니다.

RAG의 검색 근거

RAG는 질문과 관련된 외부 문서를 찾아 생성 모델의 입력에 넣는 방식입니다. 모델이 가진 일반 지식에만 기대는 대신 이번 질문에 사용할 자료를 명시적으로 제공합니다. 그렇다고 검색한 문서가 항상 적절하거나 생성 답변이 항상 맞는 것은 아닙니다.

가상 도서관의 대출 규정은 수업 자료에 정해져 있습니다. 실제 도서관의 일반적인 규정을 모델이 알고 있더라도 이 서비스는 제공한 가상 자료에 근거해 답해야 합니다.

가상 문서의 출처 구조

이 세 문서는 이후 LCEL·Graph·검색 도구 실습에서 공통으로 사용합니다. id는 문서 식별자, text는 본문, source는 출처 이름, page는 원문 위치를 뜻합니다. 여기의 page 1~3은 수업용 문서 페이지 번호이며 실제 기관 문서가 아닙니다.

주차 요금은 자료에 없습니다. 모델이 그럴듯한 요금을 알고 있어도 근거 문서에서 확인할 수 없다고 답하는 것이 이번 서비스의 요구입니다.

평가 질문과 기대 문서 ID

question_id는 질문의 이름이고 expected_document_ids는 답을 확인할 원문 ID 목록입니다. 답변 가능 여부는 answerable에 true 또는 false로 적습니다. 근거가 없는 질문은 기대 원문 목록이 비어 있어야 합니다. 정답 문장의 말투보다 어떤 자료로 확인할 수 있는지를 먼저 정합니다.

development의 3문항으로 코드와 기준을 설명하고 holdout의 2문항은 설명 후 같은 규칙이 적용되는지 확인합니다. 공개된 교육용 문항이므로 비공개 시험이나 실제 사용자 성능을 뜻하지 않습니다. 확인 문항을 보며 튜닝했다면 이후에는 새 확인 문항이 필요합니다. 35장에서는 이 구분을 평가 절차로 확장합니다.

텍스트 로딩과 메타데이터

Path.read_text는 파일을 글자로 읽습니다. UTF-8을 명시해 인코딩을 분명히 하고 비어 있는 파일은 오류로 알립니다. 일반 텍스트 파일에는 PDF처럼 페이지가 없으므로 page=None으로 표시합니다.

줄바꿈과 문단은 원문의 구조를 나타낼 수 있습니다. 로딩 단계에서 모든 공백을 지워 붙이면 뒤에서 문장 경계나 표를 해석하기 어려워질 수 있습니다. 본문과 정리 규칙을 함께 기록하세요.

PDF 본문과 텍스트 추출 결과

PDF 페이지 번호는 enumerate(...,1)로 1부터 붙입니다. 추출 결과가 비면 needs_review=True로 표시합니다. 이미지로만 된 스캔 PDF는 텍스트가 거의 없을 수 있고, pypdf의 텍스트 추출은 OCR을 대신하지 않습니다.

첨부한 library-sample.pdf는 같은 가상 규칙을 영어로 적은 3페이지짜리 텍스트 PDF입니다. 한글 공통 문서와 영어 PDF를 같은 원문 파일로 혼동하지 마세요. PDF는 추출·페이지 보존 동작을 확인하는 별도 입력입니다.

문서 사용 범위와 최신성

문서를 가지고 있다는 사실만으로 수업이나 서비스에 복제·업로드할 수 있는 것은 아닙니다. 문서의 사용 조건과 공개 범위를 확인하고, 개인정보나 비밀값이 포함되지 않았는지 검사합니다. 이번 예제는 직접 만든 가상 자료만 제공합니다.

자료가 수정되면 이전 인덱스와 새 문서를 섞지 않도록 버전이나 수집일을 기록합니다. 같은 id의 내용이 바뀌었는지 추적할 수 있어야 답변 근거를 다시 확인할 수 있습니다.
