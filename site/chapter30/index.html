02

retrieve()의 문서와 출처 반환

검색 노드는 질문에서 관련 문서를 찾고, 답변 노드는 그 문서를 읽습니다. 두 노드가 공유할 상태에 본문과 출처를 함께 담습니다.

노트북의 자료는 앞서 사용한 가상 도서관 안내 세 쪽입니다. 읽는 법에 집중하려고 로컬 검색 함수는 세 낱말의 유무를 거리로 바꾸며 k개를 고릅니다. Chroma 서버나 외부 임베딩을 호출하는 셀은 없습니다.

05

LangGraph의 검색 노드와 답변 노드 심화 읽기

검색 함수의 반환 계약

R1은 retrieve(question, k=2)가 id·text·source·page를 가진 문서 객체 목록을 반환하는 규칙입니다. 공백 질문, 양의 정수가 아닌 k, bool인 k는 ValueError입니다. True는 Python에서 정수처럼 취급될 수 있지만 검색 개수를 뜻하는 입력으로 허용하지 않습니다.

출처가 빠진 문서는 정상 빈 검색과 다릅니다. DataContractError로 중단해 원본 데이터와 변환 코드를 확인합니다. 누락된 출처를 “출처 미등록” 같은 문장으로 채우면 어디에서 잘못됐는지 감춰집니다.

검색·답변 노드의 상태 변경 필드

retrieve_node는 R1 함수를 한 번 호출하고 문서를 검증합니다. answer_node는 같은 목록을 A1에 넘깁니다. lambda는 이미 찾은 문서를 반환하므로 여기서 저장소를 다시 조회하지 않습니다. 검색을 두 번 하면 중간에 바뀐 자료나 순서 때문에 답변과 표시 출처가 달라질 수 있습니다.

START에서 answer_node로 바로 가는 연결은 없습니다. 빈 검색에서도 answer_node는 실행되지만, A1은 생성기를 호출하지 않고 no_evidence를 반환합니다. 노드 실행 수와 생성 함수 호출 수는 다른 값입니다. 이 생성 함수는 고정 규칙이므로 generation_calls=1을 외부 모델 호출 1회로 해석하지 않습니다.

Chroma 결과의 형식 변환

expected_embedding은 인덱스 생성과 질문 벡터 생성에 사용한 E1 기록입니다. provider·model·dimension·normalization·distance와 문서/원문/청킹 정책 해시가 일치해야 합니다. 차원만 같다고 다른 모델의 벡터를 섞지 않습니다. 어댑터를 만들 때 이 기록부터 확인하고, 질의할 때 실제 벡터 길이도 검사합니다.

Chroma의 한 질의 결과는 ids[0], documents[0], metadatas[0]에 나뉘어 있습니다. [0]은 첫 질의 묶음입니다. 공통 변환 코드는 세 열의 길이와 출처 필드를 검사한 뒤 문서 객체를 만듭니다. 빈 컬렉션은 []이고 잘못된 열이나 출처는 DataContractError입니다. 통신 예외는 그대로 전달합니다.
