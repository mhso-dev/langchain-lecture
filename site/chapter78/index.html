셀 01 · 입력칸과 준비 중인 버튼 표시

노트북에서 레이블을 눌러 커서가 옮겨지는지 보세요. 정적 시안이라 버튼은 비활성입니다.

오늘 읽고 수정할 화면

브라우저에서 입력칸과 버튼을 본 적이 있어도, 어느 코드가 그 요소를 만드는지 처음에는 찾기 어렵습니다. 오늘은 작은 할 일 화면의 HTML과 CSS를 읽고 문구·목록·간격을 수정합니다. 클릭 뒤 저장되는 동작은 80일에 만듭니다. 오늘의 추가 버튼과 체크박스는 정적 예시임을 드러내기 위해 비활성화했습니다.

68일의 api/http-contract-results.json에서 요청과 응답을, 77일의 cd/rollout-rollback.md에서 실제 앱 버전과 미확인을 찾으세요. 첫 15분은 아래 첫 0.5H에 포함됩니다. 자료가 없다면 실제 API·배포가 확인된 것으로 채우지 않고 역할표의 빈칸부터 읽습니다.

브라우저·API·DB의 역할

브라우저는 HTML을 읽어 화면 구조를 만들고 CSS 규칙으로 표시합니다. 입력칸의 값은 우선 브라우저 안에 있습니다. 서버로 보내려면 뒤에서 배울 이벤트 처리와 HTTP 요청이 필요합니다. DB에 남기려면 서버의 저장 동작까지 연결되어야 합니다. 이 단계를 생략하고 입력칸만 그린 상태를 저장 완료라고 부르면 오류를 찾기 어렵습니다.

79일에는 오늘의 입력·버튼·결과 영역을 별도의 과정 안내 질문 화면에 씁니다. 문서 답변을 받는 H1 API는 할 일을 만드는 API가 아닙니다. 80일에는 다시 할 일 앱의 추가·완료·삭제를 구현하고, 81일에 별도 CRUD API를 연결합니다.

HTML 문서의 바깥 구조

HTML은 내용을 요소로 나누어 표시하는 문서입니다. 태그는 요소의 시작과 끝을 나타냅니다. head에는 문자 인코딩·문서 제목·CSS 연결 같은 정보를, body에는 사용자가 읽을 내용을 둡니다. lang="ko"는 문서 언어를 나타내며 화면을 한국어로 자동 번역하는 명령은 아닙니다.

viewport 선언은 작은 화면에서 페이지 폭을 다루는 데 사용합니다. link의 href는 CSS 파일의 위치입니다. 같은 폴더의 styles.css를 가리키므로 HTML 파일만 다른 곳으로 옮기면 스타일 연결이 끊어질 수 있습니다. 단일 교재 HTML은 교재 스타일을 포함하지만 실습 화면의 HTML/CSS 두 파일은 함께 보관해야 합니다.

태그·속성·중첩을 읽기

h1은 이 화면의 큰 제목이고 section은 관련 내용을 묶는 영역입니다. 속성은 태그 안에서 요소의 이름이나 설정을 적는 부분입니다. id는 문서 안에서 한 요소를 찾는 이름이므로 중복하지 않습니다. class는 같은 스타일을 적용할 여러 요소에 붙일 수 있습니다.

중첩은 요소 안에 다른 요소가 들어가는 관계입니다. 목록 ul 안에 항목 li가 들어가고, 입력 영역 section 안에는 label·input·button이 있습니다. 닫는 태그를 옮기기 전에 어떤 범위를 묶는지 먼저 표시하세요. 문서의 id="task-a"는 화면 요소의 이름이며 뒤에서 사용할 Todo 레코드 id와는 역할이 다릅니다.

입력과 버튼을 연결하는 이름

label은 입력칸이 무엇을 받는지 설명합니다. label의 for와 input의 id를 같은 값으로 맞추면 두 요소의 관계가 분명해집니다. placeholder는 입력 전의 힌트이고 label을 대신하지 않습니다. 버튼에는 type을 적어 의도한 동작을 드러냅니다.

현재 추가 버튼은 disabled입니다. 동작을 아직 만들지 않았다는 뜻입니다. 입력칸에 글자를 적어도 목록이 늘지 않는 것은 이 단계의 정상 범위입니다. maxlength=100은 정적 예제의 입력 표시 제한일 뿐, 80일 T1 제목 규칙을 정한 값은 아닙니다.

목록·완료·오류는 서로 다른 상태

ul은 목록, li는 한 항목입니다. 제공 파일에는 미완료 예시와 완료 예시 두 개가 있습니다. checked는 체크 표시의 초기 상태를 나타내고 disabled는 조작을 막습니다. 체크가 보인다는 사실은 학습자가 실제 작업을 끝냈다는 기록이 아닙니다.

완료 상태를 색만으로 표현하면 색을 구별하기 어려운 사용자가 놓칠 수 있습니다. 예제는 문구에도 완료/미완료를 적었습니다. 오류 안내도 같은 원리입니다. 빈 제목일 때 어떤 문구를 보여 줄지 정하되 지금은 정적 표시라는 점을 기록합니다.

CSS 선택자와 속성값

CSS 규칙은 선택자와 선언으로 읽습니다. .panel은 class="panel"인 요소를 고릅니다. 중괄호 안의 padding은 안쪽 여백, margin은 바깥 간격, border는 테두리입니다. 속성 이름과 값을 콜론으로 나누고 선언 끝에 세미콜론을 적습니다.

여러 규칙이 같은 요소에 적용될 수 있습니다. 처음에는 어느 규칙이 이기는지 외우기보다 제공 선택자 하나의 값만 바꾸고 차이를 확인하세요. 모든 CSS를 한꺼번에 교체하면 원인을 설명하기 어렵습니다.

폭·줄바꿈·초점을 확인할 위치

큰 화면에서 보기 좋던 입력 줄도 작은 폭에서는 넘칠 수 있습니다. max-width는 본문이 지나치게 넓어지지 않게 하고, flex-wrap은 한 줄에 들어가지 않는 요소를 다음 줄로 보낼 수 있게 합니다. 긴 출처나 단어는 overflow-wrap으로 줄바꿈을 허용합니다.

키보드로 이동할 때 현재 선택된 요소를 알아볼 수 있어야 합니다. :focus-visible 규칙은 초점 테두리를 제공합니다. 이 선언이 있다는 이유만으로 모든 키보드 조작과 대비를 검증한 것은 아닙니다. 실제 브라우저에서 이동 순서와 보이는 상태를 따로 확인합니다.

제공 파일을 작은 변경으로 수정하기

원본 파일을 보존하고 작업 사본에서 수정하세요. 먼저 제목/안내, 다음으로 목록 예시, 마지막으로 지정 CSS의 간격이나 폭을 바꿉니다. 한 번 저장할 때마다 변경 이유를 적으면 문제가 생겼을 때 돌아갈 위치를 찾기 쉽습니다.

브라우저에서 바뀌지 않는다면 먼저 저장한 파일이 맞는지, CSS 경로가 같은지, 수정한 선택자가 요소의 class와 일치하는지 확인합니다. 서버를 새로 만들거나 프레임워크를 설치하는 것은 이 문제를 확인하는 첫 단계가 아닙니다.

빈 입력과 실패 화면을 설계하기

좋은 화면은 정상 입력만 설명하지 않습니다. 아직 항목이 없을 때, 제목이 비었을 때, 완료 여부를 구분할 때 무엇을 보여 줄지 정해야 합니다. 오늘은 상태를 표로 만들고 HTML에 예시 문구를 배치합니다. 상태를 자동 전환하는 프로그램은 80일의 작업입니다.

79일에는 다른 종류의 상태가 추가됩니다. 질문을 보내기 전, 응답 대기 중, 답변 완료, 서버 오류입니다. 목록 저장과 답변 수신을 섞지 않고 UI의 입력/버튼/결과 구조만 옮기는 이유를 설명해 보세요.

구조 검사와 화면 확인을 나누기

제공 check_static.py는 Python 표준 라이브러리로 id 중복, label 연결, CSS 파일, 스크립트 부재와 비활성 예시를 확인합니다. 코드를 기계적으로 확인할 수 있는 부분입니다. 실제로 읽기 편한지, 초점이 보이는지, 좁은 화면에서 잘리는지는 이 검사로 알 수 없습니다.
