## 병렬 집필과 합류 시점

첫 묶음은 진단, 문법, 패턴, Git 협업이다. 문법과 패턴은 서로의 노트북을 불러오지 않는다. Git 원고는 공통 파일 `cases.md`의 한 줄로 두 경로를 받아들인다. 학생이 한 트랙과 Git을 수강하는 시간이 56시간이다. 다음 묶음에 쓸 공지·문의·녹음기 설명서와 채점 자료는 코드 없이도 작성하고 원문과 대조할 수 있다.

2부의 실제 호출과 화면을 먼저 검증한 뒤 3·4부 원고를 나눠 쓸 수 있다. 3부는 검색기를, 4부는 주어진 원문을 검토하는 함수를 맡는다. 두 원고를 검토할 때는 동일한 챗봇에서 각 기능을 차례로 실행한다. 5부의 기초 예제는 따로 준비할 수 있다. 검색 노드 집필은 3부의 문서 ID·쪽수·판본·검색 결과 형식이 정해진 뒤 시작한다. 6부의 평가 질문은 미리 작성하되, 실험 결과와 채택 결정은 5부 워크플로의 실측값으로 쓴다.

다음 집필자는 노트북마다 새로 나오는 이름을 표시한다. 첫 사용 전에 뜻·입력·출력을 설명했는지, 앞에서 배웠다면 실제로 열 수 있는 절이 있는지 확인한다. 특히 SDK의 인증·메시지 역할, LCEL의 입력 사전, 그래프의 상태와 누적, LangSmith의 실행 ID·실험 단위를 앞 예제 없이 과제에서 요구하지 않는다. 각 묶음은 시작본과 풀이를 새 커널에서 각각 실행하고, 웹 본문과 노트북·원문·정답을 대조한 뒤 연결한다.
