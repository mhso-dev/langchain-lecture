02

도구 결과를 대화 기록에 누적

도구 호출 루프는 모델이 다음 도구를 요청할 때마다 실행 결과를 기록하고 다시 호출합니다. 최종 답변과 호출 상한은 서로 다른 종료 사유입니다.

두 도구를 쓰기 위해 이 장에서는 이름을 get_hours와 get_loan_rule로 정했습니다. 함수 이름이 달라도 각 요청과 결과를 같은 call_id로 연결한다는 원칙은 16장과 같습니다.

03

최종 응답과 최대 호출 횟수

모델 호출과 도구 실행은 따로 셉니다. 이번 대본의 첫 두 응답은 도구 호출이고 세 번째 응답은 답변입니다. 아래 함수는 진짜 모델 대신 준비된 응답을 순서대로 읽는 작은 루프입니다. 잘못된 ID와 중복을 검사하는 전체 수업 예제는 같은 종료 규칙을 더 엄격하게 적용합니다.

셀 03 · 최종 메시지에서 루프 종료

회차마다 먼저 응답 종류를 읽습니다. 최종 응답을 받거나 상한에 닿으면 함수를 빠져나갑니다.

모델이 더 요청할 도구가 없다고 답하면 이 루프는 끝납니다. 요청 ID 중복을 막으려면 execute(item)를 부르기 전에 이미 처리한 ID인지 확인해야 합니다. 실행 뒤에 ID를 비교하면 같은 도구가 이미 두 번 작동했을 수 있습니다.

세 번째 응답의 type이 message여서 최종 문장을 읽고 끝납니다. 대본에서 사용한 모의 모델 응답은 세 번, 도구 실행은 두 번입니다. 전체 구현은 미완료 응답도 따로 기록합니다.

복습과 실습 점검

06

도구 호출 루프와 종료 조건 심화 읽기

연속 도구 호출의 조건

사용자가 운영 시간과 대출 기간을 함께 묻는다면 모델이 서로 다른 두 기능의 결과를 필요로 할 수 있습니다. 16장의 한 번 왕복을 반복하면 결과를 받은 뒤 다음 도구를 요청하거나 답변을 마칠 수 있습니다.

실제 모델을 연결한 루프에서는 모델이 도구 선택을 요청하고 Python이 실행 조건을 검사합니다. 기본 실행의 scripted_model은 순서가 정해진 모의 응답이므로 모델의 자율 판단을 검증한 것은 아닙니다.

두 도구의 입력과 반환값
등록한 도구
이름입력반환
get_hoursday=weekday 또는 weekend가상 운영 시간
get_loan_rule빈 객체 {}가상 대출 기간 14일

두 도구는 수업용 가상 값을 읽습니다. 16일의 get_library_hours를 get_hours라는 짧은 이름으로 바꾸고, 반환에서 hours를 직접 꺼내는 형태로 정리했습니다. 함수 이름과 반환 구조가 달라졌으므로 16일 파일을 이름만 바꿔 그대로 연결하지 않습니다.

16일 run_turn은 왕복 한 번과 final_reply를 보여 주었습니다. 이번 run_agent는 반복 횟수와 tools 목록을 반환합니다. 이 장은 텍스트 답변이 없는 거절 응답도 empty_answer로 종료합니다. 거절 내용을 사용자에게 표시하는 기능은 아직 없으므로 실제 서비스의 완성된 거절 처리라고 설명하지 않습니다.

history의 요청·결과 메시지

history는 현재 요청에서 모델에 전달할 입력 목록입니다. 사용자 메시지, 모델의 output 항목, 도구 결과를 순서대로 보관합니다. 이번 루프는 함수 호출마다 새 목록을 만들며 여러 사용자의 장기 기억을 구현하지 않습니다.

seen은 이미 처리한 호출 ID 집합이고 executed는 실행 결과 목록입니다. 두 변수의 역할은 다릅니다. 호출 ID를 중복 검사한다고 같은 의미의 질문 반복을 모두 막는 것은 아닙니다.

루프의 변수
변수목적

seen같은 호출 ID 재처리 방지
executed도구 실행 시도와 결과 기록
number이번 모델 요청 번호
질문 검증과 호출 예산

question은 공백이 아닌 문자열이어야 합니다. 숫자·None·리스트를 받으면 TypeError, 공백만 있으면 ValueError가 발생합니다. 잘못된 입력은 모델을 부르기 전에 거부합니다. 호출을 시작하지 않았으므로 루프의 status 반환값과 구분합니다.

상한은 bool을 제외한 정수입니다. Python에서 bool은 int의 하위 타입이므로 isinstance(value, int)만 검사하면 True를 1처럼 받습니다. 먼저 bool 여부를 제외한 뒤 정수와 범위를 확인합니다.

허용 입력과 범위
인자유효한 값거부할 예

도구 상한 0은 오류가 아닙니다. 도구 요청을 실행하지 않겠다는 정책이며, 모델이 텍스트로 바로 답하면 completed가 될 수 있습니다. 모델 상한 0은 모델을 한 번도 호출할 수 없으므로 입력 오류로 처리합니다.

루프 한 회의 실행 순서

위 함수는 입력 검사 뒤 history를 만들고 모델을 부릅니다. 미완료 응답이면 중단하고, 도구 요청이 없으면 텍스트를 모아 공백 여부를 검사합니다. 공백만인 답변은 empty_answer입니다. answer에는 받은 텍스트를 그대로 보존합니다.

도구 요청이 있으면 개수, 공백이 아닌 문자열 ID와 재사용 여부, 도구 상한, 남은 모델 호출 기회를 확인합니다. 마지막 모델 호출에서 또 도구를 요청하면 실행하지 않고 model_limit로 끝냅니다. 이 순서는 도구 결과를 모델에 다시 돌려줄 기회를 남기기 위한 수업 정책입니다.

completed는 루프가 텍스트로 끝났다는 뜻이지 답변 정확성 평가를 통과했다는 뜻이 아닙니다. 도구가 실패한 뒤 모델이 “조회 실패”라고 답해도 루프는 정상 종료할 수 있습니다. 결과 내용과 종료 상태를 따로 읽으세요.

max_tool_calls는 정상 성공뿐 아니라 실행 검증 결과가 오류인 도구 요청 처리도 셉니다. 반복된 잘못된 인자가 비용과 시간을 계속 쓰지 않도록 제한합니다.
