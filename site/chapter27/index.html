02

add_conditional_edges()와 라우팅 함수

조건부 간선은 상태에 따라 서로 다른 노드로 이어집니다. 빈 검색 결과를 다시 찾게 할 때는 반복을 끝낼 조건도 필요합니다.

search가 시도 횟수를 올린 직후 route가 문서 유무와 attempts를 읽습니다. 문서가 있으면 답을 쓰고, 없고 한 번만 찾았다면 검색어를 바꿉니다. 두 번 찾고도 빈 목록이면 멈춥니다.

셀 01 · route()의 분기 반환값

검색을 한 번 마쳤고 문서를 못 찾았습니다. 다음에 갈 곳을 고르는 함수만 먼저 실행하세요.

실행 결과

retry

retry가 출력된 줄에서는 아직 두 번째 검색을 하지 않았습니다. route는 경로 이름을 고르고, 그래프에 등록한 조건부 간선이 그 이름을 다음 노드와 연결합니다. 첫 검색에 문서가 있었을 때와 비어 있었을 때 어느 노드를 한 번 더 지나게 되는지 비교하세요.

조건 함수의 경로 이름

search가 documents를 갱신한 뒤 route가 현재 상태를 읽습니다. route의 역할은 답변을 만드는 것이 아니라 answer·retry·stop 중 한 문자열을 반환하는 것입니다. add_conditional_edges의 대응표가 그 문자열을 등록한 노드 이름과 연결합니다.

직접 성공에서는 한 번 검색하고 종료합니다. 실패라고 무조건 다시 검색하면 같은 입력과 결과를 끝없이 반복할 수 있습니다. 이번 예제는 문서가 없고 attempts가 2보다 작을 때만 재시도합니다.

03

질의 재작성과 재검색 횟수 제한

검색 상태에 따른 다음 노드

문서가 있는지와 이미 실행한 검색 횟수가 다음 경로를 결정합니다.

첫 검색 결과가 비면 재검색하고 두 번째에도 비면 종료합니다.

셀 02 · add_conditional_edges()로 경로 등록

이미 실행한 route는 그대로 씁니다. search가 attempts를 올리는 줄과 rewrite 뒤에 다시 search로 돌아가는 엣지를 찾아보세요.

셀 01에서 나온 retry는 아직 최종 답이 아닙니다. 그래프는 rewrite로 이동한 뒤 search에 다시 들어갑니다. 다음 검색에서도 비었을 때 어떤 조건이 반복을 끝내는지 찾아보세요.

실행 결과

2

같은 상태에서 검색을 한 번 더 실행해 횟수가 2가 됐습니다. 이 셀의 함수 정의를 다음 셀에서 사용합니다.

상태에 저장하는 시도 횟수

State에 attempts 정수 필드를 추가합니다. 초기 값 0에서 시작해 search가 실제 실행될 때마다 1을 더합니다. 검색 함수 실행 후 route가 읽는 값은 이미 증가한 값입니다. 첫 번째 실패 뒤에는 1이므로 재시도하고, 두 번째 실패 뒤에는 2이므로 종료합니다.

attempts는 이 예제에서 검색 노드 실행 횟수입니다. 전체 노드 수나 모델 토큰 수가 아닙니다. 답변 노드와 rewrite 실행을 함께 세고 싶다면 별도의 기록을 설계해야 합니다.

재검색 순환 간선

rewrite 다음에 search로 돌아가는 연결이 반복을 만듭니다. answer_node와 fallback은 END로 연결되어 더 이상 돌아가지 않습니다. 모든 경우를 반복으로 처리하지 않고 성공과 포기 경로를 분리합니다.

셀 03 · rewrite 노드의 질의 변경

질문 한 건의 마지막 상태에서 횟수와 답을 확인하세요.

실행 결과

2 도서 대출 기간은 14일입니다.

두 번째 검색에서 ‘대출’이 들어 있는 질문으로 문장을 찾았습니다. 첫 번째 빈 결과만 보고 바로 끝냈다면 14일이라는 답까지 가지 못했을 것입니다.

상태표의 세 종료 경로

관찰할 경로
입력노드 순서검색 횟수
대출 기간?search → answer_node1
책을 빌리는 기간?search → rewrite → search → answer_node2
주차장은?search → rewrite → search → fallback2

두 번째 입력은 첫 검색에서 대출이라는 글자가 없어 실패합니다. rewrite가 책을 대출로 바꾼 뒤 다시 검색하면 근거가 생깁니다. 세 번째 입력은 rewrite로 바뀌지 않아도 횟수 상한으로 끝납니다. 질문이 달라진 사실과 답변이 좋아진 사실은 따로 확인해야 합니다.

과제 04 · 검색 상한과 fallback

주차장 질문을 처리한 뒤 몇 번 검색했고 사용자에게 무엇을 안내하는지 출력하세요.

풀이와 실행 결과 보기

실행 결과

2 두 번 검색했지만 근거가 없습니다. 질문을 구체화해 주세요.

두 번 모두 문서가 비어 fallback으로 갑니다. attempts가 2일 때도 retry로 보내면 설계한 상한을 넘게 됩니다. 프레임워크의 recursion_limit은 이런 실수를 발견하는 별도 보호 장치입니다.

반복 상한과 실행 오류

recursion_limit은 그래프 진행을 제한하는 별도의 안전 한도입니다. 이 예제의 검색 최대 횟수 2는 route의 조건으로 정합니다. recursion_limit=20을 검색 20회나 모델 호출 20회로 읽지 마세요. 재시도가 허용되는 업무 조건을 이 값 하나에 맡기지 않습니다.

빈 질문은 search에서 ValueError로 중단됩니다. 질문 자체가 없는데 재검색해도 정보가 늘지 않으므로 입력을 고치도록 합니다. 실제 네트워크 오류의 재시도 여부는 오류 종류·시간 제한·중복 실행 위험을 함께 판단해야 하며 이 장의 로컬 예제로 이를 검증했다고 주장하지 않습니다.
