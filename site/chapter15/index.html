06

관련 개념 더 읽기

선행 함수·API·응답 스키마와 도구 명세 대조

첫 1H 중 15분을 세 기록에 5분씩 나눕니다. 3일 functions/tests.md에서 함수의 입력·반환·예외를, 6일 api-client/results.json에서 통신 실패와 응답 형식 실패를, 12일 structured-output/cases.json에서 정상·거절·미완료를 구분한 근거를 읽습니다. 개인 기록이 없으면 아래 제공 코드로 재개하고 제공 자료를 읽었다고 표시합니다.

3일의 함수 약속은 도구 명세의 입력 범위를 설명하는 바탕입니다. 6일의 전송 성공과 내용 검증 구분은 모델 응답 관찰에도 필요합니다. 12일 Notice는 답변의 형태이고 오늘 TOOL.parameters는 요청할 함수의 인자 형태입니다. 거절·미완료·빈 응답을 정상 결과와 구분했던 규칙도 다시 확인합니다.

함수 코드를 보내는 것과 명세를 보내는 것

Python 함수는 프로그램이 실행할 코드입니다. 도구 명세는 모델에게 어떤 기능이 있고 어떤 인자를 받는지 알려 주는 설명입니다. Function Calling에서 모델은 이 명세를 보고 함수 이름과 인자를 포함한 요청을 만들 수 있습니다.

여기서 사용자가 만든 함수는 애플리케이션이 실행해야 합니다. 모델 응답 안에 함수 이름이 나타났다고 내 컴퓨터에서 함수가 실행된 것은 아닙니다. 이번 장은 요청 관찰까지 다루며 실행·결과 반환은 다음 장에서 구현합니다.

서로 다른 세 가지
대상내용이번 장
구현실제로 실행되는 Python 코드아직 실행하지 않음
명세이름·설명·인자 스키마작성

name은 코드에서 찾을 기능의 식별자입니다. description에는 언제 사용하는지와 하지 않는 일을 설명합니다. parameters는 인자의 모양을 정합니다. 이번 day는 weekday와 weekend만 받습니다.

required는 day가 필요함을 뜻하고 additionalProperties=False는 다른 필드 추가를 허용하지 않는 스키마 설정입니다. strict=True를 사용해 지원되는 형식 제약을 요청하지만 실제 실행 전에는 애플리케이션도 입력을 검사해야 합니다.

호출 요청의 구조를 읽기

arguments는 이 응답 형태에서 JSON 내용이 들어 있는 문자열입니다. json.loads로 읽으면 Python 딕셔너리가 됩니다. 문자열을 Python 코드로 실행하는 eval을 사용하지 않습니다.

call_id는 이번 호출 요청과 나중의 결과를 연결하는 식별자입니다. 같은 함수를 여러 번 요청할 수 있으므로 함수 이름만으로 어느 결과인지 구분하면 안 됩니다.

반드시 구분할 것
필드역할

name어떤 등록 기능을 요청했는지
arguments그 기능에 전달할 입력

다음 장의 execute_call은 원본 요청 안의 JSON 문자열을 직접 검사합니다. inspect_calls나 inspect_response의 parsed_calls를 그대로 실행 입력으로 넘기지 않습니다. 관찰을 위해 파싱한 값과 실행 경계가 받을 원본 요청을 파일에서도 나눠 보관하세요.

응답 목록에서 호출 항목만 찾기

모델 응답의 output에는 여러 종류의 항목이 들어갈 수 있습니다. 각 항목의 type을 보고 function_call만 읽습니다. 일반 문장에 “함수를 실행했습니다”라고 쓰여 있어도 호출 요청으로 처리하지 않습니다.

inspect_calls는 인자가 JSON 객체인지까지만 검사합니다. day의 허용값이나 name의 실행 가능 여부는 아직 검사하지 않으며 어떤 함수도 실행하지 않습니다. 이 범위를 다음 장의 실행 검증과 혼동하지 마세요.

SDK 요청에 명세를 추가하기

request_tool은 호출 목록만 반환하지 않고 status·response_kind·raw_output·parsed_calls·refusals·mode·tool_executions를 포함한 관찰 기록을 반환합니다. incomplete 응답에 파싱 가능한 요청이 있어도 response_kind는 not_completed이며 실행 가능한 완료 요청으로 취급하지 않습니다. 이 장은 어떤 도구도 실행하지 않습니다.

parsed_calls=[]만으로 성공적인 일반 답변이라고 판단하지 않습니다. message·refusal·empty·not_completed를 함께 읽습니다. message 역시 도구를 실행했다는 증거가 아닙니다. raw_output은 원본 arguments 문자열을 보존하고 parsed_calls는 관찰용 딕셔너리를 담습니다.

tools=[TOOL]은 사용할 수 있는 명세를 전달합니다. 기본 선택 설정에서는 모델이 일반 답변을 하거나 도구 호출을 요청할 수 있습니다. 도구를 등록했다는 사실만으로 호출이 반드시 발생한다고 가정하지 않습니다.

parallel_tool_calls=False는 이 실습에서 병렬 호출을 제한하기 위한 옵션입니다. 모델·API 지원 조건을 확인해야 하며, 이 함수가 실제 요청을 성공시켰다는 검증은 아직 하지 않았습니다. 기본 실행은 직접 만든 호출 자료만 읽습니다.

명세가 모호할 때 생기는 문제

설명에 “모든 질문을 처리한다”라고 적으면 기능의 경계가 사라집니다. 운영 시간만 조회하는 도구에는 날짜별 예약 가능 여부나 도서 재고를 처리한다고 적지 않습니다. 실제 구현이 할 수 있는 일만 설명하세요.

인자가 필요한 이유도 분명해야 합니다. day가 요일 이름인지 평일/주말 구분인지 설명되지 않으면 사용자 질문과 스키마가 어긋날 수 있습니다. 허용값과 설명을 함께 읽고 지원하지 않는 질문은 추가 확인 대상으로 남깁니다.
