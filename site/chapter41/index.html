화면 상태와 그래프 저장 상태

화면에 보이는 현재 답변과 그래프에 쌓이는 대화 기록은 수명이 다릅니다. 어떤 사용자와 스레드의 값을 갱신하는지 확인합니다.

LangGraph에 InMemorySaver를 연결해 스레드별로 질문을 기록합니다. 화면 담당 코드는 현재 대화의 thread_id를 전달합니다. 셀 01~03은 도서관 고정 자료를 검색합니다. 셀 04~05에서는 학생이 입력한 안내문 한 건을 같은 그래프 호출에 전달합니다.

04

Streamlit 폼에서 그래프 호출

제공 앱은 도서관 자료에 더해 폼에 입력한 안내문 한 건을 검색할 수 있습니다. 질문에 지정한 검색어가 들어 있으면 입력한 안내문을 먼저 보여 줍니다. 앞서 본 처리 중 UI에서 결정하는 것은 대화 ID와 현재 표시할 결과입니다. 새 대화 버튼은 새 ID를 만듭니다. 수업용 예제에는 로그인·운영 저장소가 없습니다.

셀 04 · 폼 상태와 대화 ID 연결

st.session_state.thread를 설정하는 줄과 engine.invoke에 같은 ID를 건네는 줄을 찾아보세요.

새 대화 버튼은 새 ID를 만들고 current를 비웁니다. 그래프 엔진을 준비하는 코드는 prepare_engine에서, 폼 제출 결과를 현재 화면에 넘기는 코드는 if submit 안에서 확인할 수 있습니다.

앱 구문 확인

화면과 그래프가 보관하는 값

prepare_engine은 @st.cache_resource를 사용해 그래프와 InMemorySaver를 재사용합니다. Streamlit의 session_state에는 현재 thread와 마지막 실행 결과 current가 들어갑니다. 새 대화는 새 ID를 할당하고 current를 비웁니다. 과거 스레드의 체크포인트는 같은 저장소에 남습니다. 메모리 저장소를 새로 만들거나 프로세스를 종료하면 이 예제의 체크포인트는 사라집니다.

폼 제출값을 그래프 입력으로 보내기

추가 문서를 사용하려면 본문과 그 안에 있는 검색어를 함께 입력합니다. 검색어만 남기고 본문을 지우면 경고를 표시하고 이전 출처를 지웁니다. 둘 다 비워 두면 기존 자료만 검색합니다. 직접 입력한 안내문에는 쪽 번호가 없으므로 화면에도 쪽 번호를 만들지 않습니다.

06

새 대화를 눌렀을 때 화면과 체크포인트의 연결 확인하기

지난 질문을 화면에서 지워도 그래프에 예전 thread_id를 보내면 이전 대화가 이어집니다. 이번에는 화면에 보관할 작은 상태와 그래프의 저장 기록을 구분하고 초기화 함수를 작성합니다.

Streamlit 미설치 · 새 대화 버튼 검사는 건너뜁니다.

설치한 환경에서는 대출 문서의 1쪽 출처가 한 번 보이고 새 대화의 출처 수는 0이어야 합니다. 이 검사는 화면에서 옛 자료를 숨겼는지를 봅니다. 저장소에 무엇이 남았는지는 바로 앞 get_state 결과로 읽습니다.
