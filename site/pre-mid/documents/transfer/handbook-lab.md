# 36쪽 운영 편람으로 문서 챗봇 인수 시험하기

서울과 부산 지점은 같은 서비스를 다른 기한으로 운영합니다. 편람에는 영수증이라는 단어가 정책, 화면 시안, 행사 기록, 접수 대장에 모두 나옵니다. 어느 페이지에 답이 **있어 보이는지**와 어느 페이지가 그 이용자에게 **실제로 적용되는지**를 구별해야 합니다. 24장에서 만든 챗봇에 새 PDF를 넣었을 때도 이 차이를 찾아낼 수 있는지 시험합니다.

[하람페이 운영 편람 36쪽](operations.pdf) · [학생용 문의 10건](questions.csv) · [쪽별 지점·대상·유효기간](pages.csv) · [PDF에서 추출한 원문](page-text.json) · [실습 노트북](handbook-evidence.ipynb)

**준비.** 교재 화면 상단에서 1~42장 자료 묶음을 받아 압축을 푼 뒤 Jupyter에서 `pre-mid/documents/transfer/handbook-evidence.ipynb`를 엽니다. 노트북의 기본 실습은 Python 표준 라이브러리만 사용합니다. PDF에서 미리 추출한 쪽별 텍스트를 함께 제공하므로 별도 모델이나 계정 없이 후보 검색·조건 대조를 반복할 수 있습니다. 실제 PDF의 쪽 번호는 1부터 세며, 화면에 보이는 ‘운영 편람 · 01쪽’이 첫 페이지입니다.

## 1. 답을 보지 않고 기준부터 적기

| 번호 | 지점 | 대상 | 적용일 | 문의 원문 |
|---|---|---|---|---|
| B01 | 서울 | 개인 | 2026-06-30 | 개인 앱에서 영수증을 며칠까지 보나요? |
| B02 | 서울 | 개인 | 2026-07-01 | 개인 앱에서 영수증을 며칠까지 보나요? |
| B03 | 부산 | 개인 | 2026-09-01 | 승인 영수증의 열람 기한은? |
| B04 | 서울 | 가맹점 | 2026-09-01 | 매장 증빙을 언제까지 보관하나요? |
| B05 | 서울 | 가맹점 | 2026-09-01 | 정산 파일 준비 시각은? |
| B06 | 부산 | 가맹점 | 2026-09-01 | 정산 파일 준비 시각은? |
| B07 | 대전 | 가맹점 | 2026-12-31 | 파일이 준비되는 시각은? |
| B08 | 대전 | 가맹점 | 2027-01-01 | 파일이 준비되는 시각은? |
| B09 | 대전 | 가맹점 | 2027-01-12 | 승인 건수와 파일 행 수가 다르면? |
| B10 | 제주 | 개인 | 2026-09-01 | 제주 개인 앱의 열람 기한은? |

학생용 CSV에는 지점(branch), 대상(audience), 적용일(as_of), 질문(question)이 있습니다. B01과 B02에서 달라진 값을 하나 찾습니다. B05와 B06은 지점 한 칸을 바꿨을 때 답도 달라지는지 확인하는 쌍입니다. 질문 문장만 복사하면 조건을 잃습니다. 그 조건까지 포함한 질문을 챗봇에 보내세요. 정답표는 이 단계가 끝난 뒤 엽니다.

## 2. 비슷한 문단과 적용 가능한 정책 가르기

B03을 맡은 상담자가 부산 화면 시연에 나온 ‘90일’을 답으로 골랐다고 합시다. PDF에서 ‘90일’을 찾고, 각 페이지의 문서 종류와 본문의 승인 여부를 읽으세요. 부산이라는 지명이 맞아도 교육용 문구라면 정책의 근거로 쓸 수 없습니다. 서울에서 제공받은 승인 기한도 부산 지점에 그대로 적용할 수 없습니다. 근거로 채택한 페이지와 제외한 페이지를 하나씩 기록하세요.

B08은 개정 경계일의 정산 파일 시각을 묻습니다. B09는 같은 대전 가맹점에서 승인 건수와 행 수가 달라졌을 때 취할 조치를 묻습니다. 현재 적용 가능한 문서가 두 장이어도 **묻는 행동**에 따라 인용할 문단이 달라집니다. 유효기간이 가장 최근인 페이지를 모든 질문의 답으로 선택했을 때 무엇을 놓칠지 설명하세요.

## 3. 결과와 원인을 서로 다른 칸에 남기기

| 내 기록 | 어떻게 채울까요? |
| --- | --- |
| 입력 | 문의 번호, 지점, 대상, 기준일, 보낸 질문 원문 |
| 검색 | 처음 찾은 후보 쪽수와 실제 본문 한 줄 |
| 답변 | 사용한 값과 단위, 답의 근거 문장 또는 보류 사유 |
| 진단 | 관련어가 나오지 않았는지, 구판·다른 지점·교육 문서가 포함됐는지, 관련 문서가 있어도 다른 행동에 답했는지 |
| 재실행 | 검색어·메타데이터 조건·답변 지시 중 하나만 바꿔 같은 입력으로 확인한 결과 |

## 4. 챗봇으로 옮겨 보기

24장 화면에서 수업용 녹음기 PDF 대신 이 편람을 선택하고 색인을 새로 준비합니다. 파일 업로드에 operations.pdf를 넣고, 이전 문서 대신 이번 편람이 선택되었는지 확인하세요. B02·B03·B08·B10 네 건은 지점·대상·적용일을 포함해 요청합니다. 아래 오프라인 노트북의 후보 쪽과 실제 챗봇에서 꺼낸 문단을 비교하세요. PDF를 바꿨는데 ‘녹음기’나 예전 설명서 쪽수가 보이면 먼저 색인·캐시가 어떤 파일을 읽었는지 확인합니다.

새 문서에서는 ‘제주 개인’과 ‘90일’이 한 페이지에 나와도 교육용 미승인 초안일 수 있습니다. “관련 페이지가 발견됐다”와 “제주 이용자에게 열람 기한을 확정해도 된다”는 서로 다른 판단입니다. 챗봇이 추측했다면 실패 사례에 어떤 근거가 있어야 답할 수 있는지도 적어 두세요.

## 5. 모범 판정과 인계

10건 모두에서 스스로 인용 쪽과 답변을 기록한 뒤 [해설과 반례](handbook-key.md)와 [기준 답 CSV](reference-answers.csv)를 엽니다. 동료에게는 직접 만든 질문 한 건, 기대한 근거, 실제로 처음 잘못된 단계, 수정 후 결과를 건네세요. 다른 팀은 해결한 질문뿐만 아니라 원래 맞았던 질문도 다시 실행합니다. 이 기록은 중간 프로젝트에서 처음 쓸 평가 사례가 됩니다.
