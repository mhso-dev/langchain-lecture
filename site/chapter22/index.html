02

어휘 벡터와 제곱 L2 거리

벡터 검색은 질문과 문서를 같은 좌표 체계로 나타내고 거리가 가까운 문서를 찾습니다. 여기서는 단어의 포함 여부로 좌표를 만들어 거리를 직접 검산합니다.

질의 벡터와 문서 간 제곱거리

대출 질의와 대출 문서의 제곱거리는 0, 휴관 문서와는 2입니다.

어휘 좌표와 숫자 벡터

임베딩은 텍스트 같은 입력을 숫자 벡터로 표현하는 방법입니다. 의미 임베딩 모델은 학습된 표현을 만들며, 검색 저장소는 그 벡터를 보관하고 가까운 항목을 찾는 역할을 합니다. 저장소 자체가 답변을 생성하는 것은 아닙니다.

이번 계산 실습은 대출·휴관·반납 세 키워드의 존재를 0과1로 표시한 벡터를 사용합니다. 학습된 의미 임베딩이 아니므로 “책을 며칠 빌리나요?”처럼 단어가 달라지면 의미가 같아도 찾지 못할 수 있습니다. 수학과 저장소를 확인하기 위한 기준선입니다.

어휘 포함 벡터와 학습된 임베딩

teaching_vector는 어휘가 글자 그대로 들어 있는지만 셉니다. 따라서 뜻이 비슷해도 표현이 다르면 가까운 벡터가 되지 않을 수 있습니다. 학습된 임베딩으로 비교할 때도 같은 모델로 문서와 질문을 모두 변환하세요.

셀 01 · 어휘 순서와 문서 벡터

20장에서 등록한 세 원문의 ID, 본문, 출처, 쪽수를 그대로 사용합니다.

실행 결과

[1.0, 0.0, 0.0]

library-1은 [1.0, 0.0, 0.0]입니다. 첫 숫자는 대출이 있다는 뜻입니다. 저장할 때와 검색할 때 단어 순서가 달라지면 숫자가 셋이어도 비교가 틀어집니다.

문서를 같은 어휘 순서로 변환하기

terms의 순서는 대출, 휴관, 반납입니다. 세 문서와 질문이 모두 같은 순서로 좌표를 만들기 때문에 첫 좌표끼리, 둘째 좌표끼리 비교할 수 있습니다.

셀 02 · 제곱 L2 거리 계산

질문 벡터와 휴관 안내 벡터에서 같은 위치끼리 빼고 제곱해 더합니다.

실행 결과

2.0

2.0입니다. 첫 두 좌표가 각각 1만큼 다르고 마지막 좌표는 같아서 1+1+0이 됩니다. 이 거리는 답변의 정답 확률이 아닙니다.

벡터 거리와 신뢰도의 차이

squared_l2는 같은 위치의 값 차이를 제곱해 더한 거리입니다. 이 예제에서는 작을수록 가깝습니다. 거리0은 벡터가 같다는 뜻이지 문서가 질문에 정확히 답하거나 사실이라는 뜻이 아닙니다.

동일한 벡터가 여러 문서에 있을 수 있고, 동점의 순서는 저장소마다 다를 수 있습니다. 최고 순위 하나만 보고 검색 품질 전체를 판단하지 않습니다.

키워드가 하나도 없는 질문은 교육용 규칙에 따라 검색 결과를 빈 목록으로 돌려줍니다. 이것은 의미가 없다는 수학적 결론이 아닙니다. 실제 의미 임베딩 모델에 같은 영벡터 규칙을 그대로 적용하지 않습니다. 빈 질문과 bool k는 입력 오류로 거부합니다.

03

Chroma 컬렉션의 저장과 조회

수업용 커널에 chromadb가 있으면 새 임시 폴더에 컬렉션을 만듭니다. 이번 노트북에서는 같은 세 문서와 모델 이름을 사용하되, 임시 컬렉션은 다른 장의 저장소를 덮어쓰지 않습니다. 아래 두 셀은 실제 Chroma를 쓰는 선택 경로입니다.

저장 벡터와 질의 벡터의 좌표

저장할 때와 질의할 때 terms의 순서를 같게 유지하세요. 어휘 순서를 바꾸면 길이가 3으로 같아도 각 숫자의 뜻이 달라집니다. 어휘나 표현 방법을 바꿀 때는 문서 벡터도 다시 계산합니다.

저장소 미실행과 검색 결과 구분

chromadb가 설치되지 않은 커널에서는 설치 안내 문장이 출력되고 검색은 실행되지 않습니다. 컬렉션을 실제로 연 뒤 후보를 얻지 못한 경우와 구분해 결과를 읽어 보세요.

셀 04 · Chroma에 본문과 메타데이터 저장

임베딩 값을 직접 주므로 외부 임베딩 모델을 내려받지 않습니다.

실행 결과

실제 저장 실습은 chromadb가 설치된 커널에서 실행하세요.

실제 컬렉션에 세 건을 넣으면 3이 나옵니다. 각 문서의 위치와 벡터가 같은 순서로 들어갔습니다. 전체 인덱스 인수인계 시에는 이름 외에도 차원·거리·원문 버전을 대조합니다.

Chroma 문서·벡터 저장

PersistentClient는 지정 폴더에 데이터를 보관합니다. collection은 관련 문서를 묶는 단위입니다. id·document·embedding·metadata 목록은 같은 순서와 같은 길이를 유지해야 합니다.

configuration의 hnsw.space를 l2로 정해 제곱 L2 거리를 명시합니다. 여기서는 HNSW 내부 구조를 학습 목표에 넣지 않습니다. 컬렉션의 E1 기록이 입력 자료와 다르면 오류를 내므로 모델이나 원문을 바꾸어 기존 컬렉션과 섞지 않습니다.

셀 05 · 컬렉션 재조회와 결과 ID

앞 셀에서 만든 같은 경로와 이름을 지정합니다. 자료를 다시 적재하지 않고 조회합니다.

실행 결과

Chroma 재열기는 실제 저장 셀을 실행한 뒤 확인하세요.

Chroma가 있으면 library-1, 1쪽이 나옵니다. ids의 첫 [0]은 첫 질문, 다음 [0]은 그 질문의 1순위입니다.

질의 벡터와 반환 구조

query_embeddings에는 질문 벡터의 목록을 넣습니다. 질문 한 개도 바깥 목록 안에 넣으므로 결과의 ids·documents·metadatas·distances도 질문별 목록으로 돌아옵니다. 첫 질문의 결과는 각 필드의 [0]에 있습니다.

n_results는 반환할 최대 후보 수입니다. 후보를 두 개 받았다고 둘 다 관련 문서라는 뜻은 아닙니다. 문서 본문과 거리를 함께 읽어 필요한 근거가 포함되었는지 확인하세요.

같은 디렉터리에서 컬렉션 다시 열기

두 번째 PersistentClient에 첫 번째 클라이언트와 같은 chroma_folder.name을 전달합니다. 같은 이름의 컬렉션을 다시 열어 검색할 수 있는지 확인하세요. 여기서 선택한 폴더는 TemporaryDirectory가 관리합니다.

셀 06 · FAISS 거리 검색

faiss와 numpy가 있는 커널에서 실제 인덱스를 메모리에 만듭니다.

같은 대출 질문으로 비교하세요. 제공된 Chroma 셀에는 설치 안내만 저장되어 있어 그 실행의 검색 ID는 미확인입니다. FAISS 셀에는 library-1과 거리 0.0이 저장되어 있습니다. Chroma를 실행했다면 ids[0][0]을 읽어 이 ID와 대조하세요.

실행 결과

library-1 0.0

실제 조회를 하면 library-1과 0.0이 나옵니다. positions는 문자열 ID가 아니므로 문서 목록의 순서를 바꾸면 연결도 다시 맞춰야 합니다. Chroma 실습은 수업 커널에 chromadb가 있는지 먼저 확인하세요. 새로 연 컬렉션에서 첫 ID를 읽었을 때만 FAISS에서 나온 첫 ID와 한 줄에 나란히 적으세요.

FAISS의 결과 위치를 문서로 연결하기

IndexFlatL2에는 벡터가 입력 순서대로 들어갑니다. positions[0][0]이 0이면 documents[0]의 ID를 읽어 library-1을 얻습니다. 검색 거리는 distances[0][0]에 따로 들어 있습니다.
