## 학생의 입력을 바꿔 확인한 결과

- 1장의 추가 시간을 7초에서 2초로 바꾸자 7장의 Git 수신 파일 합계도 154초에서 149초로 바뀌었다. 디자인 패턴 과정에서는 우선 물건을 장갑으로 바꾸자 Git으로 받은 기록에도 장갑이 남았다.
- 13장의 챗봇에서 저장한 질문을 14장의 프롬프트가 읽고, 24장은 같은 앱에 문서 검색과 출처 표시를 더한다. PDF 쪽 번호·판본과 세 갈래 검색 그래프는 다운로드 ZIP에서 재실행했다. 새 임베딩과 모델 실응답의 재현 여부는 장별로 표시했다.
- 42장의 평가가 남긴 녹음기 A형 1.1판 2쪽 질문과 검토 대기 결정을 43장의 팀 자료에서 읽었다. 45장은 정답 문서를 빼면 다른 문서가 선택되는지 확인한다. 47장은 인사말을 넣으면 검색 횟수가 0인 종료 경로를 웹·노트북 양쪽에서 따라갈 수 있다.
- 54장의 대출 기간을 14일에서 21일로 바꾸자 67장 테스트와 68장 API에서도 21일을 읽었다. 80장에서 같은 변경을 두 번 승인하면 두 번째 요청은 409로 끝나며, 83장이 이를 기록한 실제 사건과 변경 횟수를 검사한다.
- 82장에서 선택한 판본을 85장의 별도 시험 질문에 적용해 기한 90일을 확인했다. 86장은 릴리스 파일의 예상값과 관찰값을 다시 읽었다. 108장은 문서 ID를 그대로 두고 문장만 바꿔도 내용 검사가 실패한다.

## 실행 환경과 전달본

macOS에서 새 IPython 커널을 사용했다. 실습마다 외부 API 실응답, 제공된 벡터·실행 기록, 응답을 대체한 계산, 실제 로컬 파일·DB 쓰기를 구분했다. 프로젝트 41장은 앞 장 파일을 이어 쓰는 41회와 제공 예시로 다시 시작하는 41회, 총 482개 코드 셀을 확인했다. 68~85장은 최종 학생용·풀이용 노트북 각 18개, 총 338개 코드 셀을 실행했다.

빌드 결과에서 HTML 155개, 교재·노트북 116쌍, Mermaid 도식 98개의 본문 정의·순서와 내부 링크를 검사했다. 1~42장 ZIP과 개인 과제 ZIP의 배포 파일, 접힌 풀이의 마크업, 다운로드 위치를 확인했다. 최종 지문은 각 장의 검증 기록에 있다. 프로젝트의 장별 검수 기록은 `reports/chapter-reviews/chapterNN.md`, 실행 기록은 `materials/chapterNN/VALIDATION.md`에서 확인한다.

한국어 설명은 출력과 관련된 문장을 중심으로 다시 읽고 코드·숫자·인용을 대조했다. 판정은 각 묶음 기록에 남겼다. 원고의 공개 범위가 확인되지 않아 외부 맞춤법 서비스로 전송하는 단계는 생략했다.
