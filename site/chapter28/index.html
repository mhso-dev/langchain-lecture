02

기본 덮어쓰기와 add_messages의 누적

리듀서는 상태에 새 값이 들어왔을 때 기존 값과 결합하는 규칙입니다. add_messages는 메시지 ID에 따라 새 메시지를 추가하거나 기존 메시지를 갱신합니다.

셀 01 · 기본 상태 갱신의 덮어쓰기

제공 셀입니다. 두 상태 정의와 응답 함수는 그대로 두고 PlainState에서 돌아온 메시지 종류를 확인하세요.

실행 결과

['ai']

ai 하나가 남았습니다. respond가 사용자 질문은 읽었지만 AIMessage 한 개만 돌려줬기 때문입니다.

사용자가 실제로 질문했는데도 마지막 출력에는 ai만 남습니다. 응답 함수는 질문을 읽었고, 반환할 때에는 답 한 건을 담은 새 목록을 건넸습니다. 같은 반환값을 다음 셀의 add_messages가 받으면 h1과 a1이 함께 남습니다. 바뀐 곳은 응답 함수보다 상태를 갱신하는 규칙입니다.

문자열 목록과 메시지 객체

HumanMessage는 사용자 발화, AIMessage는 모델 측 발화의 역할을 표현합니다. 이 예제는 LLM 없이도 AIMessage 객체를 생성하므로 객체 타입만 보고 실제 모델 호출이 있었다고 판단하지 않습니다. content는 내용, id는 메시지를 구별하고 수정할 때 쓰는 식별자입니다.

역할과 내용을 함께 보존하면 뒤에서 모델에 입력을 구성하거나 도구 결과를 다룰 때 어떤 발화인지 구분할 수 있습니다. 도구 호출 메시지까지 한꺼번에 추가하지 않고 이번에는 human과 ai 두 역할만 사용합니다.

리듀서의 리스트 결합 규칙

PlainState의 messages는 새 리스트를 반환하면 이전 값이 교체됩니다. ChatState의 Annotated 표기는 messages의 타입과 함께 add_messages 갱신 규칙을 지정합니다. Python의 Annotated가 스스로 저장하거나 대화를 이어 주는 것은 아닙니다. LangGraph가 그 규칙을 읽어 상태 업데이트에 적용합니다.

add_messages는 새 ID를 가진 메시지를 추가하고 기존 ID와 같은 메시지는 해당 위치의 내용을 갱신합니다. 문자열이 같은지 비교해 중복을 제거하는 기능으로 이해하면 안 됩니다. 단순 리스트 덧셈과도 다릅니다.

셀 02 · add_messages로 메시지 누적

입력과 respond는 그대로 두고 스키마만 바꿉니다.

실행 결과

[('h1', 'human'), ('a1', 'ai')]

h1 뒤에 a1이 보입니다. 서로 다른 ID를 받은 메시지는 순서대로 남습니다. 응답 함수가 이전 메시지까지 다시 보낼 필요가 없습니다.

같은 메시지 ID를 다시 보낼 때

add_messages는 기존 ID가 들어오면 그 메시지를 갱신합니다. h1의 본문만 고쳐 다시 넣은 뒤 목록 길이와 내용을 함께 보세요. 새 ID를 붙인 경우에는 내용이 비슷해도 별개의 발화가 추가됩니다.

새 응답 메시지의 부분 갱신

respond는 현재 메시지 목록에서 마지막 사용자 메시지를 찾아 응답 한 개를 반환합니다. messages에는 새 응답만 들어 있습니다. ChatState의 갱신 규칙이 기존 사용자 발화와 이 변경분을 합칩니다.

상태의 목록을 직접 append한 뒤 전체 목록을 반환하는 방식은 어떤 변경분을 적용했는지 흐리게 만듭니다. 이 예제처럼 입력은 읽고 새 목록을 반환하면 단위 검사가 쉬워집니다. 응답 ID a1은 단일 응답 비교용 고정값입니다. 다중 응답에 그대로 재사용하는 정책은 아닙니다.

03

동일한 메시지 ID로 내용 갱신

내용이 비슷해도 ID가 다르면 새 발화입니다. 반대로 ID를 그대로 쓰면 그 발화를 수정할 수 있습니다. 같은 답변 ID를 계속 재사용하면 새 대화가 쌓이지 않는 이유도 여기에 있습니다.

메시지 ID와 상태 갱신

앞 셀의 combined에는 h1과 a1이 남아 있습니다. 바로 아래 과제는 질문 한 건만 든 initial에서 시작해 h1을 교체합니다.

add_messages에서 같은 a1은 기존 칸을 고쳐 2개, 새 a2는 추가되어 3개입니다. 기본 덮어쓰기에서는 받은 a1만 남습니다.

h1의 내용을 ‘반납 방법은?’으로 바꿔 보세요. 수정 후 사용자 메시지의 개수와 내용을 표시하세요.

이번에 수정하는 initial에는 사용자 메시지 h1 하나만 있습니다. 같은 ID로 고치면 한 자리의 내용만 바뀝니다. h1과 a1이 모두 있는 combined를 입력했다면 a1도 그대로 남습니다.

05

두 번째 답변이 첫 번째 답변을 덮는 문제 고치기

add_messages는 새 ID는 추가하고 같은 ID는 갱신합니다. 앞의 respond가 언제나 a1을 쓰는 상태에서 후속 질문을 보내면 실제 대화에 무엇이 남을까요?

셀 05 · 고정된 답변 ID로 두 번 응답하기

첫 대화 기록에 새 질문 h2를 붙이고 동일한 그래프를 실행합니다. 기록상 사용자 메시지 두 개에 응답 메시지가 몇 개 남았는지 읽으세요.

실행 결과

[('h1', 'human'), ('a1', 'ai'), ('h2', 'human')]
확인한 질문: 반납함은 어디에 있나요?

h1, a1, h2만 남습니다. 인덱스 1의 a1은 두 번째 질문의 답으로 바뀌었습니다. ID가 같으면 새 내용을 그 위치로 병합하기 때문에 첫 답이 사라지고 시간 순서도 어색해집니다.

과제 06 · 어느 질문의 답인지 구분되는 ID 정하기

질문의 ID를 답변 ID에 포함하는 노드를 작성하세요. 두 번째 질문 기록에서 그 노드를 실행한 뒤 add_messages로 병합해, 처음 답과 새 답이 함께 남는지 확인하세요.

정답 코드와 실행 결과 보기

실행 결과

[('h1', 'human'), ('a1', 'ai'), ('h2', 'human'), ('reply-h2', 'ai')]

기존 a1 다음에 h2와 reply-h2가 남습니다. 같은 h2의 답을 다시 계산하면 reply-h2 자리가 갱신됩니다. 서로 다른 질문을 구별하면서 같은 질문의 답을 교정할 수 있는 규칙입니다.

메시지 수가 줄었다면 먼저 두 응답의 ID가 같은지 보세요. 같은 content라도 ID가 다르면 새 줄이 되고, 내용이 달라도 ID가 같으면 기존 줄이 바뀝니다.

체크포인트에 대화를 저장해도 메시지 병합 규칙은 그대로 적용됩니다.
